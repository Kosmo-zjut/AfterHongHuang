## 必修项

### P0-1 地图 overlay 输入隔离

- `MapOverlayController` 打开及展开动画期间，从 TopBar 下缘到窗口底部必须始终存在完整输入阻断层。
- 地图 Panel 当前宽度为 0 或正在展开时，底部按钮、卡牌、道痕等不得被点击穿透。
- TopBar 保持可用；阻断层不得覆盖 TopBar。
- 关闭动画完成前仍保持阻断，释放后底页恢复输入。

### P0-2 服务节点按钮语义

- 灵脉“返回地图”：记录离开结果后立即打开可交互地图 overlay。
- 灵脉完成治疗/升级后：结算按钮灰显，结果页保留；明确的“继续/返回地图”动作只打开地图 overlay。
- 商店“离开/继续”：完成节点结果后立即打开可交互地图 overlay，原商店结果页保留。
- 事件选项完成后：结果页保留，提供并启用“继续/返回地图”按钮；该按钮只打开可交互地图 overlay。
- 关闭地图必须回到原节点结果页；只有点击合法下一节点才离开当前场景。
- 不允许出现裸 `MapScene`、空白底页、`OpenMapOnEnter + deferred` 可见中间态。

### P0-3 Overlay 互斥与模态

- Map、Deck、Settings 使用统一的 overlay 协调机制，同一时刻最多显示一个。
- 打开任一 overlay 时关闭另外两个；重复点击当前入口执行关闭。
- Settings 必须模态阻断底层输入，不能重复叠开。
- 不在每个页面复制三套互斥逻辑；使用可复用协调器或等价统一端口。

### P0-4 节点迁移事务

- 点击合法下一节点时，状态迁移和场景路由必须形成完整事务边界。
- 场景路由失败时，恢复旧 ActiveNode、RunState、节点结果/页面状态，并保留当前结果页与可重试地图。
- 成功路由后清理过期 `MapEntryMode` / `OpenMapOnEnter` 兼容标记。
- MapScene 与节点页共享同一正式进入端口，不维护双入口规则。

### P1-1 地图初始位置

- overlay 打开后将 `CurrentMapNodeId` 定位在安全可见区，不贴紧左右边缘。
- 布局测量延迟仅可用于滚动定位，不得引入空白 MapScene 或场景进入时序依赖。

### P1-2 角色选择数据绑定

- 默认角色从 Definition 中选择首个已解锁角色，空目录、无已解锁角色、缺初始牌组均显式失败。
- “随机”必须从全部已解锁 Definition 中随机选择，不能等价为“首个已解锁角色”。
- UI 槽位可以固定，但角色身份、解锁状态、背景/展示数据不得依赖数组下标、具体 ID 或内容顺序。
- 增加至少两个已解锁 Definition 经同一入口的自检，并覆盖随机候选集合。
