## 使用规则

- 每个任务必须有负责人、验收标准和当前状态。
- 任务进入开发前，必须能指向对应需求文档或补齐需求说明。
- 完成任务后，负责人需要更新相关设计文档或开发记录。
- 如果任务存在跨部门依赖，先拆成子任务，避免一个任务同时卡住多个部门。

## 状态定义

| 状态 | 含义 |
|------|------|
| Backlog | 已记录，未排期 |
| Ready | 需求清楚，可以开始 |
| Doing | 正在处理 |
| Review | 等待验收或决策 |
| Done | 已完成并更新文档 |
| Blocked | 被外部条件阻塞 |
