# 09-动态标题页文字与布局方案

> 版本: 0.1.0 | 状态: 方案冻结，待用户确认后分派实现 | 最后更新: 2026-07-27
>
> 适用范围: `Title.tscn` 的动态背景上运行时文字与菜单。本文是动态标题页布局的唯一来源；不修改标题流程、按钮语义或背景资源本身。

---

## 1. 范围与前提

- 背景母版为 `D:\用户目录\Videos\标题页s1.mp4`。UI 不向视频或背景图烘焙标题、菜单、版本号、按钮文字或版本信息。
- 已知构图前提为“不周天柱残骸/天倾断脊”主体在右，左侧留作标题与菜单安全区。动态背景向超宽屏两侧延展时，不移动核心 UI 构图。
- 当前环境可读取母版文件，但没有可用的视频解码工具，未能逐帧检查云层、天光和前景运动。本文以任务提供的构图描述和既有美术规范为依据；资源接入后须在实际循环画面上做一次可读性复核。
- 保持既有流程：`开始游戏` 进入角色选择；`时间线`、`设置`、`退出游戏` 的业务行为仍以 [01-MVP界面交互.md](./01-MVP界面交互.md) 为准。本方案只替换其视觉布局口径。

## 2. 推荐方案: 左侧题签与疏朗纵向菜单

### 2.1 视觉结构

标题和菜单组成一个无厚重面板的左侧文字组：标题在左上偏中，菜单在其下方偏左，留出中部与右侧完整展示天倾断脊。标题采用古朴、略带毛笔骨力的 CJK 可缩放字体，不使用位图字或把字画进背景。

| 元素 | 推荐表现 | 颜色与可读性 |
|------|----------|--------------|
| 游戏标题 `洪荒之后` | 左对齐，两行以内；主字宽厚而不做夸张书法飞白。可在标题左侧保留一条极细的竖向墨痕作结构，不使用印章、徽章或独立卡片包裹。 | 主字 `#D4C9B8`，少量旧铜暗金 `#8B6A36` 作下缘/细节；使用深墨描边与柔和阴影，不做外发光。 |
| 标题副信息 | 默认不新增世界观文案或营销标语。仅允许显示运行时构建信息或发行渠道要求的短辅助文本，且弱于标题。 | `#9E9588`，不超过标题字号的 22%。 |
| 菜单 | 左对齐纵向四项：开始游戏、时间线、设置、退出游戏。以文字、短横墨线和细边框构成，不做大圆角、厚底或宣传式卡片。 | 正常文字 `#D4C9B8`；`开始游戏` 以古金边线和更高文字权重作为唯一主操作。 |
| 版本号 | 左下安全区，靠标题组对齐，不占用右下主体与动态前景。 | `#8F887E`，小号、半透明；不与菜单竞争。 |
| 局部压暗 | 从左边缘到画面中线前的低频墨色渐变，仅为文字提供稳定底对比。 | 深墨 `#10100D`，左侧 alpha 建议 `0.46`，在 `x=48%` 前平滑降至 `0`；不得使用全屏黑罩、明显几何面板或高频噪点。 |

标题、菜单和版本号都属于 Godot 实时 UI；暗化层只属于背景表现层，不截获鼠标、触摸或键盘输入。

### 2.2 1920 x 1080 锚点与安全区

下表所有值均为设计分辨率逻辑像素。百分比相对完整 1920 x 1080 画布；在 16:9 分辨率下按等比缩放，不以屏幕宽度重新计算字号。

| 区域/控件 | 逻辑矩形或锚点 | 百分比范围 | 约束与验收意义 |
|-----------|----------------|------------|----------------|
| 左侧 UI 安全区 | `x=128..768, y=168..912` | `x=6.7%..40.0%`, `y=15.6%..84.4%` | 标题与菜单所有可见内容、hover 边线和焦点环均不得越出此区；右侧主体不被文字遮挡。 |
| 标题组 | `Rect2(152, 204, 560, 156)` | `x=7.9%..37.1%`, `y=18.9%..33.3%` | 标题左对齐；推荐字号 `112px`，行高约 `1.0`，描边 `3px`、阴影 Y 偏移 `6px`。长标题不得缩小到低于 `88px`，而应按不超过两行换行。 |
| 菜单组 | `Rect2(156, 516, 384, 314)` | `x=8.1%..28.1%`, `y=47.8%..76.9%` | 四项垂直排列；每项点击框 `384 x 68px`，项间距 `14px`。菜单文字基准字号 `28px`，主按钮可为 `30px`。 |
| 菜单文字起点 | `(184, 每项中心线)` | 左边距 `9.4%` | 所有菜单标签统一左对齐；短横墨线、焦点环和点击框围绕同一轴，不让每项因文字长度跳动。 |
| 版本号 | `Rect2(156, 1000, 384, 28)` | `x=8.1%..28.1%`, `y=92.6%..95.2%` | 左对齐，推荐 `16px`；与最后一项菜单至少保留 `150px` 垂直空白。 |
| 局部暗化影响区 | `x=0..922, y=0..1080` | `x=0%..48.0%` | 渐变终点须落在标题/菜单右边界之外；右半主体区域 alpha 为 `0`。 |

### 2.3 菜单交互状态

| 状态 | 视觉行为 | 输入/动画约束 |
|------|----------|---------------|
| 默认 | 米白文字、低对比短横线；主按钮保留暗金细边，其余项只保留淡墨基线。 | 文字与点击框稳定，不随背景运动漂移。 |
| Hover | 当前项文字提亮至米白偏暖，出现 `2px` 古金细边或墨线延展；其它项保持原状。 | 只在当前项产生 `120~160ms` 渐显，不位移整组，不遮挡相邻项。 |
| Pressed | 当前项整体向下 `2px`，边线转深，文字亮度略降。 | 按下反馈不超过 `80ms`；释放后立即触发既有按钮业务行为。 |
| Disabled | 文字与线条降至约 `45%` 不透明度，移除金色焦点，并保持文字可辨。 | 不接收鼠标、触摸、键盘确认；不得用“暂无功能”的假成功反馈替代禁用语义。 |
| 键盘焦点 | 文字外出现完整但克制的古金焦点环，左侧加短竖线；hover 与焦点同时存在时以焦点环为准。 | Tab/方向键移动顺序固定为“开始游戏 → 时间线 → 设置 → 退出游戏”；Enter/Space 触发现有行为。 |

`开始游戏` 是唯一视觉主操作，不能因 hover 或焦点把其它项变成同权重的金色大按钮。菜单出现可沿现有顺序逐项淡入，间隔 `100ms`；背景视频不可因菜单动画暂停或被整屏遮住。

## 3. 响应式与 Godot 装配建议

### 3.1 分辨率规则

| 目标视口 | UI 布局规则 | 最低可读性要求 |
|----------|------------|----------------|
| 1920 x 1080 | 直接使用第 2.2 节逻辑锚点。 | 标题、四个菜单项、版本号完整可见；右侧主视觉没有文字遮挡。 |
| 1280 x 720 | 以 16:9 等比缩放；逻辑 `68px` 菜单点击框约为 `45px` 高。 | 标题约 `75px`、菜单约 `19px`；焦点环、描边和版本号不重叠、不裁切。 |
| 2560 x 1440 | 以 `1.333x` 等比缩放同一逻辑画布。 | 字体由矢量/动态字体渲染，边缘清晰，不使用放大的位图字。 |
| 3840 x 2160 | 以 `2x` 等比缩放同一逻辑画布。 | 标题约 `224px` 物理显示，描边/阴影等比例放大且不锯齿。 |
| 常见超宽屏 | 保持以屏幕高度计算的居中 16:9 `TitleSafeArea`；标题与菜单继续使用其左侧锚点，额外宽度只展示背景环境。 | 不把 UI 拉到物理屏幕最左；不横向拉伸按钮，不因超宽屏移动到右侧主体上。 |

### 3.2 容器与锚点建议

- 根层分为全屏 `DynamicBackground`、不截获输入的 `TitleReadabilityGradient`、居中的 16:9 `TitleSafeArea` 和其内的 `TitleStack`/`MenuStack`/`VersionLabel`。动态背景独立覆盖实际 viewport，UI 仅在安全区内布局。
- `TitleSafeArea` 以 viewport 高度推导宽度 `height * 16 / 9` 并水平居中；16:9 时即为整张逻辑画布。超宽屏只扩展背景，不改变标题、菜单的逻辑坐标与相互关系。
- 菜单使用容器负责垂直间距和焦点顺序；标题、版本号使用锚点相对 `TitleSafeArea` 放置。正式接入应使用 `.tscn`、集中 Theme 与可复用按钮控件，不能在控制器中散落颜色、字体尺寸或绝对位置字符串。
- 字号、描边、阴影以设计逻辑单位定义，交给 viewport 等比缩放；不得用 `vw`、按宽度动态放大字号或把标题转成一张位图。

## 4. 动态背景可读性约束

1. 左侧局部渐变必须是低频、静止或仅极轻微呼吸的墨色层；不得跟随云层逐帧变化，避免标题对比闪烁。
2. 当循环中天光进入左侧安全区时，暗化层的最低对比仍须使标题轮廓和菜单文字可读；可在标题文字自身保留固定描边/阴影，但不增加全屏遮罩。
3. 菜单 hover、焦点环与按钮线条不使用持续闪烁、粒子或高饱和霓虹。动态画面已经承担氛围，UI 只承担定位和操作。
4. 背景母版的右侧主体、断脊轮廓和高对比天光不得被标题、菜单、版本号、调试文本或临时提示覆盖。运行时错误提示如必须出现，应暂居左侧安全区并在消失后恢复本布局。

## 5. 实现交付与验收口径

### 5.1 给开发部的实现约束

- 本任务仅为方案，后续接入应新建或调整标题 UI 的 `.tscn` 组合、Theme/字体资源与复用按钮控件；禁止把文本、颜色、暗化范围和坐标继续集中写入 `TitleController` 的动态 UI 构建代码。
- 背景视频播放、场景切换、退出和设置业务行为仍由既有明确流程负责人决定。标题 UI 仅提交开始、时间线、设置、退出意图，不管理角色初始化或场景流程。
- 任何视频循环、加载失败或低性能降级都不得改写 UI 锚点；背景不可用时可以显示无文字的同色静态后备背景，标题/菜单仍按本文可用。

### 5.2 最小窗口验收

| 场景 | 通过标准 | 失败判定 |
|------|----------|----------|
| 1920 x 1080 动态循环 | 左侧标题/菜单始终稳定可读；右侧不周断脊主体无遮挡；局部暗化没有可见硬边。 | 文字随视频明暗失读、整屏变黑、菜单覆盖右侧主体或出现营销式大面板。 |
| 1280 x 720 | 四个菜单项均完整可点，焦点/hover 边线不重叠，版本号未裁切。 | 点击框过小、文字折断、菜单超出安全区或按钮相互压盖。 |
| 2560 x 1440 与 3840 x 2160 | 同一相对构图，字体/描边清晰，未使用像素化标题图。 | 高分辨率出现位图放大、过细不可读描边，或 UI 比例与 1080p 明显失衡。 |
| 超宽屏 | 标题组位于居中 16:9 安全区的左侧，左右新增区域只展示环境；右侧主体仍清楚。 | UI 被钉到物理最左、横向拉伸，或因额外宽度移入主体区域。 |
| 键鼠操作 | Hover、pressed、disabled、键盘焦点符合第 2.3 节；开始游戏与退出保留现有可用语义。 | 无焦点可见反馈、禁用项仍可触发、hover 使整组跳位或改变业务流程。 |

## 6. 风险与待用户确认

| 项目 | 默认建议 | 需要确认的原因 |
|------|----------|----------------|
| 标题字体 | 先用授权明确、支持完整中文的可缩放古朴衬线/题字风字体；后续可替换为正式题字字体资源。 | 最终题字风格直接影响世界观首屏识别，需要确认字体授权与笔触强度。 |
| 左侧压暗强度 | 先按左缘 alpha `0.46`、`x=48%` 衰减至零接入。 | 实际视频循环的天光强度尚未逐帧检查，接入后可能需在 `0.40~0.52` 范围内一次微调。 |
| 标题副信息 | 默认不显示副标题或标语，只保留版本号。 | 若发行需要平台、版权或额外短句，应由用户确认文本与优先级，避免擅自扩写世界观。 |

除上述三项外，本方案无须用户决定即可进入实现任务分派。
