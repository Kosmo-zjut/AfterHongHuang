### P1-008 布局微调口径

| 区域 | 调整 | 验收要求 |
|------|------|----------|
| A 区：底部角色栏 | 整体下移 | 角色栏更靠近画面底部，但所有头像、锁定标记、随机入口仍完整可见，不贴边、不被窗口裁切 |
| B 区：开始游戏按钮 | 整体下移 | 按钮位于右侧信息面板下部，视觉上靠近底部操作区；不遮挡角色栏，不与 C 区生命统计重叠 |
| C 区：统计信息 | 精简为单行生命统计 | 只显示红心图标或红色心形文本、冒号、当前生命/生命上限，例如 `心：80/80`；不得显示初始牌组、灵力、回合、职业属性等冗余文本 |

C 区占位规则：

- 若暂无正式图标，可用红色文本心形或可替换图标占位。
- 文案只允许 `心：当前生命/生命上限` 这种短格式。
- 初始牌组可在后续单独做“牌组预览/详情”入口，但不得塞回 C 区统计行。

### 角色头像状态

| 状态 | 视觉 | 适用角色（MVP） |
|------|------|:--:|
| **已解锁·选中** | 正常色彩 + 金色边框 + ✓ 标记 | 巫祝 |
| **已解锁·未选中** | 正常色彩，无特殊边框 | — |
| **锁定** | 灰度 + 🔒 图标，无法点击 | 盗宝者 / 截教门徒 / 金乌遗孤 / 凡人 |
| **随机** | 骰子/问号图标，无锁定状态 | 随机按钮始终可用（但 MVP 仅巫祝可选，随机 = 必选巫祝） |

### 交互流程

```
1. 从标题界面进入 → 默认选中"巫祝"
   ├── 背景展示巫祝个人插画（淡入 0.5s）
   └── 巫祝头像显示选中态（金色边框 + ✓）
2. 玩家点击底部头像：
   ├── 点击已解锁角色 → 切换选中
   │   ├── 背景交叉淡入淡出到新角色插画（0.4s）
   │   ├── 旧头像取消选中态，新头像高亮
   │   └── 右侧面板刷新为新角色信息
   ├── 点击锁定角色 → 无反应（可播放锁定抖动微动画提示）
   └── 点击随机 → 从未锁定角色中随机选取（MVP 仅巫祝 → 等于选巫祝）
3. 悬停头像 → 放大 110% + 显示角色名称 tooltip（0.15s）
4. 点击"开始游戏" → 按钮按下动画 → 场景淡出（0.4s）→ 进入道痕选择
```

### MVP 特殊处理

- 后 4 个角色头像显示但灰掉，**不是隐藏**——让玩家感知到"还有其他角色，只是还没开放"
- 随机按钮可点击（虽然 MVP 只有巫祝），为后续多角色预留交互逻辑
- 每锁定角色悬停时可显示 tooltip："此角色将在后续版本中开放"

### 地图稳定布局与可读性验收

- 横向 lane 顺序固定由 `LayerIndex` 决定；同一层纵向顺序固定由生产 `NodeId`/`IndexInLayer` 决定，不能因当前可达节点筛选、字典顺序、鼠标悬停或窗口刷新重新排序。
- 节点视觉框与点击热区分离定义：热区必须是真实可命中的 `Control` 尺寸，允许在视觉框外保留小幅安全边距，但不得与同层相邻节点重叠；不能只设置 `CustomMinimumSize` 后假定有点击区域。
- 连线先绘制、节点后绘制；连线 ZIndex/场景顺序低于节点按钮，不能穿过节点文字、图标或状态徽记。连线不得拦截鼠标。
- 相邻两层的边必须保持 lane 顺序：左侧来源节点连向左侧/同序目标时，不得越过右侧来源节点连向更左目标；同一来源的分叉和多个来源汇合属于合法结构，不算交叉。
- 生产图的交叉数必须为 0。若生成图存在交叉，应该由 MapGraph Validator 拒绝或重新生成，UI 不通过弯曲连线、隐藏线段、降低透明度或缩放来“美化”错误。
- 当前可达节点使用高亮边框/亮度和清晰 tooltip；当前节点使用独立当前位置标记；已走路线保留低亮连线和“已访问”状态；锁定/不可达节点灰暗且不可点击。四种状态不能只依赖颜色，至少同时使用图标、边框或文字标记。
- 点击区域只允许进入当前 `NodeContext` 指定的下一节点；MapOverlay 在战斗、灵脉、商店、问号和 Boss 页面只读，不得通过地图进入另一个节点。
- UI 验收必须固定同一 `RunSeed` 检查重复打开地图的位置一致；生产验收还要覆盖生成器提供的多 seed 图，不能只看一张人工示意图。

### 交互流程

#### 道韵选择逻辑

```
1. 进 MapScene → 底页直接渲染 3 张道韵卡（非 overlay）
2. 点击"固化" → 原地切换：
   ├── 标题变为"道痕已固化"
   ├── 选中卡片保持亮色 + 底部显示"✓ 已固化"
   ├── 其余两张变灰（Modulate 35%）
   └── 所有"固化"按钮隐藏
3. 固化不可撤销。道韵状态通过 GameManager.CurrentChoices 持久化
```

#### 地图呼出逻辑

```
TopBar 地图按钮 → toggle：
  ├── overlay 关闭 → 固定左边界，从左向右揭示（0→视口宽度，300ms）
  └── overlay 打开 → 反向收卷（视口宽度→0，220ms），节点页保持不变

MapOverlay 打开后：
  ├── 鼠标滚轮 → 横向滚动，位置 clamp 在 [0, 内容宽度-视口宽度]
  ├── 左键按住并移动超过拖拽阈值 → 横向拖拽，位置同样 clamp
  ├── 移动未超过阈值并释放 → 视为节点点击候选
  └── 已超过阈值 → 只结束拖拽，不触发节点点击

道韵节点始终可点击；其他节点：
  ├── 道痕未固化 → 灰色不可点击，tooltip "需先固化道痕"
  ├── 已固化 + 从当前层可达 → 按节点类型进入对应 NodePage
  └── 已访问 → 灰色，不可重复点击
```

### 地图 overlay 视口与输入验收（P1-019 / BUG-20260716-004）

| 项目 | 冻结口径 | 通过标准 | 失败判定 |
|------|----------|----------|----------|
| 视口宽度 | 由 `MapGraph` 内容宽度、节点宽度和间距计算；不得只容纳当前可视层 | 后续层存在时可通过横向移动查看，节点不被永久裁切 | 内容宽度写死、后续层不可见或靠缩放挤在一屏 |
| 左侧起点与动画 | overlay 左边界固定；通过 Clip/Mask 或等价揭示从左向右展开，建议 300ms；关闭反向 220ms | 开关时地图内容从左边界向右揭示，底层节点页不被销毁或重建 | 整个面板从右侧位移进入，或打开时切换/清空底层页面 |
| 初始定位 | 打开后优先将当前节点置于视口安全区，仍保留前后层可查看范围 | 当前节点可见且不贴边；可继续滚动查看前后节点 | 打开后落在地图远端、当前节点不可见或只能看当前层 |
| 滚轮横移 | 纵向滚轮转换为横向偏移，推荐每个滚轮步长约 `160px`；输入只作用于 MapOverlay | 视口沿 X 轴连续移动，底层节点页不响应滚轮 | 只能纵向滚动、滚轮穿透底层或地图跳出视口 |
| 左键拖拽 | 按下记录起点；移动超过 `8px` 进入拖拽；拖拽释放不点击节点 | 拖拽可查看前后层，超过阈值后不触发节点进入 | 一拖地图就进入节点，或拖拽不足阈值却无法点击 |
| 边界 clamp | 横向偏移限制为 `[0, max(0, ContentWidth - ViewportWidth)]`；无内容溢出时偏移固定为 `0` | 拖拽和滚轮到边界后停止，不露出空白地图外区域 | 越界露出底色/空白，或到边界后无法返回 |
| 输入层级 | MapOverlay 打开时独占内容区输入并覆盖 NodeContinue；TopBar 保持可交互 | 战斗进行中只读；Battle 胜利、Lingmai、Shop、Event 按 NodeContext 可点击合法节点。关闭后精确恢复原节点页 | 地图 overlay 穿透到底页、战斗中进入新节点、Continue 在地图上仍可点，或合法节点无法点击 |
| 关闭恢复 | 再点地图按钮、收卷或返回键只关闭 overlay | 原节点页、结果页、奖励状态和滚动前的业务状态保持；重新打开不创建第二份地图 | 关闭后进入空白 MapScene、清空结果或叠开多个 overlay |

### 地图全展开布局与留白

MapOverlay 完全展开后，地图内容必须以视口中心为基准布置，而不是贴右或把有效节点挤到边缘。地图横向溢出时允许滚动/拖拽；“居中”指地图内容的纵向中心与可视区域中心对齐，且初始横向视图围绕当前节点附近建立，而非强行压缩整张地图。

| 项目 | 1920×1080 冻结口径 | 1280×720 等比缩放口径 | 失败判定 |
|------|-------------------|--------------------------|----------|
| 全展开地图视口 | 建议 `Rect2(64, 104, 1792, 872)`；固定左起揭示完成后不改变左边界 | 按 Canvas 等比缩放，保留完整视口比例 | 右侧抽屉位移、视口贴边或覆盖 TopBar |
| 垂直居中与留白 | 地图内容包围盒中心对齐视口中心；上下空白各至少约 `160px`，且明显大于左右安全边距 | 上下各至少约 `100px`，保持大于左右边距 | 节点/连线贴近顶部或底部，或上下留白小于左右留白 |
| 横向边距与初始位置 | 内容边界在可滚动极限处保留 `64~96px` 侧边距；初始视图将当前节点置于视口宽度 `40%~55%` 区域 | 侧边距 `32~64px`；当前节点仍不贴边 | 当前节点或首/末层贴右，后续层无法到达 |
| 滚轮与拖拽范围 | 维持横向滚轮步长约 `160px`、拖拽阈值 `8px`、`[0, max(0, ContentWidth-ViewportWidth)]` clamp | 逻辑偏移和阈值按设计坐标换算；拖拽后不得触发节点 | 拖拽误进节点、边界露出空白或无法查看最远节点 |

### 选择规则

- 道痕：点击"固化"即确认，**不可撤销**
- 3 张卡片从 `DaoMarkPool` 中随机抽取
- MVP 阶段：3 条有道效果的道痕（九乌坠日/符修遗箓/体修金刚）
- 道痕固化后，效果立即存档，进入战斗时开始生效
- **未选道痕不能打怪**——强制流程约束

### 选项分组

| 分组 | 选项 | MVP 口径 | 不可用表现 |
|------|------|----------|------------|
| 常规选项 | 休养生息 | 恢复生命，建议为生命上限 30%，不超过生命上限；满血仍可选择一次 | 不做初始禁用。满血点击后生命数值可不变化，但必须显示“灵脉平稳，气血已满”与一次性“已调息”反馈，并将该选项灰置 |

### 交互流程

1. 玩家从地图 overlay 点击可达的灵脉节点，切换到独立 LingmaiNode 页面；地图 overlay 在场景切换时关闭，不能残留或穿透输入。
2. 玩家选择一个可用选项：
   - `休养生息`：立即结算一次；满血时显示“灵脉平稳，气血已满”，不要求生命数值变化，但仍显示“已调息”并灰置该选项。
   - `精进道行`：进入卡牌选择子界面；选择卡牌后返回灵脉结算态。
   - `疗愈道友`：仅在后续存在同行道友且规则开放时可用。
   - `法宝触发选项`：仅在法宝/道器提供可触发效果时出现。
3. 选项结算完成后，页面保留当前结果态；由场景协调层按规则标记灵脉已访问。页面不出现“返回地图”或“放弃灵脉并继续前行”按钮。
4. 未选择行动时，外置 `继续` 仍可用；点击仅打开当前 LingmaiNode 上方的 MapOverlay，不提交 `NodeResult`、不消耗灵脉、不写 `VisitedNodeIds`、不产生收益或离场。只有地图内点击合法下一节点时才进入离场流程。
5. 已成功结算的灵脉选项立即灰置且不可再次触发；其他不可用项保持禁用/隐藏并说明原因。已成功结算的灵脉不可重复领取；再次点击节点应显示已访问/已枯竭态，不再进入结算。

### 文案与状态边界

- 固定术语：`灵脉节点`、`休养生息`、`精进道行`、`疗愈道友`、`法宝`、`道器`、`斗劲`。
- 禁用外部术语：不得出现`火堆`、`遗物`、`力量`等其他游戏体系词。
- 不可用选项必须禁用或隐藏，并给出原因；`休养生息` 的满血点击是明确允许的一次性调息反馈，不属于“可点但无效果”。
- MVP 阶段不要求完整法宝/队友系统；UI 只预留分组和状态，不伪造未实现效果。疗愈道友的显示/隐藏只依赖可用友方目标列表，单人状态只是该列表为空的一个来源。
- 需要策划部补齐：卡牌强化的具体升级表、队友治疗规则、法宝/道器触发条件。
- 需要开发部保证：LingmaiNode 的成功行动通过统一 NodeResult 持久化访问状态；未选行动不得直接写 `VisitedNodeIds`，外置 Continue 入口也不得提交 NodeResult 或切换场景；已执行选项灰置且已访问节点不可重复领取。

## Act1 NodePage 页面与 Overlay 契约（ACT1-UI-CONTRACT-20260713）

本节是第一大关新增节点的 UI/UX 统一口径。它定义页面层级、输入边界、场景入口/退出和验收方式；不定义战斗数值、商店价格、事件结果或 Boss 玩法规则。

### 1. 统一 NodePage 壳层

每个节点都使用同一套页面骨架。节点页面是底层内容；生命、套牌信息、地图进度属于运行状态，由 TopBar 和呼出 overlay 独立展示。

```text
NodePageRoot
  ├── Background
  ├── NodeContent                 # Battle / Lingmai / Shop / Event / Boss
  ├── TopBar                      # 固定，读取 RunState
  ├── NodeContinue                # 固定右侧偏下；节点本地继续，打开地图
  ├── OverlayHost
  │   ├── MapOverlay              # 共享地图视口，卷轴视觉
  │   ├── DeckOverlay             # 呼出式套牌信息
  │   └── SettingsOverlay         # 呼出式设置
  └── TransitionLayer             # 场景切换/错误提示，不承载玩法状态
```

推荐 1920×1080 下的显示层级和输入规则：

| 相对内容层级 | 层级 | 输入规则 | 打开/关闭 |
|-------------|------|----------|-----------|
| 0~49 | 当前节点底层页面 | 只接收当前节点允许的操作 | 进入节点创建，退出节点销毁 |
| 50~79 | TopBar | 唯一常驻全局可交互层：套牌、地图、设置入口 | 位于内容区遮罩之外；胜利、奖励、地图 overlay 不得阻断 |
| 节点本地层（集中常量） | NodeContinue | 节点主面板外的“继续”；仅开/关地图，不结算、不离场、不消费 | 高于当前节点主面板；低于 MapOverlay/CardRewardOverlay；不得新增或改写既有数值区间 |
| 节点内容覆盖层（集中常量） | MapOverlay | 打开后独占 overlay 区输入；不得穿透到底层 | TopBar/NodeContinue 均可请求打开；激活时覆盖当前 NodeContent、VictoryPanel、CardRewardOverlay 与 NodeContinue，收卷后恢复 |
| 200~299 | DeckOverlay | 只读查看套牌；不得改变 RunState | 套牌按钮 toggle；关闭按钮、再次点击或返回键关闭 |
| 300~399 | SettingsOverlay | 模态独占全部输入 | 设置按钮打开；关闭按钮或返回键关闭 |
| 400~449 | VictoryModal | 胜利遮罩与总奖励面板独占 TopBar 下缘以下内容区输入；TopBar 始终可操作 | 敌人死亡进入胜利结果时打开；仅合法地图节点点击后离场 |
| 节点内容覆盖层（集中常量） | VictoryMapOverlay | 胜利页地图独占内容区输入；覆盖 VictoryPanel、CardRewardOverlay 与 NodeContinue；关闭后回打开前的胜利/奖励焦点 | 由本地“继续”或 TopBar 地图入口打开；收卷/返回键关闭；合法节点点击后离场 |
| 胜利局部模态层（集中常量） | CardRewardOverlay | 卡牌奖励局部模态，位于胜利总面板之上、地图之下；地图激活时仅保留状态且不得接收输入，TopBar 仍可操作 | 由奖励行打开；跳过/关闭只关自身，完成后回总面板；地图关闭后恢复原候选与已选进度 |
| 490~499 | Transition/Error | 阻断所有输入，直到完成或返回 | 只用于切换、错误和明确结果提示 |

壳层硬规则：

- 同一时间最多一个 Map/Deck/Settings overlay；打开新 overlay 时先关闭旧 overlay，不创建副本。
- 当前打开 overlay 获得输入焦点，底层页面和其他 overlay 的鼠标事件全部拦截；关闭后焦点回到打开按钮或当前节点。TopBar 是唯一例外：它保持全局可操作，并通过现有协调链恢复原焦点。
- MapOverlay 在 MapScene/地图探索页、BattleNode 胜利结果、LingmaiNode 与 ShopNode 中按 NodeContext 可操作合法节点；战斗进行中只读。EventNode/BossNode 是否可操作由 NodeContext 明示，UI 不以“是否结算完成”猜测。
- DeckOverlay 在所有节点页面均只读，不会抽牌、换牌、重置手牌或修改牌组；设置 overlay 也不得改变节点进度。
- TopBar 在所有节点读取 RunState 的当前/最大生命、永久套牌摘要、灵韵、道痕/法宝和地图进度；非 BattleNode 不显示当前回合灵力、护体、斗劲或其他战斗临时状态。
- BattleNode 的当前回合灵力、护体、斗劲、易损/永炎等临时状态只读取 BattleState；BattleState 不得被 TopBar 当作 RunState 跨节点保存。
- 页面切换时关闭所有 overlay、清除 hover/选中/拖拽/滚动/动画中间态；不能把旧节点的弹窗、按钮或输入回调带到新页面。
- `VictoryModal` 是 TopBar 下缘以下内容区的输入边界，不以逐个禁用手牌、日志、结束回合或 Debug 控件替代。其遮罩不得覆盖或阻断 TopBar；胜利和 CardReward 期间 TopBar 的地图、套牌、设置入口始终可操作。胜利页地图激活时必须覆盖 CardReward 与 Continue；地图关闭后恢复原 CardReward 候选和进度。CardReward、胜利页地图或任一 TopBar overlay 关闭后，只恢复其打开前的胜利/奖励焦点，不恢复战斗输入。
- `NodeContinue` 在 BattleNode 胜利结果、LingmaiNode、ShopNode、EventNode 的位置与文案一致：视口右下 `right=64px`、`bottom=72px`、`200×64px`（1920×1080）；固定文案为“继续”，tooltip 为“打开地图卷轴”。它和 TopBar 地图按钮调用同一 toggle，不得分叉为结算、离场、消费、清页逻辑。MapOverlay 与 CardRewardOverlay 必须覆盖/阻断它；TopBar 不受影响。

#### NodeContinue 与 TopBar 验收

| 页面/状态 | 外置入口文案与位置 | 灰置规则 | 必须保持的状态 |
|-----------|------------------|----------|----------------|
| BattleNode 胜利 | `继续`，视口右下统一锚点；主面板内无继续按钮 | 仅地图动画、Transition/Error 或无有效地图上下文时灰置；CardReward/Map 打开时被覆盖并不可点 | 未领灵韵、CardReward 计划、已领进度和胜利面板均不变 |
| LingmaiNode 未选择/已选择 | `继续`，同一锚点；不得出现“返回地图/放弃灵脉” | 未选择时不可灰置；成功选择后仅该灵脉选项灰置，继续仍可用；Map 打开时被覆盖 | 未选择不写访问状态；成功选择后结果与灰置状态保留 |
| ShopNode / EventNode | `继续`，同一锚点；不以文案暗示结算或离场 | 商品/事件选项按自身规则灰置；继续不随其状态灰置，Map 打开时被覆盖 | 余额、库存、事件结果、已选状态和当前详情保留 |
| TopBar 横条 | TopBar 背景连续覆盖全宽 `0..ViewportWidth`、高度 `44px`；右侧菜单组 `right=24px`、间距 `8px` | 胜利、CardReward、地图 overlay 不得整体阻断 | 1920×1080 与 1280×720 均不得在右侧菜单前后出现透明/空白/断裂区域；地图、套牌、设置热区完整可点 |

### 2. 场景入口与退出契约

节点页面只读取上下文并发出命令，不直接初始化角色或重建牌组。以下是 UI 层需要遵守的概念契约，具体类型由开发部按现有工程实现适配：

```text
NodeContext = {
  node_id, node_type, act_id, map_layer, map_index,
  entry_source,                 # Map / VictoryContinue / Debug
  map_read_only, consume_policy
}

NodePage.Enter(RunStateSnapshot, NodeContext)
  -> 页面只读渲染当前状态

BattleNode.Enter(RunStateSnapshot, BattleStateSnapshot, NodeContext)
  -> 只在战斗页面读取当前回合和敌人运行态

UI Command = {
  OpenOverlay | CloseOverlay | SelectOption | PurchaseItem |
  StartBattle | ConfirmTarget | ClaimReward | LeaveNode
}

NodeResult = {
  node_id, status, consume_node, payload, return_target
}
```

入口/退出约束：

1. 进入节点时由上层提供 `RunStateSnapshot + NodeContext`；BattleNode 另接收该战斗的 `BattleStateSnapshot`。页面不得调用 `InitCharacter`，不得重置 RunState 的生命、永久套牌、灵韵、道痕或地图进度；新战斗可按玩法命令创建新的 BattleState。
2. UI 操作只触发命令并等待结果；结算成功、取消、返回、失败都要有明确状态，不能用“关闭页面”代替未定义的成功。
3. `NodeResult` 返回给场景协调层，再由协调层更新 RunState、访问状态和下一节点；UI 不直接猜测节点是否消耗。
4. 若当前节点上下文无效，显示“节点不可用/返回地图”错误态，并记录错误；不能静默跳到标题或重置角色。
5. `consume_policy` 由节点规则提供。Act1 推荐：Battle/Boss 在胜利结算后消耗；Lingmai 只有成功行动后消耗；Shop/Event 按节点规则在离开或选项结算时消耗，不能由 UI 硬编码牌名或按钮文本猜测。

### 3. NodePage 通用状态机

```text
Entering → Ready
             ├── OverlayOpen(Map/Deck/Settings) ↔ Ready
             ├── Resolving → Result → Leaving
             ├── Invalid → Leaving
             └── LeaveRequested → Leaving
Leaving → NodeResult 返回场景协调层
```

Overlay 状态与节点业务状态正交：打开地图/套牌/设置不会重置当前页面状态；BattleNode 的 BattleState 只在战斗页面内保持，离开战斗结算后按结果提交并销毁。结算状态下可按页面规则禁用 TopBar，避免在结果写入前切走。

### 4. 五类节点页面结构与状态机

#### 4.1 BattleNode

页面结构：`TopBar + 战斗场景/双方状态 + 手牌区 + 灵力/结束回合 + 战斗日志开关 + VictoryResult`。地图 overlay 只读，套牌 overlay 只读。

```text
Entering → PlayerTurn ↔ CardTargeting
PlayerTurn → EnemyTurn → PlayerTurn
PlayerTurn → Victory → RewardOverlay → MapOverlay → Leaving（仅点击合法下一节点）
PlayerTurn → Defeat → Result → Leaving
```

- 敌方目标牌：从选中卡牌指出上凸箭头；默认自身/无目标牌按既有 P0-012 口径点击/长按进入持牌状态。
- VictoryResult 就地显示；CardReward 叠在胜利结果上方，选卡或跳过后回到胜利结果。
- VictoryResult 保持为当前 BattleNode 的结果页；奖励领取/跳过只更新对应奖励行或 overlay，不提前销毁结果页。
- 主面板外置 `继续` 与 TopBar 地图按钮都只打开/关闭当前页面上的 MapOverlay；`继续` 的 tooltip 为“打开地图卷轴”，地图不是其按钮文字。关闭 overlay 必须恢复同一胜利页与奖励状态。不得在 VictoryResult 主面板内保留“继续”按钮。只有在地图中点击合法下一节点时，才提交离场并进入目标 NodePage。

#### 4.2 LingmaiNode

页面结构：`TopBar + 灵脉说明 + 常规选项 + 条件选项 + 结果提示 + 主面板外的 NodeContinue`。页面独立于 MapScene；NodeContinue 打开的地图可选择合法下一节点。

```text
Entering → Choice
Choice → UpgradeSelection → Choice
Choice → Resolving → Completed → Leaving
Choice → LeaveRequested → Leaving
Invalid → Leaving
```

- `休养生息`：满血时初始仍可选择一次；点击后可不改变生命数值，但必须显示“灵脉平稳，气血已满”及一次性“已调息”反馈，并将该选项灰置。成功行动后按规则结算并消耗灵脉。
- `精进道行`：打开卡牌选择子页；取消只回到 Choice，不消耗灵脉；成功升级后结算并消耗灵脉。
- `疗愈道友`：只在 `AvailableFriendlyTargets`（或等价的可用友方目标列表）存在至少一个合法目标时渲染；列表为空时隐藏，不用散落的 `is_singleplay` 标志或假效果驱动。
- 法宝/道器触发项：只有上下文提供可用效果时显示；没有时隐藏或禁用并说明原因。
- 不设置“返回地图”或“放弃灵脉并继续前行”按钮。未选择行动时，NodeContinue 仍可打开/关闭当前页 MapOverlay；按钮本身不提交 `Exited/Skipped`、不消耗灵脉、不写访问状态。选择灵脉选项成功后，该选项灰置，NodeContinue 仍保持可用。

#### 4.3 ShopNode

页面结构：`TopBar + 商店标题/灵韵余额 + InventoryList + ItemDetail + PurchaseButton + 主面板外的 NodeContinue`。套牌 overlay 只读；NodeContinue 打开的地图可选择合法下一节点。

```text
Entering → Inventory
Inventory → ItemSelected → Inventory
ItemSelected → PurchaseResolving → Inventory
Inventory → LeaveRequested → Leaving
Invalid → Leaving
```

- 每个库存项显示名称、类型、价格、当前可购买状态和售罄状态；购买按钮必须是明确的“购买”动作，不用点击卡片本身暗示已扣款。
- 灵韵不足、已售罄、库存条件不满足时，购买按钮禁用并显示具体原因；不得扣除灵韵或伪造购买成功。
- 购买成功后余额、库存和牌组/法宝状态即时刷新；同一物品不能重复购买超过库存限制。
- 不设置“离开”或“完成商店结算”按钮。NodeContinue 与 TopBar 地图按钮仅开/关当前页 MapOverlay，不提交 `LeaveNode`、不结算商店、不消费节点；只有地图内点击合法下一节点才进入离场，节点消费时机仍由 `consume_policy` 决定。已购买/售罄/余额不足的商品保持灰置并显示原因，NodeContinue 不因此灰置。

#### 4.4 EventNode（问号事件）

页面结构：`TopBar + 事件标题/叙述 + OptionList + ResultPanel + 主面板外的 NodeContinue`。地图和套牌 overlay 只读，选项结算中不得切走。

```text
Entering → Options
Options → Resolving → Result
Result → MapOverlay（仅查看/选择合法下一节点） → Leaving
Options → MapOverlay（仅查看/选择合法下一节点） → Leaving
Invalid → Leaving
```

- 每个选项显示可见的风险/代价/收益提示；不可用选项禁用并说明原因。
- 选择后进入 Resolving，输入锁定，结果面板明确展示实际发生的生命、灵韵、牌组或节点状态变化。
- 明确的事件选项成功时提交一次 NodeResult；NodeContinue/TopBar 地图不提交、补写或推断 NodeResult。它们只保留当前选项/结果态并打开当前页 MapOverlay；关闭 overlay 回到原状态。同一事件选项不能重复触发；若规则允许未选择离开，由地图内合法节点转换和 `consume_policy` 决定消费时机，UI 不自行推断。

#### 4.5 BossNode

页面结构：`TopBar + Boss立绘/名称/简述 + 关底状态 + 开始斗法 + 结果/奖励区域`。进入战斗前地图只读；战斗中复用 BattleNode 的战斗交互，但上下文标记 `node_type=Boss`。

```text
Entering → Intro
Intro → BattleStarting → BattleNode
BattleNode → VictoryResult → ActResult → Leaving
BattleNode → DefeatResult → Retry/Leaving（由玩法规则决定）
Invalid → Leaving
```

- BossNode 是独立节点入口页，不直接把普通战斗页当作地图节点底页。
- 开始斗法前可查看 Boss 信息，但不得提前领取奖励或标记通关。
- 胜利后奖励和大关推进使用外置 `继续` / TopBar 地图入口；入口先打开当前页 MapOverlay，只有点击合法下一节点才清理旧节点 overlay 并原子进入目标页面，不在主面板内设置“继续/完成”按钮。

#### 4.6 节点按钮副作用统一表

所有生产按钮先执行其字面命令，再由结果状态决定是否允许打开地图 overlay。`地图`、`跳过`、`关闭`本身不消费奖励、不提交额外 NodeResult、不清空节点页、不直接调用 `GoToScene(Map)`；胜利、灵脉、商店不得用“继续/返回/离开/结算”充当地图入口。

| 页面/按钮 | 唯一命令 | 点击后的页面状态 | 允许离场的时机 | 禁止副作用 |
|-----------|----------|------------------|----------------|------------|
| BattleNode「NodeContinue / TopBar 地图」 | `ToggleOverlay(MapOverlay)` | VictoryResult 与未完成奖励行保留 | 仅 MapOverlay 点击合法下一节点后 | 不直接切 MapScene，不销毁胜利/奖励页，不领取奖励、不重复提交战斗结果 |
| BattleNode「卡牌奖励」 | `OpenOverlay(CardReward)` | 胜利页保持在下层 | 奖励完成/关闭后仍回胜利页 | 不因打开重抽候选或消费奖励 |
| LingmaiNode「NodeContinue / TopBar 地图」 | `ToggleOverlay(MapOverlay)` | 灵脉选项、结果页和未选择状态均保留；成功选项灰置 | 仅合法节点点击后离场 | 不提交 `Exited/Skipped`、不写 `VisitedNodeIds`、不消耗灵脉、不直接切 MapScene |
| ShopNode「NodeContinue / TopBar 地图」 | `ToggleOverlay(MapOverlay)` | 商店余额、库存、已购/禁用状态保留 | 仅合法节点点击后离场 | 不提交 `LeaveNode`、不结算商店、不消费节点、不直接切 MapScene |
| EventNode「NodeContinue / TopBar 地图」 | `ToggleOverlay(MapOverlay)` | 事件结果、已执行选项灰显和未选状态保留 | 仅合法节点点击后离场 | 不提交 `LeaveNode`、不结算事件、不清页、不重复触发选项 |
| CardReward「跳过/关闭」 | `CloseOverlay(CardReward)` | 胜利页奖励行恢复可见 | 不触发离场 | 不删除奖励行、不调用奖励放弃、不改永久牌组 |
| MapScene/MapOverlay「节点」 | 目标节点预检并提交离场 | 当前地图状态保持到预检成功 | 预检成功后原子进入目标 NodePage | 不允许锁定/不可达节点点击，不在拖拽释放时误触发 |

所有按钮验收都要同时检查：点击反馈、按钮禁用态、NodeResult 次数、RunState/BattleState 写入次数和页面生命周期。无效入口必须显示明确错误及可用的地图返回入口，不能出现只有 TopBar 的空白内容页。

### 5. 任意节点切换的状态保留与丢弃

| RunState：跨节点保留 | BattleState：只在战斗节点内保留，离战斗后提交/丢弃 |
|--------------------------------|--------------------------------|
| 当前生命/生命上限 | 本回合灵力、护体、斗劲 |
| 基础最大灵力（角色永久属性） | 易损、永炎及其他临时状态 |
| 永久套牌、卡牌升级/新增后的牌组结果 | 战斗抽牌堆、手牌、弃牌堆、消弭牌和敌人运行态 |
| 灵韵、道痕/法宝、Act/Seed、地图层/位置、已访问节点 | 战斗回合、敌人意图、战斗胜负和战斗日志中间态 |
| Act/Seed/地图进度（含已访问节点、已提交奖励和完成标记） | 当前 hover、选中、拖拽、目标高亮、节点选项草稿 |

RunState 不保存当前回合灵力、护体、斗劲、易损/永炎等 BattleState 字段。BattleNode 胜利/失败时只通过 `NodeResult` 提交允许跨节点的结果，例如当前生命变化、永久牌组变化、灵韵和奖励；离开 BattleNode 后清理 BattleState。

### 6. 第一大关窗口验收口径

以下清单用于可见窗口验收，不以 headless 存在节点作为通过依据。每项确认“入口 → 操作反馈 → 结果状态”。

| # | 操作 | 通过标准 | 失败判定 |
|---|------|----------|----------|
| 1 | 启动并进入 MapScene | 节点底页在下，TopBar 常驻；生命/套牌/地图进度可见且互不覆盖 | 进入旧摘要页、状态缺失或 UI 叠层错位 |
| 2 | 在 MapScene 打开/关闭地图 | 地图从固定左侧向右揭示；节点可操作；再次点击/收卷关闭；不生成第二张地图 | 右侧抽屉式位移、地图重复叠开、点击穿透或无法关闭 |
| 3 | 在 MapScene 打开/关闭套牌 | 套牌 overlay 只读显示当前牌组；toggle 可重复使用；关闭后底层状态不变 | 叠开多个页面、牌组被改动或状态重置 |
| 4 | 地图、套牌、设置互相切换 | 同时最多一层 overlay；新层关闭旧层；下层不接收鼠标 | 多层争抢输入、按钮穿透、关闭错层 |
| 5 | 进入 BattleNode | 战斗页独立；TopBar 与手牌、灵力、结束回合不重叠 | 战斗嵌在地图底页或进入时生命/牌组被初始化 |
| 6 | BattleNode 打开地图/套牌/设置 | 地图只读，套牌只读，设置模态；关闭后回到同一回合和同一手牌 | 可从战斗地图进入下一节点、overlay 改变战斗状态 |
| 7 | 战斗胜利与奖励 | VictoryResult 保持在当前节点；CardReward 在其上层；选卡完成后回到结果页，跳过只关闭 overlay；奖励行未完成前保留 | 奖励层销毁错误、候选重抽/换序、未完成奖励被删除或碎片占位复现 |
| 8 | 点外置继续 | 胜利/奖励页主面板外的 `继续` 与 TopBar 地图同样打开 MapOverlay；关闭后原页和奖励状态完整恢复；地图/CardReward 打开时 Continue 被覆盖；只有点击合法下一节点才离场 | 入口穿透地图/CardReward、直接切换空白 MapScene、销毁结果页，或点击继续即提交离场 |
| 9 | 进入 LingmaiNode | 独立灵脉页显示选项和主面板外 `继续`；未选择也可打开可交互地图并选择合法下一节点 | 仍显示 MapScene 旧灵脉底页、出现“返回/放弃”按钮或无入口 |
| 10 | 灵脉选择/不选择 | 满血休养生息初始可点，点击后显示一次性已调息并灰置；成功选项结算后灰置并按规则标记访问；未选择时 Continue 只开地图、不提交 `Exited/Skipped` | 满血初始禁用、重复点击已调息、疗愈道友在无合法目标时显示、点击继续即结算/离场、切换空白 MapScene |
| 11 | 进入 ShopNode | 独立商店页显示库存、余额、购买与主面板外 `继续`；地图可选择合法下一节点 | 商店直接改写地图底页、出现“离开/完成结算”按钮或无外置入口 |
| 12 | 商店购买边界 | 余额不足/售罄/条件不满足明确禁用；成功购买即时刷新余额与库存 | 负数购买、重复购买、禁用项仍扣款 |
| 13 | 进入 EventNode | 独立问号事件页显示选项；选项选择后锁定并进入结果页 | 选项点击无反馈、结果不展示或可重复触发 |
| 14 | EventNode 离开 | 结果确认或允许的离开动作保留结果并打开地图 overlay；节点消费状态符合规则，点击合法下一节点后才离场 | 返回后事件可无限重复、直接切空白 MapScene 或旧事件输入残留 |
| 15 | 进入 BossNode | 独立 Boss 入口页显示开始斗法；开始前不提前领奖/通关 | Boss 直接伪装为普通战斗或进场即结算 |
| 16 | Boss 胜利/失败 | 胜利显示 Act1 结果并按规则离开；失败显示明确结果和允许的下一步 | 状态卡死、奖励重复或直接重置整局 |
| 17 | 跨节点状态复核 | 战斗损失生命、奖励加牌、灵脉升级/回血、商店购买后，切换节点仍保持 RunState 结果；非战斗节点不显示当前回合灵力/护体/斗劲/临时状态 | 任意场景切换导致生命、永久牌组、灵韵、地图进度重置，或把 BattleState 临时状态带入非战斗节点 |
| 18 | 重复入口与返回键 | 返回/TopBar/战斗 Debug 入口重复操作不会创建重复页面；页面退出后旧输入不再响应 | 多实例、双重结算、旧按钮仍可点击 |

| 地图全展开居中且留白关系稳定 | 当前已具备全宽输入阻断、横向滚轮、左键拖拽、`8px` 阈值、scrollbar clamp 和地图内容水平居中；但全展开 Panel 仍固定为 `x=320, width=1600, y=44, height=1036`，不是本文件规定的居中 `Rect2(64,104,1792,872)`，也未形成可验收的上下大留白。 | 保留左起向右揭示、滚轮/拖拽和 clamp；将全展开终态改为居中容器并按本节留白比例布局。1920×1080 与 1280×720 分别窗口检查当前节点初始视口、全部层可达、上下留白和左右边距，不能以右侧贴边代替居中。 |
| 设置分辨率必须真实生效且可追溯 | 当前已有 `ResolutionSettings` 统一目录、OS 应用结果核验、用户配置保存及启动恢复。剩余 UI 问题是：选择失败时 `SettingsHelper` 只写日志，OptionButton 不会回选上一次成功值，也未向玩家显示失败原因；设置对话框仍标注 `Transient=false`，需窗口确认其输入独占性。 | 失败时恢复到最后成功选项并显示可读错误提示；设置开启时采用独占输入根。对 1920、1280、重开、切场景、重启、headless/不支持尺寸逐项窗口验收，确保下拉值、实际窗口和保存值一致。 |

推荐顺序：

1. 抽出 `NodePageRoot + OverlayHost + TopBar` 的可复用场景/控件，先不改变玩法状态。
2. 用兼容适配读取现有 GameManager，定义 NodeContext/NodeResult 的最小字段和日志。
3. 迁移 BattleNode、胜利/奖励返回和 LingmaiNode，优先验证地图/套牌 overlay 一致性。
4. 新增 ShopNode、EventNode、BossNode 页面骨架，再接入策划确认的库存、事件结果和 Boss 规则。
5. 运行第一大关窗口验收清单，确认跨节点状态不重置后再扩大玩法范围。

### 层级结构（从下到上）


### 各区域详细设计

#### A. 顶部功能栏

| 元素 | 位置 | 内容 | 交互 |
|------|------|------|------|
| 灵韵数量 | 左上 | 铜钱图标 + 数字 | 悬停显示"灵韵：可在行脚宝商处购买卡牌/法宝" |
| 道痕数量 | 左中 | 紫韵图标 + 数字（已固化的道痕数量） | 悬停展开道痕列表 tooltip |
| 场景名称 | 顶部居中 | 如"不周废墟·外围" | 静态文本 |
| **套牌按钮** | 右上第一 | 图标 📋 + "套牌" | 点击弹出套牌浏览面板（全屏半透明遮罩 + 牌组网格）。再次点击或点遮罩区域关闭 |
| **地图按钮** | 右上第二 | 图标 🗺 + "地图" | 点击弹出统一 MapOverlay；BattleNode 战斗中只读；胜利、Lingmai、Shop、Event、Boss 是否可点击合法节点由 `NodeContext` 明示，不由按钮文案或结算状态猜测 |
| **设置按钮** | 右上第三 | 图标 ⚙ | 点击弹出设置面板（音效/画质/退出等）。战斗中的设置面板需包含"放弃本局"选项 |
| **日志按钮** | 右上靠近设置 | 图标/文字 "日志" | Toggle 战斗日志。默认收起，只保留小型提示区；展开时显示最近战斗记录 |

> 旧版“套牌/地图/设置按钮可占位并弹提示”的口径已废弃。当前三类入口必须接入统一 NodePage overlay：套牌/地图可重复 toggle，设置为模态层；均不得重置节点或 RunState。

#### B. 玩家角色区（画面左侧）

| 元素 | 说明 |
|------|------|
| **立绘** | 当前角色半身像，静止时正常姿态；出斗击牌时短暂切换到战斗姿态 |
| **HP/护体条** | 立绘脚下。上=HP（赤红），下=护体（青蓝）。HP变化时有晃动动画 |
| **buff/debuff 图标** | HP条上方一排小图标。每个 24×24px。悬停弹出 tooltip 显示详情（名称+层数+效果描述） |

#### C. 敌人区域（画面右侧）

| 元素 | 说明 |
|------|------|
| **立绘与名称** | 从当前 `ActiveEncounter.EnemyInfo` 读取名称与对应立绘；不得默认显示某个敌人名称。受伤时有受击抖动动画 |
| **HP/护体条** | 最大生命从同一 `EnemyInfo` 读取，当前值从当前 `BattleState` 读取；护体只在当前战斗状态存在时显示 |
| **意图图标与文字** | 从同一 `EnemyInfo + BattleState` 解析当前意图；必须显示“意图名称：效果摘要”，例如 `伏石：获得 8 护体`，图标只做辅助，不得替代文字 |
| **机制/状态图标** | 只显示当前 `EnemyInfo` 定义且已激活的机制；未激活机制隐藏，不得用通用哨兵值显示灵猴闪避等特定机制 |

### 敌人信息与意图显示契约

| 信息 | 唯一来源 | 展示要求 | 缺失处理 |
|------|----------|----------|----------|
| 敌人姓名 | `ActiveEncounter.EnemyInfo.Name` | 立绘附近显眼显示；随遭遇切换 | 显示“敌人信息缺失”错误态并记录，不回退到默认敌名 |
| 最大生命 | `ActiveEncounter.EnemyInfo.MaxHp` | 初始化 HP 条和数值 | 缺失时不伪造 60/默认值，阻止战斗 UI 进入可玩态 |
| 机制 | `EnemyInfo.Mechanic` + `BattleState` 激活状态 | 仅激活后显示名称、层数和简短说明 | 未激活隐藏；定义缺失显示数据错误，不显示错误机制 |
| 当前意图 | `EnemyInfo.GetIntentForTurn(turn, BattleState)` | 名称与效果摘要同一行或相邻两行；例如“伏石：获得 8 护体” | 缺少摘要时显示“意图效果数据缺失”并记录，不降级成泛化“攻击” |

意图视觉验收：

- 玩家无需点击 tooltip 就能读懂当前意图将造成的主要结果；攻击、获得护体、施加易损、特殊机制都必须有可读摘要。
- 意图更新只发生在规则规定的回合/状态转换后，不能因打开地图、套牌或设置 overlay 改变意图。
- 使用至少两种不同 `EnemyInfo` 进入同一战斗 UI，姓名、HP、机制、意图名称和效果摘要必须整体切换；不能只替换立绘而沿用前一个敌人的文字或数值。
- 生产 UI 不在控制器中写死“山野妖猴”“伏石”等内容名；示例文案只允许出现在数据定义或测试 fixture，UI 读取字段渲染。

#### D. 灵力与结束回合行

| 元素 | 位置 | 说明 |
|------|------|------|
| 灵力显示 | 手牌区上方，居左 | 圆点/火焰图标 + "2/3"，当前灵力/灵力上限 |
| 灵力消耗效果 | — | 出牌时对应数量的圆点熄灭，回合开始时全部重新点亮 |
| 结束回合按钮 | 右下角 | 棕色底板 + 金色边框。文字"结束回合"。点击后进入玩家回合结束结算 |

#### E. 手牌区

| 参数 | 值 |
|------|------|
| **位置** | 画面底部中央，略高于底边 |
| **排列方式** | 略微扇形展开，每张卡牌微微旋转（±2°递增），中心卡牌角度为 0° |
| **卡牌尺寸** | MVP 约 180×250px（后续可调） |
| **卡牌内容** | 名称（顶部）、费用（左上角火焰圆点）、类型图标（右上角）、效果文本（中部）、背景文本（底部小字） |
| **费用显示** | 卡牌左上角，圆形火焰图标 + 数字（0/1/2/X） |

#### F. 战斗日志

| 状态 | 视觉与交互 | 验收要求 |
|------|------------|----------|
| 默认收起 | 只显示一行小型最近事件提示，位置在顶部功能栏下方或战场中上部，不进入底部手牌区 | 不遮挡手牌、灵力、结束回合按钮，不拦截手牌 hover/点击/拖拽 |
| 展开 | 点击"日志"按钮后展开为半透明调试面板，显示最近若干条战斗记录；用于 demo 调试和问题复现 | 展开面板高度受限，底边不得低于手牌区上沿；鼠标事件不应穿透到面板内按钮，但不得覆盖手牌操作热区 |
| 收起 | 再次点击"日志"按钮或点击面板关闭按钮后收回默认状态 | 收起后恢复正式体验视野，只保留最近事件提示或完全隐藏日志正文 |

日志边界：

- MVP 正式体验默认不展示大日志，避免破坏战斗沉浸感。
- Demo 阶段必须保留日志开关，方便定位出牌、回合和奖励问题。
- 日志内容可以记录文字，不要求完整战报系统；优先记录出牌、伤害、敌人行动、胜利、奖励领取。
- 日志面板不作为核心操作入口，不得影响卡牌、目标区、结束回合、TopBar 的点击。

### 出牌交互

```
1. 手牌默认在底部做“牌扇”排布：以屏幕下方不可见位置作为虚拟圆心，卡牌沿圆弧居中展开，中心卡最正且最高，左右卡逐步降低并按圆弧切线轻微旋转。
2. hover 手牌 → 当前卡牌从牌扇中原位抬升并摆正放大展示卡面，提高 ZIndex，压在相邻卡上方；不改变其他卡布局，不保留牌扇倾斜角度，不把卡牌飞到战场中央。
3. 点击手牌 → 卡牌选中并隆起：
   ├── 敌方目标牌 → 卡牌仍停留在手牌区的中心悬浮位，只有箭头离开手牌区；上凸弧形箭头从该卡牌顶部/中心指向鼠标或目标
   ├── 默认自身牌 → 不显示攻击箭头；点击后进入与长按一致的持牌跟随状态，移出手牌区后再次点击或释放即按自身目标自动打出
   └── 无目标牌 → 不显示攻击箭头；点击后进入与长按一致的持牌跟随状态，移出手牌区后再次点击或释放即自动打出
4. 长按并拖拽手牌：
   ├── 敌方目标牌拖拽时优先表现为“卡牌保持手牌区悬浮 + 上凸箭头跟随鼠标/目标”；不要让攻击牌本体飞到战场中央
   ├── 默认自身牌 / 无目标牌拖出手牌区后松手 → 自动扣费并打出，不要求点击自身立绘
   ├── 需要选择目标的牌拖到合法目标区松手 → 扣费并打出
   ├── 拖到非法区域松手 → 卡牌回弹到原手牌位置，取消出牌
   └── 拖拽中右键 / Esc → 取消并回弹
5. 再点同一张卡 / 右键 / 点空白区域 → 取消选中。
6. 灵力不足的卡牌 → 灰暗显示（40%不透明），不可 hover 隆起、不可点击选中、不可拖拽打出。
7. 任意卡牌打出、消耗或离开手牌后 → 剩余手牌立即重新计算牌扇布局，重新并拢居中，不留下原卡位空洞。
```

交互优先级：

- 点击选中与长按拖拽都必须可用。短按走点击选中；按住并移动超过拖拽阈值后进入拖拽模式。
- 点击选中默认自身牌/无目标牌后，不应停在原位等待玩家点自身；应进入和长按拖拽一致的持牌跟随状态。玩家将卡牌移出手牌区后，再次点击或释放即自动打出；仍在手牌区内取消或回位。
- 目标策略必须由卡牌数据或等价字段驱动，不按牌名硬编码。MVP 至少区分：敌方目标牌、默认自身牌、无目标牌；后续若加入友方目标、区域目标或多目标，再扩展目标策略枚举/配置。
- 攻击箭头只服务敌方目标牌。箭头起点是当前选中/拖拽的卡牌，不是玩家立绘；曲线方向必须为从卡牌出发后向上抬起再落向目标的上凸曲线，不使用当前下凹弧线。默认自身牌、无目标牌不显示攻击箭头，避免误导玩家。
- 攻击牌本体不得离开手牌栏进入战场中央；攻击牌出手牌区的视觉反馈应主要由箭头承担。默认自身牌和无目标牌可以拖出手牌区，并在松手后自动结算。
- 手牌布局不得保留已打出卡牌的占位。每次手牌数量变化后，都要按新数量重新居中分布成牌扇；例如 3 张变 2 张时，两张剩余卡应围绕手牌区中心重新并拢。
- 拖拽、点击确认和非法释放都必须有即时反馈：目标高亮、箭头、回弹、灰暗、日志或飘字至少一种。
- 当前代码若仍为散乱旋转、hover 放大保留牌扇倾斜角、攻击牌本体飞出手牌栏、箭头从玩家立绘出发/不可见/下凹、默认自身/无目标牌点击后不能进入持牌跟随状态、出牌后剩余手牌留下空位、无拖拽释放或日志遮挡手牌，属于 BUG-20260707-004 / P0-012 待实现项，不按通过验收。

#### 目标策略

| 策略 | 适用卡牌 | 箭头 | 释放/确认 | 实现要求 |
|------|----------|------|-----------|----------|
| 敌方目标牌 | 斗击卡，或任何需要选择敌方目标的牌 | 显示，从当前卡牌指出，以上凸曲线跟随鼠标/目标 | 拖到敌方合法目标松手，或选中后点敌方目标 | 不按“斗击”牌名硬编码，应由目标策略字段判断 |

### 右键取消状态矩阵（BUG-20260713-007）

右键取消只针对当前 BattleNode 且没有更高层模态 overlay 拦截输入时生效。它取消当前卡牌交互，不是撤销已经提交的出牌；结算中或结算完成后不得回滚 BattleState/NodeResult。

| 当前状态 | 右键动作 | 必须清理 | 不得发生 |
|----------|----------|----------|----------|
| 空闲，无 hover 卡牌 | 无副作用 | 无 | 不选卡、不扣费、不改目标、不写日志“取消出牌” |
| 仅 hover 卡牌 | 取消 hover | hover 放大、摆正和临时层级，卡牌回到牌扇目标位 | 不进入选中/持牌，不扣费、不打出 |
| 鼠标按下，尚未超过拖拽阈值 | 取消按下态 | 按下高亮、拖拽计时和候选卡 | 不转换为点击选中，不显示箭头 |
| 点击选中敌方目标牌 | 取消选中 | 卡牌回牌扇目标位、上凸箭头、目标高亮、鼠标跟随 | 不改变当前目标、不扣灵力、不打出 |
| 敌方目标牌拖动/箭头瞄准 | 取消瞄准 | 拖动偏移、箭头、控制点和合法目标标记 | 不把鼠标下目标提交为出牌目标，不触发命中 |
| 点击或长按进入持牌的默认自身/无目标牌 | 取消持牌 | 跟随鼠标状态、手牌区外确认标记和临时层级；卡牌回牌扇目标位 | 不自动打出、不扣费、不要求点自身、不改 RunState |
| 非法区域释放后的回弹动画 | 取消残留交互 | 回弹完成后清除选中、目标和箭头状态 | 不重复扣费、不重复触发回弹或结算 |
| 出牌结算中、胜利/失败结果态 | 忽略右键，保持结果流程 | 由结算状态机清理输入 | 不回滚已提交的卡牌、灵力、伤害、奖励或 NodeResult |

实现与验收约束：

- 右键必须在 BattleNode 的统一输入入口捕获，不能只在卡牌控件自身有鼠标悬停时才可用；高层 Map/Deck/Settings overlay 打开时由 overlay 按统一输入优先级拦截，卡牌不应收到事件。
- 右键事件优先于同一帧的左键目标确认和拖拽释放；重复右键必须幂等，不产生重复取消事件或重复日志。
- 取消只能清理 UI 瞬时态和当前交互引用；不得调用 `PlayCard`，不得写入扣费、伤害、目标、牌组、生命、地图进度或节点访问状态。
- 视觉上应在同一帧或明确的短回弹动画内恢复原牌扇位置；箭头、目标高亮和持牌跟随必须消失，回到手牌后仍按当前手牌数量保持连续牌扇。
- UI/UX 验收至少覆盖：卡牌 hover 后右键、敌方目标牌出现箭头后右键、拖动中右键、默认自身/无目标牌点击持牌后右键、空闲右键，以及打开 overlay 时右键；每项都检查“不耗费、不打出、不改目标”。

### Battle Debug 一键胜利（P1-018）

该入口是战斗验收辅助，不属于正式战斗按钮。它只存在于 Debug 构建的当前 BattleNode 底页，不能恢复旧版全局 F10 跳场景面板，也不能成为跨节点流程入口。

| 项目 | 冻结口径 |
|------|----------|
| 可见范围 | 仅 Debug 构建、仅当前 BattleNode 底层；Map/Lingmai/Shop/Event/Boss 页面和所有 Release 构建不创建、不显示该控件或其快捷键 |
| 视觉隔离 | 使用独立的 Debug 区域/复用 Debug 控件和集中主题，与“结束回合”“确认目标”“继续”等正式按钮分区、颜色和图标明显区分；不覆盖手牌、敌人意图或 TopBar |
| 推荐文案 | `Debug：直接胜利（真实流程）`；文案和可见性由 Debug 场景/配置控制，正式资源不保留隐藏的 Release 文案 |
| 可用条件 | 当前 BattleState 有效、未处于出牌/敌人行动/胜负结算中、没有模态 overlay；按钮不可用时要有明确状态，不静默成功 |
| 点击结果 | 复用真实“战斗胜利 → EncounterResult/NodeResult → 胜利弹窗 → 灵韵/卡牌奖励 → 外置继续打开地图”链路；奖励领取、跳过、回地图的交互与正式流程一致 |
| 禁止行为 | 不直接设置地图层/当前位置、生命、永久套牌、灵韵、Seed、VisitedNodeIds，不伪造奖励，不跳过 NodeResult，不直接切换 MapScene，不重建角色或牌组 |
| 重复点击 | 进入结算或结果态后立即禁用；重复点击不得重复奖励、重复写节点结果或创建多个胜利/奖励层；过程应有 Debug 日志或可见反馈 |

Debug 一键胜利验收：

1. Debug 窗口进入 BattleNode，能看到独立按钮；进入 Map、Lingmai、Shop、Event、Boss 页面均不可见、不可通过旧快捷键触发。
2. 点击按钮后，敌人意图/战斗输入进入正式结算锁定，按真实胜利链路依次出现胜利结果、奖励入口和回地图；不能瞬移到地图或绕过奖励页。
3. 领取灵韵、选择/跳过卡牌奖励、继续回地图后，RunState 只出现真实流程允许的变化；不能凭 Debug 按钮额外恢复生命、改牌组或改地图进度。
4. Release 构建检查控件树、输入映射和可见文本，确认没有 Debug 按钮、快捷键、全局面板或调试提示残留。

开发实现边界：正式 UI、Debug 控件和状态提示优先使用 `.tscn`、复用控件与集中主题；不要在 `BattleController` 中继续复制动态样式、固定坐标或内容文案。Debug 命令应由 BattleNode/战斗协调层发出并返回正式结果，UI 只负责显示状态和触发命令。

### 胜利奖励总面板的模态焦点（UI-FOCUS-SETTINGS-20260717）

胜利结果显示后，BattleNode 进入 `VictoryModal` 焦点域。该域从遮罩出现开始，到玩家在胜利地图中点击合法下一节点并完成离场前持续存在；CardReward 和胜利页地图只是在该域内切换上层内容。

| 相对内容层级 | 输入与视觉 | 关闭/回退 |
|------|------------|-----------|
| 胜利遮罩 `VictoryScrim` | 只覆盖 TopBar 下缘以下的 BattleNode 内容区；墨黑/深褐 alpha `0.72`，允许范围 `0.68~0.78`；根节点 `MouseFilter=Stop` | 仅离开 BattleNode 时移除；不可点穿到下层内容区，不覆盖或阻断 TopBar |
| 胜利总面板 `VictoryPanel` | 面板背景 alpha 不低于 `0.96`；只接收灵韵领取、奖励行等胜利操作，不放置地图/继续入口 | 始终保留在 CardReward 与地图下方；不因关闭上层 overlay 消失 |
| CardReward | 胜利局部模态，位于 VictoryPanel 之上；地图未激活时独占内容区输入并覆盖本地继续；展示固定 `RewardPlan` 和当前领取进度 | 选满、跳过或关闭后只移除自身，焦点回胜利总面板；地图激活时保留状态但不接收输入 |
| 胜利页地图 `VictoryMapOverlay` | 由主面板外 `NodeContinue` 或 TopBar 地图入口打开；激活时独占内容区输入并覆盖 VictoryPanel、CardReward 与本地 Continue | 地图关闭后恢复打开前的胜利/奖励焦点与进度；只有地图内合法下一节点点击成功后才触发离场 |

模态验收硬规则：

- 任何胜利 modal 动画帧都不得发生内容区点击穿透。面板出现、CardReward 打开/关闭、地图展开/收卷期间，手牌 hover/点击/拖拽、结束回合、日志、敌人目标区、F9 和所有 Debug 测试入口均不得产生可见或状态上的交互结果；TopBar 的地图、套牌、设置入口必须始终可操作。
- 地图展开期间，CardReward 与 Continue 必须被地图完整遮住且不接收输入；不得以提高 Continue 或 CardReward 的固定 ZIndex 使其漂浮在地图上方。地图关闭后，CardReward 的 `RewardPlan`、候选顺序与已选进度原样恢复。
- 背景必须明显降暗，但仍可辨认这是原战斗场景；胜利标题、奖励行、按钮和 CardReward 正文必须保持足够对比，不能因遮罩过深而难读。
- 下层 Debug 控件即使 ZIndex 较高或采用 Canvas 绘制，也必须处于 `VictoryScrim` 以下或受同一 modal 输入门禁控制；视觉遮住总面板或仍能响应按键均为失败。

#### 胜利奖励行主轴居中（UI-REWARD-NODE-COHERENCE-20260720）

胜利总面板的主轴是 `VictoryPanel` 自身水平中心，而不是左侧奖励列表、文字控件或局部容器的中心。以 1920×1080 下 `VictoryPanel=960×760` 为例，主轴为其局部 `x=480px`；奖励内容列、每一条可点奖励行的命中矩形、图标/文字/数值组合都必须围绕该轴对称布局。

| 项目 | 1920×1080 推荐值 | 允许范围/约束 | 失败判定 |
|------|------------------|---------------|----------|
| 奖励内容列 `RewardColumn` | `width=640px`，`x=(960-640)/2=160px` | 宽度 `560~720px`；始终由面板宽度居中计算，不能写死左偏 x 坐标 | 字形看似居中但整列偏左，或面板缩放后列中心偏离主轴 |
| 可点奖励行 `RewardRow` | 与内容列同宽、同中心；行内图标 + 奖励文案 + 数值为一个居中组合 | 命中矩形不得比视觉行向左或向右偏移；候选完成后余行重新流式居中 | 点击热区和视觉内容不重合，或只有文本居中、整行仍左偏 |
| 动态增减 | 灵韵领取后该行移除，余行垂直补位且持续以同一主轴居中 | 列宽不因单条短文本收缩；滚动条仅在内容溢出时出现 | 领取后留下横向空位、行组跳到左侧、长短文案改变列中心 |

验收至少覆盖：仅一条奖励、灵韵与卡牌奖励两行、灵韵领取后只剩卡牌奖励、较长奖励文案，以及 CardReward 关闭回总面板。每一状态均以面板中心辅助线检查行的视觉中心和点击矩形中心；仅把 Label 的文本对齐设为居中不构成通过。

### 胜利页外置继续锚点

胜利页不保留面板内“继续”按钮。`NodeContinue` 是独立于胜利主面板、奖励列表和 CardReward 的固定操作位，使用与 LingmaiNode、ShopNode、EventNode 完全一致的视口右下锚点：1920×1080 下 `right=64px`、`bottom=72px`、`width=200px`、`height=64px`；1280×720 等比缩放后不小于约 `133×43px`。

- 固定显示 `继续`；tooltip 为“打开地图卷轴”。地图是动作与 tooltip，不是按钮文字；不得显示“地图”“返回地图”“放弃灵脉”“离开”或“完成商店结算”。
- 奖励列表可使用胜利面板的完整中部区域：建议 `x=96px`、`y=130px`、`width=768px`、最大高度 `500px`；超出时在列表内部滚动。主面板内不再预留继续按钮安全区。
- 奖励结算错误面板也不显示内置继续按钮；保留同一个 NodeContinue。入口点击只发出 `ToggleOverlay(VictoryMapOverlay)`，不领取奖励、不提交额外结果、不清理页面。
- NodeContinue 属于节点页本地层：高于 `VictoryPanel`，低于 `VictoryMapOverlay` 和 `CardReward`。地图或 CardReward 打开时必须完整覆盖其视觉与命中区，禁止点击穿透；关闭后才恢复该入口。仅 Transition/Error、地图动画或无有效地图上下文可以灰置。

#### 胜利/奖励输入归属图

```text
屏幕顶端：TopBar（唯一常驻全局可交互层）
  ├─ 地图 / 套牌 / 设置：通过 overlay 协调器打开；关闭后恢复此前胜利或 CardReward 焦点
  └─ 不被 VictoryScrim、MapOverlay、CardReward 覆盖或禁用

TopBar 下缘以下的内容区（地图激活时，从高到低）：
  VictoryMapOverlay（独占输入；覆盖 CardReward、NodeContinue 与 VictoryPanel）
  CardRewardOverlay（地图关闭时才独占输入；地图激活时仅保留状态）
  NodeContinue（节点页本地“继续”；仅 toggle 地图）
  VictoryPanel / VictoryScrim / BattleNode 下层（不得穿透）
```

验收路径：胜利页打开 CardReward → 点击右下原 Continue 区域不得响应 → 从 TopBar 打开地图 → 地图完整遮住 CardReward、Continue 与胜利面板，内容区只有地图可操作 → 收卷地图 → 恢复同一 CardReward、候选与领取进度 → 关闭/跳过 CardReward → Continue 恢复 → 点击 Continue 打开地图 → 地图展开时同一区域仍不得响应 → 收卷地图后恢复胜利页，不出现空白页。TopBar 的三个入口在每一步均可操作，但其关闭必须精确恢复此前局部状态，而不是销毁 CardReward 或禁用奖励行。

### 1920×1080 / 1280×720 分辨率验收

| 检查点 | 1920×1080 | 1280×720 | 失败判定 |
|--------|-----------|-----------|----------|
| 胜利 modal | `960×760` 总面板居中；遮罩覆盖 TopBar 下缘以下内容区；外置 `继续` 位于视口右下 | 等比缩放，标题、主轴居中的奖励行和外置继续完整可读；无裁切或重叠 | 下层内容可点、面板超出窗口、奖励行整体左偏、入口被遮罩挡住或按钮/文本重叠 |

### 交互流程

```
1. 从当前胜利计划读取一个 `RewardPlan`，按 `Candidates` 的既定顺序展示；UI 不重抽、不洗牌、不按牌名重建候选。
2. 点击候选：向当前奖励槽提交候选索引和候选 ID；显示即时选中/已领取状态。
   ├── 已领取数量 < `ChoiceCount` → overlay 保持打开，未选候选继续可选，已选候选禁用
   └── 已领取数量 = `ChoiceCount` → 该奖励行完成，关闭 overlay，回到下方胜利弹窗
3. 点击“跳过”或关闭：只关闭当前 CardReward overlay，不消费奖励槽、不删除胜利页奖励行、不提交 NodeResult、不修改永久牌组；可再次点击同一奖励行重新打开。
4. 重复打开必须复用同一奖励槽计划和已领取进度；候选 ID、顺序、`ChoiceCount` 不变化。额外奖励来源也按各自 `RewardPlan` 独立显示，不合并成无来源的通用奖励。
```

### 选择规则

- MVP 奖赏卡池 = 巫祝正式最小奖赏卡池（详见 `03-玩法系统/01-卡牌系统.md` §10）。当前代码若仍使用拳袭/格挡/烈拳/燃血随机 3 选 1，属于待开发接入项。
- 当前 MVP 奖励计划由胜利结算层预先生成；CardReward UI 只消费已校验的 `RewardPlan`，不得知道卡池、遭遇层级或奖励来源规则。
- 领取位置由开发部按现有奖励事务契约执行；UI 不自行决定加入抽牌堆/弃牌堆，也不在关闭 overlay 时写入永久牌组。
- 选择是否可撤销由 `ChoiceCount` 和奖励事务规则决定；已提交的候选不得通过关闭 overlay 回滚，未完成的奖励槽可以重新打开继续选择。

### CardReward 计划身份与状态契约（BUG-20260716-003）

当前工程的 `RewardPlan` 没有单独的 `RewardPlanId` 字段。UI 应把以下不可变字段作为计划身份，不能只用卡牌 ID 或显示文案判断“是不是同一份奖励”：

| 身份字段 | 用途 |
|----------|------|
| `RewardSlotId` | 当前胜利页奖励行的稳定槽位身份；重复打开必须定位到同一行 |
| `NodeId` + `EncounterId` | 绑定产生该奖励的节点和遭遇，防止跨战斗串用 |
| `ProfileId` + `SourceId` | 区分奖励档案和额外来源；来源不同必须保留独立奖励槽 |
| `CardPoolId`、`CandidateCount`、`ChoiceCount`、`MergeRule` | 校验展示计划与来源规则一致，不由 UI 自行改变 |
| `Candidates[i].Id` | 当前候选的稳定内容身份；只用于显示/提交候选，不替代 `RewardSlotId` |

`RewardId` 是一次实际领取写入的奖励身份，不能当作 `RewardPlan` 身份，也不能在打开/关闭 overlay 时生成新的 `RewardId`。UI 每次打开只读取当前胜利计划和已领取候选索引；缺少真实计划或槽位不属于当前胜利计划时，显示错误态并阻止操作。

### CardReward 状态与按钮口径

| 状态 | 奖励行 | CardReward overlay | 允许操作 | 禁止副作用 |
|------|----------|--------------------|----------|------------|
| 未打开 | 保留且可点（未完成时） | 不存在 | 点击奖励行打开同一计划 | 不重抽候选、不改变牌组 |
| 打开/未选择 | 保留 | 显示固定候选顺序 | 选择候选、跳过/关闭 | 不因打开生成奖励、不提交节点结果 |
| 部分已选（`ChoiceCount > 1`） | 保留且可点 | 显示已选进度，已选候选禁用 | 继续选择、跳过/关闭 | 关闭不清空进度、不移除奖励行 |
| 达到 `ChoiceCount` | 移除/置为已完成且不可再点 | 自动关闭或明确关闭 | 回到胜利页，继续打开地图 overlay | 不重复领取、不重复发卡 |
| 缺少计划/身份校验失败 | 保留但禁用 | 显示错误与返回胜利页入口 | 关闭错误态 | 不伪造候选、不默认成功、不删除奖励行 |

UI 验收必须覆盖：连续多次打开/关闭同一奖励槽候选 ID 和顺序不变；3 选 2 领取一张后关闭重开，第一张仍已选且只允许再选一张；未完成时跳过不会改变奖励行、永久牌组或 NodeResult；完成后再次点击原行不可重复领取。

## P0-012 二次返工用户复测口径

用户复测 P0-010 / P0-012 时，至少覆盖以下操作：

1. 进入战斗后观察底部手牌：仍保持牌扇，中心最高最正，左右逐步降低并轻旋。
2. hover 左、中、右不同卡牌：当前卡必须原位抬升并摆正放大，不保留原倾斜角度。
3. 点击或拖动敌方目标牌：箭头必须从卡牌指出、清晰可见并跟随鼠标/目标；攻击牌本体不飞出手牌栏。
4. 拖动默认自身牌或无目标牌离开手牌区并松手：不显示攻击箭头，不要求点击自身立绘，直接扣费并结算。
5. 将任一卡拖到非法区域松手：卡牌回弹取消，不扣费、不造成效果。

## P0-012 三次返工用户复测口径

本轮基于用户二次实机复测截图补齐，只覆盖三项新失败点；hover 摆正、攻击牌不飞出、日志表现沿用已通过结论。

1. 敌方目标牌箭头：点击/拖动斗击类敌方目标牌后，箭头必须从卡牌顶部/中心附近出发，先向战场上方抬起，再落向目标，形成上凸曲线；不得是从卡牌下方贴地滑出的下凹弧线。
2. 默认自身/无目标牌点击持牌：点击格挡等默认自身牌后，卡牌应进入与长按拖拽一致的持牌跟随状态；将卡牌移出手牌区后再次点击或释放，立即自动打出。
3. 默认自身/无目标牌取消：点击选中后若仍在手牌区内取消、右键或 Esc，卡牌回到牌扇原位，不扣费不结算。
4. 出牌后重排：任意卡牌打出后，剩余手牌立即按新数量重新居中并拢成扇形；例如 3 张变 2 张时，2 张应围绕手牌区中心重排，不留下中间或原位置空位。

## P1-007 手牌布局参数化与 Debug 可视化

本节定义 P1-007A 的 UI/UX 口径。当前阶段不做完整 Godot EditorPlugin，先采用“配置资源 + Debug 可视化点位 + 独立布局计算器”的轻量方案。参数默认值以 1920×1080、卡牌约 180×250px 为基准，后续可由开发部通过 `HandLayoutProfile` 或等价配置资源接入。

### 参数表

| 参数名 | 用途 | 1920×1080 推荐默认值 | 建议范围 | 影响说明 |
|--------|------|----------------------|----------|----------|
| `CardSize` | 单张卡牌目标尺寸 | `180×250` | 宽 `150~220`，高 `210~310` | 决定重叠程度、可读性和 hover 放大后占屏面积 |
| `HandAreaRect` | 手牌可布局边界 | `Rect2(300, 760, 1320, 280)` | X `240~420`，Y `720~820`，W `1080~1500`，H `220~340` | 所有默认/hover/selected 状态不得越过核心操作区；右侧需避开结束回合按钮 |
| `HandAnchor` | 牌扇中心卡目标点 | `(960, 910)` | X `840~1080`，Y `860~970` | 1 张手牌、奇数手牌中心卡和重排后的视觉中心 |
| `VirtualFanCenter` | 屏幕下方不可见虚拟圆心 | `(960, 1680)` | X `840~1080`，Y `1280~2400` | 决定牌扇弧度。Y 越低弧线越平，Y 越近弧线越明显 |
| `CountAngleCurve` | 不同手牌数的总扇形角度 | `1:0° / 2:9.5° / 3:16° / 5:28° / 7:40° / 10:54°` | 1 张必须 `0°`；10 张建议不超过 `65°` | 避免低张数拉太开，也避免高张数挤成一团 |
| `MaxRotation` | 单卡最大旋转角 | `16°` | `8°~24°` | 控制左右边缘卡倾斜程度。hover/selected 必须回到 `0°` |
| `EdgeDropY` | 左右边缘卡相对中心卡下降量 | `74px` | `35~120px` | 决定中心卡“最高”、左右逐步降低的牌扇感 |
| `MinCardGap` | 高张数时卡牌中心最小间距 | `78px` | `55~100px` | 防止 10 张手牌完全叠死；仍允许适度覆盖相邻卡 |
| `MaxCardGap` | 低张数时卡牌中心最大间距 | `138px` | `105~170px` | 防止 2~3 张手牌分散到两侧，必须仍围绕中心并拢 |
| `DefaultZIndexMode` | 默认静止态遮挡顺序 | `LeftToRightAscending` | 固定为从左到右递增 | 几何上的“中心卡最高最正”不代表层级最高；默认静止态最左卡在最底层，右侧卡依次轻微盖住左侧卡 |
| `InteractionZIndexBoost` | hover/selected/held 临时层级提升 | `+100` | `+20~+300` | 当前操作卡必须临时压到所有静止手牌之上，保证可读、可点 |
| `ReflowDuration` | 出牌/抽牌后重排动画时间 | `0.12s` | `0~0.25s` | 数量变化后立即重排，不留下空位；动画可短但不能拖慢出牌节奏 |
| `HoverScale` | hover 放大倍率 | `1.18` | `1.08~1.30` | 放大后应能读卡面，不遮挡关键战场信息 |
| `HoverLiftY` | hover 抬升距离 | `-105px` | `-60~-160px` | 从牌扇中原位抬升并摆正，不移动到战场中央 |
| `SelectedScale` | 点击/持牌状态缩放 | `1.20` | `1.10~1.35` | 与 hover 接近，保证选中反馈明确 |
| `SelectedLiftY` | 点击/持牌状态抬升距离 | `-120px` | `-80~-180px` | 用于默认自身/无目标牌点击后的持牌跟随起点 |
| `HeldFollowOffset` | 持牌时卡牌相对鼠标偏移 | `(0, -90)` | X `-40~40`，Y `-60~-140` | 避免鼠标遮住卡面；默认自身/无目标牌点击与长按共用 |
| `HandExitThresholdY` | 判定离开手牌区的高度 | `740` | `700~800` | 默认自身/无目标牌移出该边界后点击/释放才自动打出 |
| `ArrowStartOffset` | 敌方目标牌箭头起点偏移 | `(0, -110)` | X `-40~40`，Y `-70~-150` | 箭头从当前卡牌顶部/中心附近出发，不从玩家立绘或屏幕固定点出发 |
| `ArrowArcHeight` | 上凸箭头弧线高度 | `260px` | `160~420px` | 控制箭头先向上抬再落向目标；不得形成下凹弧线 |
| `ArrowTargetPadding` | 箭头落点与目标边缘距离 | `36px` | `16~60px` | 避免箭头头部压住敌人血条或意图文本 |
| `DebugOverlayEnabled` | Debug 点位可视化开关 | `false` | `true/false` | 默认关闭；只用于调参和验收，不进入正式体验 |

### 手牌数量验收

| 手牌数量 | 默认布局应看到什么 | Debug 重点 | 失败判定 |
|----------|--------------------|------------|----------|
| 1 张 | 卡牌位于 `HandAnchor` 附近，角度 `0°`，不偏左/右 | 目标点与中心线重合 | 单卡偏离中心或带明显旋转 |
| 2 张 | 两张围绕中心线左右对称，轻微外旋，总跨度约 `9.5°`，中间不留大洞；右侧卡轻微盖住左侧卡 | 两个目标点距离中心相近，间距约 `100~130px`；ZIndex 左低右高 | 仍沿用 5 张以上跨度，导致中间空挡明显；左侧卡压住右侧卡 |
| 3 张 | 中心卡几何位置最高最正，左右卡轻微下降并外旋；遮挡层级仍按左低右高排列 | 三个目标点连续，无旧卡位空洞；ZIndex `0 < 1 < 2` | 打出 1 张后剩余 2 张没有重新居中；中心卡默认压住左右卡 |
| 5 张 | 标准 MVP 牌扇：中心几何位置最高，左右逐步下降，边缘卡仍可识别名称/费用；右侧卡依次轻盖左侧卡 | 目标点沿弧线连续，卡框不遮挡结束回合按钮；ZIndex 从左到右递增 | 牌扇断裂、左右高度无规律、边缘卡压到按钮；中心卡或左侧卡默认置顶 |
| 7 张 | 适度压缩重叠，仍保持中心卡几何位置最高、左右对称；默认遮挡顺序左低右高；hover 任一卡可读完整卡面 | `MinCardGap` 生效，hover 目标点不超过手牌区上方安全线；hover ZIndex 临时最高 | 卡牌完全叠死或 hover 放大后遮住敌人/玩家核心信息；hover 卡被静止卡压住 |
| 10 张 | 高张数压缩，允许明显重叠，但费用、名称区域至少能判断卡牌；默认从左到右逐张覆盖；hover/selected 必须可读 | 目标点仍连续；所有卡框在 `HandAreaRect` 内或只轻微越界；ZIndex 右侧高于左侧 | 左右边缘出屏、目标点跳变、hover 选不到被压住的卡；遮挡顺序反向或中心卡默认最高 |

### 不得回退的既有交互

- hover 必须摆正放大，不保留牌扇倾斜角度。
- 默认静止态遮挡顺序必须从左到右递增：最左卡在最底层，每张右侧卡轻微盖住左侧卡；“中心卡最高最正”只描述几何位置和旋转，不代表 ZIndex 最高。
- hover / selected / held 状态必须临时提高层级，当前操作卡压过所有静止态手牌，保证卡面可读和鼠标可命中。
- 攻击牌本体不得飞出手牌栏，出手牌区的主要反馈是上凸箭头。
- 敌方目标牌箭头必须从卡牌指出并呈上凸曲线，不从玩家立绘或固定屏幕点出发。
- 默认自身/无目标牌点击后进入持牌跟随状态，在手牌区外点击/释放自动打出。
- 任意卡牌打出后，剩余手牌立即按当前数量重新居中成扇形，不留下空位。

### 风险与边界

- 本轮不做完整 Godot EditorPlugin，不做可拖拽编辑器窗口，不做运行时保存参数到用户配置。
- 本轮不重做卡牌美术、卡面信息层级或正式卡框资源。
- 本轮不调整玩法数值、卡牌效果、敌人逻辑、奖励逻辑或目标策略语义。
- Debug overlay 默认关闭，正式体验不得显示调参点位。
- 若开发部继续在 `BattleController.cs` 内保留部分动态 UI 构建，只能作为 P1 轻量修复；应把布局计算、参数读取和 Debug 绘制拆出独立方法/类，避免继续扩大大型动态 UI 系统。
