# 10-全局音量与设置页规格

> 版本: 0.2.0 | 状态: 阶段 A UI/UX 规格修订，待开发部实现 | 最后更新: 2026-07-29
>
> 适用任务: `AUDIO-SETTINGS-001`。本文是全局音量与共享设置页的唯一 UI/UX 实现口径。本轮只定义界面、交互、节点职责和验收，不修改 Godot 工程、代码、Theme、音频或美术资源。

---

## 1. 固定结论与职责边界

- 设置页是所有节点页和标题页共用的一个 `SettingsOverlay`，不切场景、不重置角色、生命、牌组或地图进度。
- 信息架构采用**单页分组**，不采用页签：同一视口依次显示“声音”和“显示”两组。声音调整需要反复试听，分组单页能让玩家同时看到三个音量层级和分辨率状态，也避免在 1280×720 下额外隐藏内容或制造页签焦点陷阱。
- 音频事实和持久化由已批准的 `AudioSettingsService` 负责；UI 只读取快照、提交音量/静音意图并显示结果，不直接决定总线、分贝换算或配置文件写入。
- `Master` 控制总音量，`Music` 控制音乐，`SFX` 控制音效；标题 BGM 不新增单独 UI 行，使用“音乐”行，并同时受“总音量”和“音乐”控制。
- 默认值固定为：总音量 `80%`、音乐 `65%`、音效 `80%`。三项都支持 `0%~100%`，`0%` 必须表现为可靠静音。
- 设置变更即时生效；关闭设置不回滚已经成功应用的音量或分辨率。持久化和失败恢复由服务/显示设置职责完成，UI 必须展示真实结果，不显示假成功。

## 2. 页面结构与层级

### 2.1 1920×1080 基准布局

设置中央内容面板以设计分辨率为逻辑基准，居中显示，视觉上位于 TopBar 下方；外层 `OverlayScrim` 覆盖整个 viewport（包含 TopBar）并负责独占输入。TopBar 因此保持可见但不可交互。推荐外框为 `Rect2(580, 210, 760, 660)`，外框中心为 `(960, 540)`；内容超出时由内容区处理，不让面板贴边或裁切。

| 区域 | 推荐逻辑尺寸/位置 | 说明 |
|------|------------------|------|
| 设置面板 | `760×660`，水平/垂直居中 | 深棕纸墨底，背景不透明度建议不低于 `0.96`；外框不超过 `8px` 圆角，避免卡片套卡片。 |
| 标题栏 | 面板顶部 `76px` | 左侧标题“设置”，标题字号 `30px`；不显示“返回标题界面”。 |
| 关闭按钮 | 标题栏右上，局部 `44×44px`，距上/右 `16px` | 仅使用关闭图标或已有 Theme 图标；无底部关闭按钮。可见标签/辅助名为“关闭设置”。 |
| 内容内边距 | 左右 `28px`，标题栏下方 `28px`，底部 `28px` | 内容列宽约 `704px`；所有行共用同一左轴与右轴。 |
| 声音分组 | 内容区上半部 | 组标题、三条音量行、组内间距见第 3 节。 |
| 显示分组 | 声音分组下方，以 `HSeparator` 分隔 | 保留现有分辨率选择和状态提示，不新增画质选项。 |
| 游戏内返回主菜单 | 面板底部 footer 右侧，`220×52px` 左右 | 仅游戏内显示；点击直接提交放弃本局意图，旁边保留简短“当前对局进度不会保存”说明；不新增“应用/关闭”按钮。 |

推荐纵向排布：标题栏 `76px`；内容左右内边距 `28px`；声音标题 `32px`；音量行各 `56px`、行间距 `12px`；分组间距 `18px`；显示标题 `32px`；分辨率行 `56px`；状态提示预留 `48px`；footer 分隔和退出行共约 `92px`。各项由 Container 排布，数值用于基准而不是脚本散落坐标。

### 2.2 输入层级与共享实例

```text
NodePage / TitlePage
  ├── TopBar（常驻视觉；设置打开时被全屏遮罩阻断输入）
  ├── PageOverlay（地图或套牌；页面内按协调规则二选一）
       └── SettingsOverlay（全屏 scrim + 中央内容面板，独占视口输入）
       ├── SettingsPanel
       │    ├── TitleBar + CloseButton
       │    ├── SoundGroup
       │    ├── DisplayGroup
       │    └── Footer + ReturnToMainMenuButton（游戏内）
       └── OverlayScrim（覆盖整个视口；只放行设置面板、右上角关闭和 Esc）
```

- 打开设置时，遮罩覆盖整个视口并阻断当前页面、其它 overlay 和 TopBar；TopBar 仍可见但不可交互。只有设置面板、标题栏右上角关闭和 `Esc` 响应输入。
- 地图与套牌仍由页面内 overlay 协调规则管理，不能彼此叠开；**设置不属于这一互斥组**，可以压在地图、套牌、胜利面板或 CardReward 之上。打开设置不得关闭、销毁或重建下层 overlay，关闭后恢复原实例和状态。
- 设置打开时点击其它 TopBar 入口没有响应；不得在全局输入入口增加“设置是否打开”的特判来绕过 GUI 遮罩，也不得创建重复 overlay。
- 关闭是 UI 行为：只有标题栏右上角关闭和 `Esc` 调用设置关闭命令；不得触发场景切换、奖励结算、节点离场或状态重置。
- `Esc` 只关闭当前设置实例；设置未打开时不执行设置关闭副作用。关闭过程中不得穿透触发下层按钮；关闭后下一次新的 TopBar 输入才按原入口职责处理。

### 2.3 语义平面与输入归属

以下是给现有 `OverlayCoordinator` 的语义契约，不是要求新增通用框架，也不是允许控制器自行分配数字 `ZIndex`。实现可以使用集中命名的容器/层级边界，但所有覆盖关系必须由这些平面及其输入归属表达。

| 语义平面（由低到高） | 负责内容 | 激活时输入归属 | 关闭/恢复 |
|----------------------|----------|----------------|----------|
| `PageContent` | 当前 Map/Battle/Lingmai/Shop/Event/Boss 页面及 `NodeContinue` | 当前节点页面操作 | 页面离场时销毁；不保存旧节点的 UI 瞬时态 |
| `VictoryResult` | 胜利遮罩、胜利面板和奖励行 | 覆盖内容区，允许胜利结果/奖励行操作 | CardReward/地图/设置关闭后仍保留，合法节点离场时结束 |
| `CardReward` | 当前胜利 `RewardPlan` 的卡牌选择 overlay | 地图/设置未激活时独占内容区；覆盖 VictoryResult 和 NodeContinue | 跳过/关闭只关自身，候选顺序与已领取进度保留 |
| `MapOverlay` | 当前页面或胜利页地图卷轴 | 覆盖 PageContent、VictoryResult、CardReward 和 NodeContinue；战斗中按 `NodeContext` 只读 | 收卷只恢复打开前焦点；点击合法节点才离场 |
| `GlobalSettings` | 共享设置面板及其全屏遮罩 | 覆盖上述所有内容平面和 TopBar 的输入，是整个视口的最上层模态；仅设置面板、右上角关闭和 Esc 有输入 | 只关闭设置；下层平面和实例原样露出 |
| `TransitionOrFatalError` | 场景转场、致命错误和明确阻断提示 | 按错误/转场契约阻断输入；不由设置页改变 | 完成或安全返回后由流程负责人移除 |

`TopBar` 是固定装配的全局视觉层，但 `GlobalSettings` 激活时其整条输入区域被全屏 `OverlayScrim` 阻断；TopBar 只保持可见，不保持可交互。地图、套牌或胜利/CardReward 单独存在时仍沿用原 TopBar 入口规则。任何控制器不得用散落魔法 `ZIndex`、`CanvasLayer.Layer`、`Reparent` 或 `MoveChild` 把页面临时抬到另一平面。

### 2.4 设置压栈与精确恢复

`SettingsOverlay` 是临时压栈层，不是替换当前页面的导航。现有协调器按以下顺序处理：

1. **打开**：记录当前页面和内容平面快照，然后把同一设置实例放入 `GlobalSettings` 容器。快照至少包含当前页面/节点上下文、下层 overlay 实例身份、地图横向滚动位置与只读/可交互状态、Victory/CardReward 的候选/领取进度、当前焦点和页面输入状态。
2. **打开时保留下层**：地图打开时不收卷、不销毁、不重建地图；胜利面板或 CardReward 存在时不清理奖励计划、候选行或已领取进度。设置遮罩只阻断它们的输入和视觉，不改变其事实状态。
3. **当前左键手势**：若下层正在进行未提交的卡牌拖拽/目标瞄准，打开设置时取消并消费该瞬时手势；不回滚已经提交的结算。地图滚动位置、奖励计划和页面状态不属于该瞬时手势，必须保留。
4. **关闭**：右上角关闭或 `Esc` 只移除当前 `GlobalSettings` 实例，先恢复快照中的焦点和输入归属，再让原地图/Victory/CardReward 实例继续接收事件；不得通过重新实例化页面来“恢复”。再次点击设置入口不是关闭路径，因为设置全屏遮罩会阻断该点击。
5. **其它 TopBar 入口**：设置打开时地图、套牌和设置入口均不可交互，不排队或延迟执行被遮罩的点击。设置关闭后，玩家必须发起新的 TopBar Press 才能执行地图/套牌职责；若下层已有地图，地图按钮按原 toggle 关闭它，不影响其它 RunState。
6. **初始化/关闭失败**：设置实例初始化失败时，不得销毁快照中的下层实例；显示可追踪错误并保持原页面。任何关闭路径都不得调用 `NodeResult`、领取奖励、切场景或清空 overlay。

验收重点是“同一实例和状态恢复”，不是关闭后重新画出一张看起来相同的地图或奖励页。

## 3. 声音分组

### 3.1 三条音量行

声音组依次显示“总音量”“音乐”“音效”，顺序固定，不按当前值排序。每行由统一的可复用 `VolumeRow` 构成：标签、滑块、百分比读数、静音入口。

| 控件 | 1920×1080 推荐尺寸 | 行为与显示 |
|------|-------------------|------------|
| 标签 | 宽 `156px`，左对齐 | 文案固定为“总音量”“音乐”“音效”；不显示技术总线名 `Master/Music/SFX`。 |
| `HSlider` | 宽 `360px`，高不小于 `32px` | 最小 `0`、最大 `100`、步长 `1`；拖动和点击轨道即时提交百分比。填充段用古金，未填充段用深墨灰。 |
| 百分比 | 宽 `64px`，右对齐 | 显示整数 `0%`~`100%`，与滑块同一行；更新不能造成布局跳动。 |
| 静音入口 | `64×44px`，右侧 | 文字“静音”或已有 Theme 的静音图标；必须有可访问名称“静音/取消静音”和 tooltip。不得新增音频美术资源。 |

单行控件之间建议间距：标签到滑块 `16px`，滑块到百分比 `16px`，百分比到静音入口 `12px`。行高固定为 `56px`，三行不因提示文字或语言长度改变高度。

### 3.2 滑块、静音和百分比语义

- 滑块值是 0 到 100 的线性 UI 百分比；UI 不显示 dB，不把 `-∞ dB` 当作可编辑值。`0%` 是合法值，输出必须静音。
- 静音按钮是独立的显式静音状态：开启时保留当前百分比读数但暂时静音该层；关闭时恢复该百分比。若百分比本身为 `0%`，关闭静音仍保持 `0%`，不擅自恢复默认值。
- 静音状态与上级总线串联：总音量静音/为 `0%` 时，音乐与音效行可以显示自身值，但实际输出仍为静音；降低/静音音乐不得改变音效；降低/静音总音量同时影响音乐与音效。
- 在显式静音期间拖动滑块仍更新百分比；当玩家把滑块拖到大于 `0%` 的值时，UI 退出该行显式静音并即时试听新值，避免“滑块已调高但仍完全无声”的误解。若开发服务采用不同内部顺序，外在结果必须一致。
- 首次运行显示 `80% / 65% / 80%`；加载失败、缺少必要音频层或服务初始化失败时，不伪造默认成功状态。声音组显示“声音设置不可用：<可读原因>”，三行进入禁用态，并保留可关闭设置页的能力。

### 3.3 鼠标、键盘和状态

| 状态/输入 | 视觉与行为 |
|-----------|------------|
| 默认 | 标签、百分比和滑块轨道清晰可读；填充段用古金或低饱和暖色，静音按钮为次级样式。 |
| Hover | 当前行滑块拇指和静音按钮边框提亮，`120~160ms` 完成；不改变行高、不放大面板。 |
| Pressed/拖动 | 拇指保持古金高亮；百分比每个步长即时更新。松开后不需要“应用”按钮。 |
| 键盘焦点 | `Tab` 顺序为三行的滑块/静音入口，再进入显示分辨率，最后进入游戏内 footer 的返回主菜单；焦点环完整可见，不用颜色单独表达。 |
| 滑块键盘 | `←/→` 每次 `1%`，`PageUp/PageDown` 每次 `10%`，`Home=0%`，`End=100%`；方向键不触发关闭或场景操作。 |
| 静音键盘 | `Enter/Space` 切换静音；切换后读数和按钮状态立即反馈。 |
| `0%` | 百分比明确显示 `0%`，滑块拇指在最左端；有效输出为静音，但不强制把显式静音按钮状态写成另一种值。 |
| 显式静音 | 静音按钮进入选中/按下状态，按钮可读名变为“取消静音”；百分比保持最后设置值。 |
| Disabled | 服务不可用、总线缺失或设置写入失败时，行整体降至约 `45%` 不透明度，禁止拖动/切换；状态提示说明原因，不能把禁用误显示成已应用。 |
| 错误反馈 | 配置保存或应用失败显示在声音组状态区，保留上一次已成功值；不得弹出覆盖滑块的连续错误对话框。 |

## 4. 显示分组

- 保留现有“画面分辨率”标签和 `OptionButton`，选项继续读取 `ResolutionSettings` 的正式目录：`1920×1080（推荐）`、`1600×900`、`1280×720`。不在本阶段增加画质、窗口模式或缩放选项。
- 分辨率选择仍即时应用；成功时状态行显示“已应用：<宽> × <高>，下次启动仍保留。”；失败时恢复上一次实际生效项，并显示可读错误。状态行最小高度 `48px`，允许两行，不得挤压声音行或返回主菜单入口。
- 状态提示视觉优先级低于分组标题和音量交互：正常提示用 `#9E9588`，失败提示用 `#C83A2A` 配合文字，不使用闪烁或整面板变色。分辨率选择改变窗口后，设置面板仍保持打开且布局重新适配。
- 显示设置与音频设置共用 `user://afterhonghuang-settings.cfg` 时，各自保存必须保留另一 section；UI 不显示配置文件名，但错误提示应明确“显示设置未应用”或“声音设置未保存”，不能混淆责任。
- 不支持的窗口尺寸/比例继续按现有契约禁用或提示“当前版本不支持”；不得通过缩小字体、压缩滑块或裁切设置面板伪装支持。

## 5. 关闭与节点迁移口径

### 5.1 关闭路径

| 操作 | 结果 | 禁止副作用 |
|------|------|------------|
| 点击右上角关闭 | 关闭当前共享设置实例，恢复原页面焦点 | 不回滚成功应用设置，不切标题，不提交节点结果，不清理牌组/生命。 |
| `Esc` | 与右上角关闭完全相同 | 不关闭下层节点或执行其它页面动作。 |
| 设置打开时点击 TopBar 任一入口 | 被全屏遮罩阻断，无响应 | 不关闭设置、不执行地图/套牌职责、不创建第二个设置页、不排队延迟执行。 |
| 打开时点击面板外 | 设置为模态时不关闭、不穿透 | 不触发下层卡牌、地图节点、战斗或页面按钮。 |
| 点击返回主菜单 | 直接提交 `AbandonRunToTitle` 意图给流程负责人 | UI 不伪装保存、不提交奖励、不推进节点、不自行清理上下文或切场景；不创建额外中间状态。 |

### 5.2 现有节点的保留、删除与迁移

| 现有对象 | 处理口径 | 说明 |
|----------|----------|------|
| `SettingsDialog.tscn` | 保留共享场景并重组节点 | 保留统一实例入口；迁移为自定义标题栏、`SoundGroup`、`DisplayGroup`、footer 结构，采用正式 `.tscn`、Theme 和复用 `VolumeRow`。 |
| `SettingsDialogController` | 保留设置表现与事件协调职责，补充音频绑定 | 不承担音频总线规则、配置保存或节点流程；关闭信号统一指向同一关闭命令。若现有 `AcceptDialog` 基类无法移除内建底部按钮，则将弹窗表现根迁移为可自定义标题栏的 `Window` 兼容根，保留共享实例契约。 |
| `SettingsHelper` | 保留 | 继续负责单实例生命周期、打开/关闭和 overlay 注册；不得新建第二套 SettingsManager。 |
| `ResolutionSettings` | 保留 | 继续作为分辨率目录、应用、保存和失败恢复的唯一事实源。 |
| `ReturnToTitleButton` | 删除旧节点、事件和对应连接 | 旧“返回标题界面”语义不再复用；设置关闭只回到原页面。 |
| `AcceptDialog` 内建“关闭”按钮 | 删除可见按钮和对应底部区域 | 右上角关闭与 `Esc` 是唯一关闭入口；不得增加底部“应用/关闭”。 |
| `ReturnToMainMenuButton` | 仅在游戏内设置实例显示，放在 footer 右侧 | 点击直接提交放弃本局并返回标题的意图；标题页设置隐藏，不伪装为存档或普通关闭。 |
| 音量数据/服务 | 由 `AudioSettingsService` 统一提供 | UI 不写入 `GameManager`，不建立全局 BGM 播放器，不复制音量状态。 |

### 5.3 游戏内返回主菜单

这是游戏内设置独有的危险操作，适用于 Map、Battle、Lingmai、Shop、Event、Boss 等存在当前运行上下文的页面；标题页打开设置时隐藏该入口。

| 项目 | 冻结口径 |
|------|----------|
| 按钮文案 | `返回主菜单`；不使用“保存并返回”“返回标题界面”或“离开节点”。 |
| 位置 | 设置面板 footer 右侧；按钮旁或其下方显示静态说明“当前对局进度不会保存”，不遮挡状态提示和音量控件。 |
| 点击反馈 | 不创建额外中间状态、不创建第二层 modal、不等待第二次点击；立即向场景/运行上下文负责人提交 `AbandonRunToTitle` 意图。 |
| 提交结果 | UI 不保存当前 RunState、不提交奖励、不推进节点、不自行清理或切场景；流程负责人清理当前节点和 BattleState 临时上下文后返回标题页。 |
| 可见性 | `SettingsContext.HasActiveRun=true` 时显示；标题页为 false 时隐藏且不占用 footer 空间。 |

## 6. Godot Control / Container / Theme 装配建议

- 使用一个可复用 `SettingsOverlay` 场景和一个 `VolumeRow` 子场景；声音三行只通过参数绑定标签、当前值和静音状态，避免控制器复制三套样式。
- 内容结构使用 `MarginContainer → VBoxContainer → SoundGroup / Separator / DisplayGroup / Footer`；每条音量行使用 `HBoxContainer`，滑块设置稳定最小宽度，百分比列和静音列固定宽度，避免数值变化造成布局抖动。
- 顶部使用自定义 `TitleBar` 的 `HBoxContainer`；标题左对齐，关闭按钮右对齐。不要依赖 AcceptDialog 自动创建的底部按钮来表达关闭。
- Theme 集中定义字体、字号、深棕底、米白文字、古金 focus/hover、赤色错误和禁用透明度；控制器不散落颜色、尺寸或长期文案。
- 关闭按钮、静音入口和游戏内返回主菜单入口都要有稳定最小热区；`1280×720` 等比缩放后，普通操作热区不小于约 `40×40` 物理像素，分辨率选项和滑块仍可用键盘操作。
- 面板、滑块、按钮尽量复用当前项目已有纸张/墨色底、九宫格和按钮状态资源；本阶段不要求新美术资源，不使用纯 emoji 作为正式图标。

## 7. 分辨率验收

| 检查项 | 1920×1080 | 1280×720 |
|--------|-----------|----------|
| 面板 | 居中 `760×660` 逻辑布局；标题栏、三条声音行、显示组和游戏内返回主菜单 footer 全部可见 | 等比缩放后约 `507×440`；不裁切、不与窗口边缘重叠，内容仍可上下扫描 |
| 声音行 | 标签、滑块、百分比、静音入口在同一水平轴；值变化不跳列 | 每行仍至少约 `43px` 高；滑块拇指、百分比和焦点环清楚可见 |
| 显示状态 | 分辨率下拉和成功/失败状态同组显示 | 状态可换行但不覆盖返回主菜单入口；错误文字可读 |
| 关闭与返回 | 右上关闭明显；游戏内返回主菜单位于 footer 右侧且不是主按钮 | 关闭热区不小于约 `40×40`；返回入口不与状态提示重叠 |
| 背景与遮罩 | 设置下层变暗但不抢面板；面板正文对比充分 | 下层不可点击；文字、滑块和按钮不因缩放失读 |

## 8. 最小窗口验收清单与升级条件

### 8.1 窗口验收路径

1. 从标题页打开设置，确认单页同时出现“声音”和“显示”，不存在“返回主菜单”和底部内建“关闭”；游戏内设置才显示“返回主菜单”。
2. 检查首次值为总音量 `80%`、音乐 `65%`、音效 `80%`；拖动三条滑块，百分比与听感即时变化。
3. 将音乐调低/静音，确认音效不随之静音；将总音量调低/静音，确认音乐与音效均受影响；标题 BGM 使用音乐行语义。
4. 分别测试每行 `0%`、显式静音、取消静音、键盘 `Home/End/方向键/PageUp/PageDown`，确认读数和焦点反馈明确。
5. 选择支持的分辨率，确认既有实时应用和状态提示保持；制造/遇到应用失败时，选项恢复上一次成功值且错误可读。
6. 点击右上角关闭或按 `Esc` 关闭同一实例；设置打开期间点击 TopBar 设置入口不响应，关闭后必须重新点击才可打开设置；原节点页状态和已成功设置保持。
7. 在设置打开期间尝试点击面板外、TopBar、下层按钮和其它节点操作，确认全视口无点击穿透；不产生第二个设置页。
8. 在 1920×1080、1280×720 窗口各检查一遍；确认 1280 下控件可读、可聚焦、可操作。

### 8.1.1 覆盖层与输入回归路径（BUGFIX-OVERLAY-CARD-INPUT-001）

| 路径 | 操作 | 通过标准 | 失败判定 |
|------|------|----------|----------|
| 地图 → 设置 | 打开地图，横向滚轮或左键拖拽到非初始位置；点击 TopBar 设置；再用右上角关闭或 `Esc` | 设置位于地图之上；地图不关闭、不重建；关闭后回到同一地图实例、同一滚动位置、同一只读/可交互状态 | 点击设置先关闭地图、地图回到初始位置、节点页重建或地图输入穿透 |
| 胜利面板 → 设置 | 进入胜利面板，点击设置；尝试点击下层奖励行、Continue、手牌/Debug 和 TopBar 区域 | 设置全屏遮罩覆盖并阻断整个视口；TopBar 仍可见但不可交互；只有设置面板、右上角关闭和 Esc 响应；关闭后胜利面板焦点与奖励进度不变 | 设置被胜利面板遮住、下层或 TopBar 可点、关闭入口失效或奖励进度丢失 |
| CardReward → 设置 | 打开 CardReward，记住候选顺序与已领取进度；点击设置；关闭设置 | 设置位于 CardReward 之上；CardReward 不销毁、不重抽、不接收输入；关闭后候选与进度完全相同 | CardReward 被销毁/重建、候选变化、奖励行被消费或输入穿透 |
| 地图 + CardReward → 设置 | 在胜利页先打开 CardReward，再打开地图，再点击设置；关闭设置、地图 | 设置始终位于当前内容平面最上层；关闭设置露出同一地图，再收卷露出同一 CardReward 与胜利面板 | 设置打开导致地图或 CardReward 关闭/重建，关闭顺序错误或出现空白页 |
| 设置 → 其它 TopBar 入口 | 设置打开时点击地图、套牌或设置入口；再用右上角关闭，之后重新点击一个 TopBar 入口 | 设置期间所有 TopBar 热区均无响应；关闭只由右上角或 Esc 完成；关闭后新的 TopBar Press 才执行自身职责；无重复设置实例和点击穿透 | 设置被 TopBar 点击关闭、入口被延迟执行、同时出现多个 overlay 或下层收到被遮罩点击 |

| 攻击牌目标区释放 | 敌方目标牌拖到合法敌人、其它 UI 控件、空白区分别释放 | 统一手势负责人消费每次 Release 一次：合法敌人只结算一次；其它区域只回弹一次，不静默丢事件、不重复扣费 | 释放到控件后无反应、由多个控件重复处理、攻击牌飞出后卡死或重复结算 |

### 8.2 必须升级给总项目经理的条件

- 为隐藏 AcceptDialog 内建按钮必须改动共享弹窗生命周期、`OverlayCoordinator` 或 `GameManager`，超出阶段 B 任务卡允许文件范围。
- `AudioSettingsService` 无法提供独立的音频快照/变更结果，导致 UI 必须直接写总线或复制音量状态。
- 分辨率现有保存逻辑无法保留 `audio` section，或失败恢复会覆盖另一设置分组。
- 需要新增美术资源、重制 BGM、建立全局常驻 BGM 播放器，或改变标题视频/玩法/节点流程。

本规格不启动 QA、自动化或窗口代操作；阶段 A 仅交付文档，代码实现后的状态按项目规则为“开发完成，待用户窗口验收”。
