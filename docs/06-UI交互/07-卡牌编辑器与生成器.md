# 07-卡牌编辑器与生成器

> 版本: 0.4.0 | 状态: 冻结最小开发工具 UX / C5 完整制卡与执行同源验收口径 | 最后更新: 2026-07-20

---

## 1. 定位与边界

本工具面向开发、策划和测试人员，用于维护卡牌定义草稿、检查数据并生成本地开发产物。它不是玩家运行时 UI、不是卡牌收集页、不是营销展示页，也不进入 Release 构建或玩家菜单。

- 仅作为 Godot `EditorPlugin` 在编辑器内运行；入口位于插件菜单或停靠面板。不得提供独立运行时命令、玩家调试入口或 Release 资源入口。
- 编辑器专用入口不得出现在玩家 Title、TopBar、设置、BattleNode、MapOverlay、DeckOverlay 或任何 Release 输入映射中。
- 正式 UI 优先使用独立 `.tscn`、集中主题和复用表单/校验控件；不得把编辑器界面继续塞进战斗、TopBar 或动态脚本拼装的玩家页面。
- 编辑器只读取和写入策划部冻结的版本化卡牌 Schema。缺 Schema、Schema 版本不匹配或定义字段不足时，必须阻断生成并显示错误，不能按卡牌名称、临时默认值或 UI 分支猜测规则。
- “生成”只产生可审查的本地开发输出及 manifest；预览、校验和取消均不得悄悄修改正式运行时数据。接入正式数据目录、版本控制提交和发布流程由开发部/策划部另行定义。
- 本工具不创建、覆盖或改变 NodeContinue、MapOverlay、TopBar、灵脉节点、奖励节点及其输入层级/状态合同；这些玩家 UI 合同继续以 `00-UI交互总览.md` 与 `01-MVP界面交互.md` 为准。

## 2. Schema 对接边界与新建草稿

最低草稿载体为 `CardDefinitionDraft`，对应 `CardDefinitionResource Schema v1` 的完整可编辑投影。编辑器不得只新建名称、费用和描述后就允许生成；任何可生成单卡必须有完整结构化字段、可解析预览和可验证的效果序列。

| 表单顺序 | 必填字段 | UI 约束 |
|----------|----------|----------|
| 1. 身份/归属 | `SchemaVersion`、稳定 `Id`、`DisplayName`、`DescriptionFallback`、本地化/显示引用、`Owner` | SchemaVersion 只读；ID 目录唯一且符合命名规则；Owner 用受控枚举/资源选择；fallback 非空并与 Effects 预览一致，不能拿空字符串或卡名反推效果 |
| 2. 费用与分类 | `Costs[]`（费用类型、数量、失败策略；生命费用声明 `CanCauseDefeat`）、`Category`、`Rarity`、`Tags`、`Availability`、`Balance` | 至少一个明确费用语义；不得把生命支付偷藏在效果描述里；类别/稀有度/标签/可用性/平衡元数据不能由运行时默认补齐 |
| 3. 目标策略 | `TargetPolicy` 的 `SelectionMode`、`Scope`、最小/最大目标数、无效重定向策略 | 以结构化目标策略驱动预览；ACT1 仅允许已实现的 `None`、`Self`、`SingleEnemy` 进入生产池 |
| 4. 效果列表 | `Effects[]` 的 `Order`、`EffectType`、目标选择器、参数/公式、持续域或移区信息 | 每项效果可新增、删除、排序并按连续 Order 校验；不可只填写“伤害 8”这种无类型摘要 |
| 5. 池/升级/预览 | `RewardPoolIds`、`Upgrade`、`Preview`/`AssetRefs`、`Source`、`GeneratedBy`、生成时间或 manifest 引用 | 池、升级和预览引用都是生成字段；资源解析失败显式提示；追踪信息由工具生成但必须可见、可审查 |

### 2.1 受控未分配新建态

“新建草稿”必须一次性创建完整字段**控件树**，但不得替用户填入任何具体职业、卡池、内容 ID、类别、效果或数值。除 `SchemaVersion` 外，所有内容绑定字段在 UI 中初始显示为 `未分配`；这是编辑器专用哨兵，不是任一 Schema 枚举、Resource 值、卡池 ID 或可序列化的 `CardDefinitionResource` 字段。

| 字段 | 新建态显示 | 保存/生成前条件 |
|------|------------|----------------|
| `SchemaVersion` | 当前冻结版本 `1`，只读 | 唯一允许的受控默认值；防止写入旧结构 |
| `Id` | `未分配` | 用户输入目录唯一、符合命名规则的稳定 ID；不得生成临时 `draft_*` 内容 ID |
| `DisplayName` / `DescriptionFallback` | `未分配` | 均须明确填写；fallback 必须能被预览，且与有序 Effects 摘要一致，不能为空或由名称反推效果 |
| `Owner` / `Category` / `Rarity` | `未分配` | 由受控枚举/资源选择；不得预置 `Neutral`、具体角色、`Skill` 或任一稀有度 |
| `Costs[]` | `未分配` | 至少添加一项完整费用；生命费用须同时声明 `CanCauseDefeat`，不得预置费用类型或数值 |
| `TargetPolicy` | `未分配` | 必须选择 `SelectionMode`、`Scope`、目标数和无效重定向策略；不得预置 Self、敌方或任意目标策略 |
| `Effects[]` | `未添加效果` | 用户显式添加至少一项效果，填写连续 `Order`、`EffectType`、目标选择器、参数/公式和持续域/移区；不得预置 `GainBlock` 或任何数值 |
| `RewardPoolIds` | `未分配` | 必须由 Catalog 可选池显式选择；不得预置 `wuzhu`、`reward_cards`、草稿池或任何具体池 ID |
| `Upgrade` | `未分配` | 必须明确选择“不可升级”或填写完整升级关系；不可升级是用户确认的内容决定，不是默认值 |
| `Tags` | `未分配` | 至少添加经 Schema 允许的标签；不得注入 `draft` 等隐含内容标签 |
| `Availability` / `Balance` | `未分配` | 分别填写可用版本/特性/禁用原因及完整平衡元数据；不得预置 B1、未发布或未分类状态 |
| `Preview` / `AssetRefs` | `未分配` | 必须选择可解析资源，或按 Schema 明确选择“允许空占位”并提供可读原因；不得硬编码资源路径 |

`未分配` 存在时，编辑器可以在内存中保持当前输入、显示字段错误和卡面骨架，但**保存草稿、生成预览、确认生成均不可用**，并显示未完成字段数和定位入口。它不得写入 `.tres`、Catalog、奖励池、升级图、manifest、隔离资源目录或任何可被运行时读取的持久化位置。崩溃恢复若有，最多保存非生产的会话恢复数据，重开后仍显示为未保存、未分配草稿，不能伪装为已保存定义。

策划部负责字段语义、效果合法组合和数值规则；开发部负责 Schema 解析、唯一 ID 查询、生成器和产物目录；UI/UX部只定义工具流程、错误呈现和可读性。新增卡牌不应要求修改编辑器控制器的具体名称或 ID 分支。

## 3. 最小工具界面

```text
┌──────────────────────────────────────────────────────────────┐
│ 新建草稿 | 保存草稿 | 校验 | 生成前 diff | 确认生成              │
├───────────────┬────────────────────────┬─────────────────────┤
│ 编辑表单       │ 卡面预览                │ 校验与生成结果       │
│ 身份/归属       │ 名称、费用、类别、描述      │ 错误摘要 / 字段定位   │
│ 费用与分类      │ 目标策略、效果顺序、资源状态│ 产物 diff / manifest  │
│ 目标/效果/池升级│ 仅展示，不执行战斗          │ 可复制的错误详情       │
└───────────────┴────────────────────────┴─────────────────────┘
```

- **编辑**：左栏严格按“身份/归属 → 费用与分类 → 目标策略 → 效果列表 → 池/升级/预览”顺序分组。所有内容绑定字段初始为 `未分配`，必填项和阻断原因可见；任何编辑都会标记 dirty，并在离开、切换草稿或取消前给出保存/丢弃/留在当前页选择。删除/重置草稿需单独确认，不与关闭窗口混用。
- **未选枚举与数值显示**：任何尚未选择的枚举、对象引用、效果类型、目标选择器、费用类型都显示 `未分配`；尚未填写的数值/公式显示 `未设置`。二者均为错误态文案，不映射为 `自身`、`None`、`0`、首个枚举项或其他运行时默认值。字段完成选择或输入后才显示对应语义和值。
- **预览（编辑态）**：中栏只显示“按 `Effects.Order` 的效果时间线”、目标策略摘要和静态卡面骨架。每个时间线步骤直接读取当前效果的 Order、类型、目标和参数；未分配/无效字段显示错误占位，不伪造一张可打出的卡，也不创建 BattleState、加入玩家套牌或发放奖励。
- **效果列表**：空列表显示 `未添加效果` 与“新增效果”按钮；点击后必须能创建首个可编辑效果行（Order、类型、目标、参数/公式、持续域/移区均为 `未分配/未设置`），不能要求用户先存在旧效果。每行有删除、上移、下移操作；删除最后一项后回到空列表错误态。重排后自动重编号为连续 Order，并立即更新预览时间线和 DescriptionFallback 一致性检查；重复、跳号、无效目标或缺参数均为字段级阻断错误。
- **校验**：工具栏“校验”运行 Schema、ID、Owner/Category、费用、TargetPolicy、效果顺序/参数、池/升级、可用性、平衡元数据、资源和文案参数检查。通过显示版本、摘要和时间；失败按字段定位。未校验、校验过期或校验失败时“确认生成”禁用，并说明原因。
- **生成前 diff**：展示“新建/覆盖/无变更”类型、目标 Resource、Catalog/池/升级引用变化、字段级旧值→新值、预计 manifest 和输出集合。diff 没有被明确确认前，不允许任何写入。
- **生成**：确认后显示“正在写入”状态，使用暂存输出和原子提交；成功显示产物清单、manifest 身份和可审查路径。失败保留草稿及全部错误，不显示假成功。

### 3.1 保存、冲突与目录更新

- **保存前条件**：所有必填字段完成、Validator 通过、diff 已刷新且没有未确认变更时，`保存草稿`才可用。保存用于写入有效 `CardDefinitionResource`，不是把未分配输入落盘的快捷方式。
- **重复 ID**：输入的 ID 已被 Catalog 或现有 Resource 占用时，ID 字段显示 `重复 ID`、冲突资源名称和路径；保存/生成禁用。用户只能修改 ID、打开现有资源查看差异或取消，不能以自动改名、取第一项或覆盖现有资源化解。
- **路径冲突**：目标 `.tres` 路径已存在而当前不是该资源的显式编辑会话时，显示 `路径冲突`、现有资源身份和目标路径；默认操作为取消。只有“编辑已打开的同一资源”才允许写回原路径，并在确认框中显示字段 diff；新建资源不得静默覆盖。
- **成功保存**：原子提交成功后，界面显示实际 Resource 路径、Catalog 更新结果、写入的 manifest/追踪身份和最新校验时间；资源目录刷新后可在插件卡表定位该 ID。任一目录、Catalog 或 manifest 更新失败均进入回滚态，不得显示保存成功。

### 3.2 编辑预览与运行时执行同源

编辑器预览和玩家运行时不共用“显示猜测”，但必须共用同一份结构化定义和执行顺序：

| 阶段 | 输入 | UI 必须呈现 | 禁止行为 |
|------|------|-------------|----------|
| 编辑态预览 | `CardDefinitionDraft` 的 `TargetPolicy` 与按 `Effects.Order` 排序的效果项 | 标题“按 Effects.Order 的效果时间线”；每步显示顺序、类型、目标与参数；未分配字段显示错误 | 根据 DescriptionFallback、卡名或固定旧字段编造效果、顺序或目标 |
| 目标确定后 | 已校验 `CardDefinition` + 当前战斗上下文 + 已选目标 | 由开发部构造不可变 `ResolvedCardExecution`，其中包含实际目标、实际费用、按顺序解析后的效果步骤及参数 | UI 另算费用/目标/效果，或让日志使用另一份效果顺序 |
| 确认与结算 | 同一 `ResolvedCardExecution` | 确认摘要、战斗日志、结算飘字/状态反馈均引用同一执行身份和步骤序列；日志按实际结算完成的步骤输出 | 先显示描述摘要再按另一套固定字段结算，或在目标变化后复用旧解析结果 |

`DescriptionFallback` 是显示/本地化回退字段，不是执行规则来源。编辑器应在校验中比较其摘要与 Effects 时间线是否明显矛盾；玩家运行时则以 `ResolvedCardExecution` 为唯一可见确认、日志和结算顺序来源。缺少该对象、目标已失效或执行身份不匹配时，必须阻断出牌并显示可追踪错误，不能静默回退为无目标、零费用或第一张卡定义。

## 4. 错误与状态呈现

| 状态 | 呈现 | 禁止行为 |
|------|------|----------|
| 未分配新建态 | 所有内容绑定控件显示 `未分配`；保存、diff、生成禁用，并列出未完成字段数 | 预置具体职业、卡池、内容 ID、效果、费用或把哨兵序列化 |
| 未保存草稿 | 工具栏 dirty 标识、关闭/切换前保存、丢弃、留在当前页三选一 | 静默丢弃、自动保存或自动生成 |
| 字段错误 | 字段旁错误、右栏摘要、点击摘要定位字段；错误在字段被修复前持续可见 | 只写控制台日志或以默认值继续 |
| Schema/版本错误 | 阻断横幅和预期/实际版本 | 自动迁移并覆盖原草稿 |
| 重复 ID | ID 字段显示冲突 Resource 名称和路径；保存/生成禁用 | 自动改名、取第一项或覆盖现有 Resource |
| 路径冲突 | 显示现有资源身份、目标 `.tres` 路径和取消入口；新建资源默认取消 | 静默覆盖；把不同 ID 写入现有路径 |
| 资源缺失 | 显示缺失引用、字段路径和资源选择入口，阻断保存/生成 | 回退到首张卡、默认资源或假 ID |
| 未完成定义 | 列出所有 `未分配`、无效或不一致字段的逐字段阻断原因 | 把新建态当作玩家可用卡、注入默认内容，或偷偷改投任一奖励池 |
| 生成预览 | 显示 diff、输出集合、Catalog 影响和 manifest | 预览即写正式数据 |
| 确认写入 | 显示不可重复点击的进行态；写入完成前禁用关闭/再次生成 | 并发生成、只写一部分资源后报告成功 |
| 写入失败/回滚中 | 显示失败阶段、当前回滚进度和受影响资源集合 | 关闭窗口掩盖失败、继续显示旧 diff 为成功 |
| 已回滚 | 显示“未写入任何正式产物”，列出已清理的暂存/目标路径及可复制诊断；草稿保留且仍为 dirty | 留下孤儿 Resource、Catalog 引用、半写 manifest 或假成功 |
| 回滚失败 | 阻断横幅、残留路径清单、诊断 ID、重试/复制诊断入口；禁止继续生成 | 静默忽略残留文件或把未清理状态标为成功 |

## 5. 开发验收清单

1. 新建草稿立即含本章全部字段控件树；除只读 `SchemaVersion` 外，内容绑定字段一律显示 `未分配`，不预置具体职业、卡池、内容 ID、类别、费用、目标或效果，且保存/diff/生成均禁用。
2. 表单顺序固定为“身份/归属 → 费用与分类 → 目标策略 → 效果列表 → 池/升级/预览”；每组的必填标识、未完成计数和跳转错误入口均可见。
3. 任何未选枚举/对象/效果类型/费用类型均显示 `未分配`，未填数值/公式显示 `未设置`；它们绝不显示或传递为“自身”、`None`、`0`、首个枚举项或其他隐式值。
4. 空 Effects 列表可点击“新增效果”创建第一行；首行的 Order、类型、目标、参数/公式、持续域/移区均可编辑。新增多行后可删除、上移、下移；删除最后一项恢复空列表错误态，重排后预览与连续 Order 一致。
5. 完整填写一张 ACT1 单卡后，`DescriptionFallback`、卡面、目标策略摘要和按 `Effects.Order` 的效果时间线一致；改变效果顺序会同步更新预览和一致性检查，不能沿用旧顺序。
6. 缺少必填字段、无效 Owner/Category、费用错误、无效 `TargetPolicy`、重复/跳号 `Order`、效果参数错误、重复 `Id`、路径冲突、未知奖励池、断升级、Availability/Balance 缺失、文案参数缺失、资源引用缺失各至少覆盖一次：字段定位和摘要一致，且保存/生成被阻断。
7. 编辑后 dirty 可见；关闭、切换、重置、diff 和确认均有保存/丢弃/取消的明确路径。校验通过后再修改任意字段，保存与生成权限必须立即失效，直到重新校验并刷新 diff。
8. 编辑器预览的每个效果步骤与同一草稿 `Effects.Order`、目标和参数一致；玩家运行时在目标确定后，预览、目标确认摘要、日志和执行反馈都由同一 `ResolvedCardExecution` 驱动。用两张名称、费用、目标和顺序均不同的定义反证不会串用旧固定字段。
9. 校验通过但未确认 diff/写入时不得写输出；取消 diff/确认对话框后草稿仍在，正式数据、Catalog、奖励池、升级关系和 manifest 均无变化。重复 ID 或路径冲突时必须显示冲突身份和路径，且新建资源不得覆盖。
10. 有效保存后，插件显示实际 Resource 路径、Catalog 更新、manifest/追踪身份和最新校验时间；刷新资源目录与插件卡表后能定位同一 ID。目录、Catalog 或 manifest 任一步失败均回滚，不得显示成功。
11. 注入任一写入阶段失败时，界面先显示失败与回滚；回滚成功后确认没有孤儿 Resource、半写 manifest、Catalog/奖励池/升级引用残留，草稿仍可修复并重试。回滚失败必须显示残留路径与诊断，不能显示成功。
12. 编辑器只在 Godot Editor Plugin 的菜单/停靠面板出现；Release 构建、玩家 Title、TopBar、BattleNode、MapOverlay、DeckOverlay 和设置菜单中均不存在入口。

## 6. 本轮不做与依赖

- 本轮只做 Godot Editor Plugin 内的最小单卡创建、编辑、校验、预览、diff、保存和回滚体验；不做运行时玩家制卡、卡牌美术重做、批量 AI 生成、自动平衡、自动提交版本控制、批量迁移或遥测看板。
- 依赖策划部提供版本化卡牌 Schema、效果枚举、目标模式、文案参数规则和校验规则。
- 依赖开发部提供 Definition 解析、唯一 ID 查询、未分配态不可序列化门禁、生成器、暂存/原子提交/回滚、开发产物目录、manifest 与 Debug/Release 隔离，以及 `ResolvedCardExecution` 作为目标确定后的确认/日志/结算唯一执行视图。缺任一依赖时工具应显示阻断原因，而不是退化为可写的自由文本页、注入默认内容或向正式奖励池回退。
