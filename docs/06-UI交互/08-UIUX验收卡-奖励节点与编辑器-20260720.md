## 1. 使用边界

本页是 `UI-REWARD-NODE-COHERENCE-20260720` 与 `CARD-AUTHORING-UX-REVIEW-20260720` 的可执行 UI/UX 验收卡，不代表任何实现已经通过。QA 先做静态可证伪检查，再由用户或指定验收人员完成 Godot 编辑器/游戏窗口实测；构建、headless 或截图不能替代下列交互结果。

本页不改变 Continue、地图、TopBar、灵脉、奖励事务或 `CardDefinition Schema v1` 的既有数据边界；详情以 `00-UI交互总览.md`、`01-MVP界面交互.md`、`07-卡牌编辑器与生成器.md` 为准。

## 2. 奖励与节点页冻结契约

### 2.1 层级、输入与恢复

| 层/状态 | 输入与视觉责任 | 关闭/切换后的恢复 | 明确禁止 |
|----------|----------------|-------------------|----------|
| `TopBar` | 唯一常驻全局可交互层；地图、套牌、设置始终可请求打开 | 全局 overlay 关闭后回到此前的节点页或 CardReward 焦点 | 被胜利遮罩、地图或 CardReward 覆盖/禁用；另建第二套全局入口 |
| 胜利总面板 | 仅处理灵韵领取和奖励行；奖励内容列、文字与可点行命中矩形均以 `VictoryPanel` 主轴居中 | 上层关闭后仍保留同一面板、奖励行和领取进度 | 用局部文本居中伪装整体居中；在面板内放置继续/地图入口 |
| `NodeContinue` | 节点页本地右下操作位，固定文案 `继续`，tooltip 为“打开地图卷轴”；只执行 `ToggleOverlay(MapOverlay)` | 地图收卷且无 CardReward 时恢复同一位置和可用性 | 领取奖励、提交 NodeResult、结算灵脉/商店、离场、清页或跳转空白 MapScene |
| `MapOverlay` | 当前节点页上的共享地图；打开时独占 TopBar 下缘以下的内容区输入，并覆盖整个当前节点内容，包括 VictoryPanel、CardReward 与 Continue | 收卷后精确恢复原节点页、奖励/选项、滚动和焦点；只有点击合法节点才离场 | 地图打开后 CardReward/Continue 仍可见或可点；战斗中可进入节点；关闭后丢失当前页面 |
| `CardRewardOverlay` | 胜利面板上的局部模态；地图关闭时展示同一 `RewardPlan`、候选顺序和已选进度，并覆盖 Continue | 跳过/关闭只关闭自身，回到同一胜利面板与奖励行；地图激活时仅保留状态，收卷后恢复 | 点击穿透 Continue/底层战斗；位于地图之上；关闭即删除奖励行、消费奖励或清空进度 |

地图激活时内容区优先级固定为：`MapOverlay` → `CardRewardOverlay`（保留状态但被地图覆盖）→ `NodeContinue` → `VictoryPanel/NodeContent`。TopBar 位于该内容区之外并保持交互。

当 CardReward 激活时由 TopBar 请求打开地图，协调器必须保留而非销毁当前 CardReward 焦点、候选顺序和已选进度，并让地图覆盖其视觉与输入；地图关闭后恢复该 CardReward。任一时刻内容区只能有一个实际输入焦点，不得以抬高 Continue 或 CardReward 的固定 ZIndex 绕过地图。

### 2.2 无空白页回归

Battle 胜利、Lingmai、Shop、Event 的 `继续` 和 TopBar 地图只开关当前页上的 MapOverlay。任一关闭、取消、非法节点点击、路由失败或奖励未完成路径都必须保留可见的原节点页面或明确错误页；只剩 TopBar、空白底色、失效按钮或旧页输入回调均为失败。

## 3. 灵脉冻结契约

| 项目 | 通过行为 | 失败行为 |
|------|----------|----------|
| 队友治疗可见性 | UI 只读取 PartyRoster/等价队伍上下文中的合法非自身友方目标列表；列表为空时隐藏“疗愈道友” | 用 `is_singleplay` 等散落布尔值驱动；单人仍显示不可用队友治疗占位 |
| 满血休养生息 | 当前生命等于上限时仍可点一次；即时显示“已圆满，无额外变化”，生命数值可不变，随后该选项按节点一次性规则灰置 | 满血初始禁用；点击无反馈；可重复领取/重复反馈 |
| 本地继续 | 未选择灵脉操作也可点击 `继续` 打开地图；不提交 `Skipped/Exited`、不写访问状态 | 点击继续即消耗灵脉、结算节点、跳转地图页或出现空白页 |

## 4. Editor-only 卡牌编辑器契约

编辑器仅作为 Godot `EditorPlugin` 菜单/停靠面板存在，绝不出现在 Title、TopBar、设置、BattleNode、MapOverlay、DeckOverlay、玩家调试入口或 Release 输入映射中。

| 验收面 | 冻结口径 |
|--------|----------|
| 新卡起点 | 仅 `SchemaVersion=1` 预置。其余内容字段全部显示“待配置/未分配”，为不可序列化的编辑器哨兵；不得假装为具体职业、卡池、类别、费用、目标、效果、标签或内容 ID。未分配时保存、diff、生成均禁用。 |
| 字段分组 | 严格为“身份/归属 → 费用与分类 → 目标策略 → 效果列表 → 池/升级/预览”；每组显示必填标志、未完成计数和可跳转的字段错误。 |
| Effect 列表 | 空列表显示“未添加效果”和“新增效果”；可新增第一项，填写 Order、类型、目标、参数/公式、持续域/移区；支持删除、上移、下移与连续 Order 重排。未选枚举显示“未分配”，未填数值显示“未设置”，不得显示为自身、`None`、`0` 或首个枚举项。 |
| dirty、确认与保存 | 编辑即 dirty；离开/切换/重置有保存、丢弃、取消路径。校验通过后改任意字段，保存/生成重新禁用直至校验和 diff 刷新。确认前不写入；取消后不改变 Resource/Catalog/池/升级/manifest。 |
| 冲突与失败恢复 | 重复 ID 显示冲突 Resource 与路径；路径冲突显示目标 `.tres` 与取消入口；新建资源不静默覆盖。写入失败显示失败阶段与回滚进度；成功回滚后无孤儿 Resource/Catalog/manifest，回滚失败必须显示残留路径与诊断。 |
| 预览边界 | 编辑态卡面只展示“按 Effects.Order 的效果时间线”，不伪造可打出的默认卡。目标确定后，确认摘要、日志与结算反馈只读取同一不可变 `ResolvedCardExecution`；DescriptionFallback 不得作为执行规则来源。 |

## 5. 验收分工

### 5.1 QA 静态可证伪检查

| # | 检查项 | 静态判定 |
|---|--------|----------|
| S1 | 层级与输入门禁 | Continue 相对 Map/CardReward 的层级为低；地图激活时高于 CardReward、Continue 与 VictoryPanel 并覆盖其命中区；TopBar 未被内容遮罩纳入；无全局高 ZIndex Continue/CardReward 例外。 |
| S2 | 按钮副作用 | 搜索 Continue/地图/关闭/跳过回调：Continue/地图不含奖励领取/放弃、NodeResult、离场、`GoToScene(Map)` 或页面清理；关闭/跳过只允许关闭自身 overlay，不得清理底层页面或状态。 |
| S3 | 奖励稳定性 | CardReward 读取稳定 RewardPlan 身份、候选和已选进度；跳过/关闭路径不消费奖励或删除奖励行。 |
| S4 | 灵脉数据来源 | 队友治疗只消费 PartyRoster/合法目标列表；满血休养初始可用且行动后只有该选项灰置。 |
| S5 | 编辑器入口与新建态 | EditorPlugin-only；Release/玩家树和输入映射无入口。除 SchemaVersion 外新卡字段为不可序列化未分配态；无具体职业、卡池、ID 或效果预置。 |
| S6 | 编辑器编辑与保存 | 可新增首个 Effect，删除/重排/参数校验完整；未选枚举不被回退为自身/0；重复 ID/路径冲突、原子写入与回滚有可检查门禁。 |
| S7 | 执行同源 | 编辑预览按 Effects.Order；目标确定后 UI 确认摘要、日志和执行均消费同一 ResolvedCardExecution，不按卡名/描述/旧固定字段分支。 |

### 5.2 必须人工窗口实测

| # | 操作路径 | 预期可见结果 |
|---|----------|--------------|
| W1 | 胜利页观察一条、两条奖励，再领取灵韵 | 奖励内容和可点行整体围绕胜利面板主轴；领取后余行垂直补位，横向不偏移。 |
| W2 | 打开 CardReward 后点击右下原 Continue 区域；关闭/跳过后重试 | CardReward 期间 Continue 无响应；关闭后恢复。候选顺序和多选进度保持，不删除未完成奖励行。 |
| W3 | 胜利页点 Continue 开地图，收卷地图；CardReward 激活时从 TopBar 开地图再关闭 | 地图完整覆盖 VictoryPanel、CardReward 与 Continue；内容区只有地图可操作。收卷回同一胜利/奖励焦点。TopBar 全程可点；CardReward 被恢复而非重抽、丢失或禁用。 |
| W4 | Battle、Lingmai、Shop、Event 各点 Continue、关闭地图、尝试非法节点 | 始终返回原节点页面；无空白占位页；仅合法节点点击才离场。 |
| W5 | 单人进入灵脉；满生命点击休养生息 | 不显示疗愈道友；休养可点一次，显示“已圆满，无额外变化”，随后该项灰置。 |
| W6 | Godot EditorPlugin：新建卡、填写字段、空 Effects 新增首项、重排/删除、取消、重复 ID/路径冲突、保存失败 | 初始全部为待配置；错误定位清晰；取消不写入；冲突不覆盖；失败可见回滚。 |
| W7 | 用两张目标与 Effects 顺序不同的卡完成目标确认和结算 | 卡面预览、确认摘要、日志和实际反馈按各自 ResolvedCardExecution 顺序一致，不串卡、不显示旧顺序。 |
