# 03-存档系统

> 状态: ✅ v1.0 | 最后更新: 2026-07-05

---

## 概述

采用**节点级存档**方案。存档时机为地图节点过渡之间，战斗中不存档。

这是永久设计决策——不仅为了降低实现复杂度，也因为 **S/L（存档/读档）本身就是 Roguelike 卡牌游戏的核心战术玩法之一**：玩家在地图分支节点冒险尝试不同路线、验证道痕构筑效果，都是通过节点级存档实现的。

## 设计原则

| 原则 | 说明 |
|------|------|
| 节点级存档 | 存档时机在地图节点之间（进入战斗前、战斗胜利后、事件选择后），不在出牌/战斗中途存档 |
| 单一存档位 | 一个角色一条命，不存在"多存档槽"。存档覆盖不可逆 |
| 死亡即删档 | 角色死亡后存档立即清除，无法通过读档复活（Roguelike 核心约束） |
| C# 实现 | 用 `System.Text.Json` 序列化 GameManager 状态，存储至 `user://save_<CharacterId>.json` |
| 热退出自动存档 | 按 ESC 退出 / 关闭窗口时自动调用存档，下次启动有"继续游戏"按钮 |

## 存档时机

```
Title → 角色选择 → 道韵固化后 ─存档→ 地图 ─选择节点后─存档→ 战斗 ←──┐
                         │                                        │
                         │                               战斗胜利后─存档→ CardReward → 地图
                         │                                        │
                         │                               战斗失败 → 删档
                         └────────────────────────────────────────┘
```

| 时机 | 触发方式 | 说明 |
|------|---------|------|
| 道韵固化后 | 自动 | 选完道痕后立刻存档（防止意外退出丢失道痕选择） |
| 进入地图节点前 | 自动 | 玩家在地图上点了一个节点但还没进去，此时存档方便 S/L 尝试不同路线 |
| 战斗胜利后（CardReward 之前） | 自动 | 保证胜利结果不丢失 |
| 灵脉/事件节点结束后 | 自动 | 节点效果已结算完毕 |
| 按 ESC 退出 | 自动 | 保存当前进度后退出 |
| 关闭游戏窗口 | 自动（`NotificationWMCloseRequest`） | 同上 |

## 存档数据结构

```json
{
  "characterId": "wuzhu",
  "difficulty": "地仙",
  "playerHp": 75,
  "playerMaxHp": 80,
  "playerLingli": 3,
  "playerMaxLingli": 3,
  "playerDoujin": 0,
  "playerHuti": 0,
  "playerYirongCeng": 0,
  "playerYongyan": 0,
  "lingYun": 0,
  "daoMarks": [
    { "id": "dm_tixiu_jingang", "name": "体修金刚", "grade": "地品", "description": "...", "effectType": 1, "effectValue": 10 }
  ],
  "daoMarkSelected": true,
  "currentMapLayer": 0,
  "currentMapIndex": 0,
  "visitedNodeIds": ["node_dao"],
  "deckCardIds": ["拳袭", "拳袭", "拳袭", "拳袭", "格挡", "格挡", "格挡", "格挡", "烈拳", "燃血"]
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `characterId` | string | 角色 ID，同时也是存档文件名的一部分 |
| `difficulty` | string | 难度标签（凡人/地仙/天仙） |
| `playerHp` ~ `playerYongyan` | int | 战斗属性快照 |
| `lingYun` | int | 灵韵货币数量 |
| `daoMarks` | array | 已固化的道痕列表 |
| `daoMarkSelected` | bool | 道痕是否已选 |
| `currentMapLayer/Index` | int | 当前地图节点位置 |
| `visitedNodeIds` | array | 已访问节点 ID 列表（用于禁止回退） |
| `deckCardIds` | array | 当前牌组卡牌 ID 列表（不包含战斗中临时状态） |

### 序列化规则

- 不存储手牌、抽牌堆、弃牌堆状态（这些只在战斗中有效，下次加载时从牌组重新洗牌）
- 不存储敌人状态（加载时从 `CurrentMapLayer/Index` 对应的地图节点重新初始化敌人）
- 不存储战斗回合计数、临时 buff（这些是战斗中瞬态数据）
- `CardRuntime` 序列化时只保留 `CardInfo.Id`，不保留 `CurrentCost` 等运行时计算结果

## 读档流程

```
Title → 检测 user://save_<CharacterId>.json 是否存在
  ├─ 否 → 无"继续游戏"按钮，只能"开始新游戏"
  └─ 是 → 显示"继续游戏"按钮
           → 点击 → 读取存档 → 恢复 GameManager 状态
           → 跳转 MapScene → 渲染已探索的地图节点
```

## 删档时机

| 时机 | 说明 |
|------|------|
| 角色死亡（PlayerHp ≤ 0） | 战斗失败后自动删除存档文件 |
| 通关（击败 Boss） | 通关结算后删除存档（当前角色生命结束） |
| 在标题界面点"开始新游戏" | 如果有旧存档，弹窗确认后覆盖 |

## 技术实现方案

### 依赖

- `System.Text.Json`（Godot .NET 内置，无需额外 NuGet 包）
- 文件路径：`user://save_<CharacterId>.json`（Godot 用户数据目录，跨平台）

### 核心方法签名

```csharp
// GameManager.cs
public void SaveGame();                          // 序列化当前状态到 JSON 文件
public bool LoadGame(string characterId);        // 从 JSON 文件恢复状态，失败返回 false
public void DeleteSave(string characterId);      // 删除存档文件
public static bool HasSave(string characterId);  // 检查某角色是否有存档
```

### 自动存档钩子

在 `GameManager._Notification(int what)` 中：
- `NOTIFICATION_WM_CLOSE_REQUEST`：调用 `SaveGame()` 后 `GetTree().Quit()`
