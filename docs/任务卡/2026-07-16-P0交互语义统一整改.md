## 背景

用户窗口实测确认三类问题仍存在：

1. CardReward 点击“跳过”后，胜利页卡牌奖励行被永久删除。
2. ACT1 地图后续层超出可视区，无法滚动或拖动查看；地图仍以右侧抽屉方式滑入。
3. Lingmai、Shop、Event 等节点页的“继续/返回地图”仍可能清空当前页、切换 `MapScene` 或露出无价值空白底页。

## UI/UX部任务

模型：`gpt-5.6-luna`
推理强度：`high`
职责：只冻结交互与更新 UI 文档，不修改玩法状态或核心代码。

### 冻结口径

- CardReward 的“跳过”只关闭当前 overlay，不消费奖励槽、不删除胜利页奖励行、不提交奖励、不修改永久牌组。
- 重复打开同一奖励槽必须显示同一候选 ID、同一顺序、同一已选进度。
- 地图是当前节点页上的 overlay。打开和关闭不销毁、隐藏或重建节点页。
- 地图内容支持滚轮横向滚动和鼠标左键拖拽；拖拽超过阈值后不得触发节点点击。
- 地图卷轴固定左侧起点，从左向右揭示；不允许整个面板从右侧滑入形成抽屉观感。
- 节点效果完成后，页面保留结果；已使用操作按钮灰显并不可再次触发。
- “继续/返回地图”只打开地图 overlay；只有点击合法下一节点才离开当前节点页。
- 无效入口必须显示明确错误和地图入口，不允许 TopBar + 空白内容占位。

### 输出

- 更新 `06-UI交互/01-MVP界面交互.md`。
- 给出地图拖拽阈值、滚轮步长、边界、动画时长和按钮灰显状态表。

## 开发部任务

模型：`gpt-5.6-luna`
推理强度：`high`
工作区：`洪荒之后-code/`

### A. CardReward

1. 删除 `BattleController.AddCardRewardRow()` 取消回调中的 `TrySkipBattleCardReward()` 和奖励行删除。
2. overlay 关闭后恢复奖励入口可用；只有达到 `ChoiceCount` 后才移除奖励行。
3. CardReward 打开时读取 GameManager 已领取候选索引，恢复多选进度和按钮禁用状态，不依赖每次 `Show()` 新建的本地空集合。
4. 同一 `RewardPlan` 重复打开不得重新调用 Resolver、随机流或重排候选。
5. 增加自检：连续 10 次打开/关闭候选 ID 和顺序一致；3 选 2 选一张后关闭重开，第一张保持已选，第二张完成后只发两张；关闭不改变牌组和奖励槽状态。

### B. 共享地图 overlay

1. 不再让 `MapController` 和 `BattleController` 分别维护两套地图动画/视口语义；抽取可复用地图 overlay 或共享视口组件。
2. 内容宽度由 `MapGraph` 层数、节点宽度和间距计算，不写死只容纳当前可视层。
3. 支持：
   - 鼠标滚轮映射为横向滚动；
   - 鼠标左键按住拖动；
   - 边界 clamp；
   - 拖拽阈值与节点点击隔离；
   - 打开时优先定位当前节点附近，同时允许查看前后层。
4. 展开动画：overlay 左边界固定，使用裁切宽度、遮罩或等价方式从左向右揭示；关闭反向收卷。禁止从右侧整体位移进入。
5. Battle 中地图只读；Battle 胜利、Lingmai/Shop/Event 结算后地图可交互。

### C. 节点页按钮统一

1. 审计 `BattleController`、`LingmaiController`、`ShopController`、`EventController`、`MapController`、`TopBar`、`CardRewardController` 中全部 `Button.Pressed`。
2. Lingmai/Shop/Event 成功或跳过后：
   - 提交一次 NodeResult；
   - 保留当前页面和结果；
   - 灰显所有会重复执行的操作；
   - “继续/返回地图”只打开共享地图 overlay；
   - 关闭 overlay 回到同一结果页。
3. 禁止继续/返回按钮直接 `GoToScene("res://scenes/Map/Map.tscn")`、清空内容区、销毁当前页或额外提交奖励/NodeResult。
4. 只有地图中点击合法下一节点时才执行目标节点预检、原子离场和目标场景进入。
5. 删除或改造所有无业务价值的空白底页路径；错误状态显示明确错误，不静默空白。

### 允许修改

- 不回退 C7-C11 的奖励防伪、事务和意图 Resolution 修复。
