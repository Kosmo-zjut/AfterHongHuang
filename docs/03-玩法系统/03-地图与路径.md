# 03-地图与路径

> 版本: 1.3.0 | 状态: 🚧 ACT1 Rev2 无交叉与混合层规则已冻结，生成器待实现 | 最后更新: 2026-07-13

> 当前已实现路径仍是静态 MVP 地图；Act 1 目标规格改为 `RunSeed` 驱动的分层 DAG。完整规则详见 [11-第一大关设计](./11-第一大关设计.md) §3。

## 1. 概述

玩家在 MapScene 中通过 **呼出式卷轴 overlay** 查看地图路线，选择下一个要前往的节点。每个节点代表一种遭遇类型，从起点（道韵）到终点（Boss）依次推进。

### 1.1 设计目标

- 横向分层：每层（Layer）是一个"纵列"，从左到右推进
- 层内分岔：同一层可以有多个可选的并行节点，玩家择其一进入
- 卷轴呼出：地图不占用主界面，通过 TopBar 按钮 toggle 呼出
- 只读共享：MapRenderer 静态工具类让 Battle 场景也能复用地地图绘制

---

## 2. 节点类型

| 类型 | 枚举值 | 图标 | 说明 |
|:--:|------|:--:|------|
| **道韵** | `MapNodeType.道韵` | ◆ | 起始节点。进入地图时底页直接展示 3 张道韵卡，必须固化才能解锁后续节点 |
| **战斗** | `MapNodeType.战斗` | ● | 普通战斗遭遇。击败后获得灵韵 + 卡牌奖励 |
| **灵脉** | `MapNodeType.灵脉` | ▣ | 灵脉节点。进入后提供休养生息、精进道行、疗愈道友和条件型法宝选项 |
| **Boss** | `MapNodeType.Boss` | ■ | 关底 Boss。击败后通过当前关卡。卡牌奖励全部为天品卡 |

### 2.1 MVP 阶段节点范围

> MVP 仅实现 4 层×5 节点（含 Boss），不含精英、商店、事件、宝箱等节点类型。

> ACT1 设计规格将路线扩展为 9 层：3 层弱怪、4 层混合节点、1 层 Boss 前置和 1 层 Boss。实现时必须以 `ActDefinition` 的层配置为输入，不把 4 层静态路线写死为长期规则。

## 3. 地图数据结构

### 3.1 分层数据：MapLayerData

```csharp
public class MapLayerData
{
    public MapNodeInfo[] Nodes;  // 本层包含的节点数组
}
```

每层是横向排列的一个"纵列"。从左到右依次为 Layer 0（道韵）→ Layer N（Boss）。

### 3.2 节点信息：MapNodeInfo

| 字段 | 类型 | 说明 |
|------|------|------|
| Id | string | 节点唯一标识 |
| Name | string | 显示名称（如"妖猴出没""灵脉节点"） |
| Type | MapNodeType | 节点类型枚举 |
| EnemyId | string | 战斗节点对应的敌人 ID（非战斗节点为 null） |
| Layer | int | 所属层级（0 = 道韵起点） |
| PositionIndex | int | 层内位置索引（同一层从上到下排列） |
| StableOrder | int | 生成器写入的稳定层内顺序；不可由 UI 坐标或字典顺序推断 |

### 3.3 层间连接：MapConnection

```csharp
public class MapConnection
{
    public int FromLayer;       // 来源层级
    public int FromIndex;       // 来源节点在 FromLayer 中的位置索引
    public int[] ToIndices;     // 目标节点在下一层中的位置索引数组
}
```

连接关系定义了"从某个节点出发，下一层可以去哪些节点"。

### 3.4 MVP 当前路线（历史静态实现）

```
Layer 0（道韵选择）      →  Layer 1（两条岔路）   →  Layer 2（灵脉汇合）  →  Layer 3（Boss）
     [道韵选择]          →    [妖猴出没]           →    [灵脉节点]        →    [关底·妖王]
                        ↘    [散修伏击]           ↗
```

> 数据定义在 `DataDefs.cs` 中硬编码，后续可迁移至 JSON 配置表。

> 上图只描述当前静态 MVP 的历史形态，不是 ACT1 Rev2 生成器规则。Rev2 的节点类型、稳定顺序和边集合必须由 `ActDefinition` / `MapGraphDefinition` 生成并通过 Validator。

### 3.5 Act 1 路线规格入口

Act 1 的随机路线必须满足以下约束：

- 同一 `RunSeed`、规则版本和 Act ID 生成相同节点类型、连接、遭遇、商店库存和事件分支。
- Layer 1~3 只能是弱怪；Layer 4~7 才允许强怪、灵脉、问号和商店；Layer 8 固定 Boss。
- 上述层窗口、允许类型、每层/每图配额和权重必须来自 `ActDefinition`；生成器不得用固定层号分支替代窗口数据。
- 每条有效路径恰好经过 3 场弱怪、至少 1 场强怪、至少 1 个灵脉，问号 0~1 个，商店 0~1 个；整张图至少生成 1 个、建议 2~3 个可达商店候选，且每个 Layer 3 节点至少存在一条“经过商店后到 Boss”的路径，禁止连续商店。
- 图生成后必须做起点正向可达 Boss、Boss 反向可达起点的双向检查；删除或重生成不在有效路径上的节点。
- 路线目标有效路径数为 8，允许范围 4~12；不能用隐藏默认边修复死路。

节点生成、连接修复和种子派生详见 [11-第一大关设计](./11-第一大关设计.md) §3。

### 3.6 ACT1 Rev2 图验证入口

开发部实现时，地图图模型必须至少暴露以下可验证结果：

| 验证结果 | 规则 |
|------|------|
| `StableOrderValid` | 每层节点的 `StableOrder` 唯一、连续，并随同 seed 固定；`LayerOrder` 与节点字段一致 |
| `NoCrossing` | 对任意相邻层边，来源顺序不反转目标顺序；共享端点不算交叉 |
| `ReachabilityValid` | 起点可到 Boss，Boss 可反向到起点，无死路、无孤立节点 |
| `PathQuotaValid` | 所有完整路径保留 3 弱怪、强怪/灵脉下限、问号/商店上限和 Boss 约束 |
| `MixedLayerValid` | ACT1 混合层每层至少 2 种类型、至少 1 个战斗节点，灵脉/商店/问号不独占整层 |
| `ServiceAdjacencyValid` | 同类非战斗节点不得沿边相邻，商店不得连续 |
| `ShopReachabilityValid` | 图级至少 1 个商店候选；每个 Layer 3 节点至少有经过商店到 Boss 的路径 |
| `GraphFingerprintValid` | 指纹包含规则版本、节点稳定顺序、类型和有序边集合；同 seed 指纹一致 |

任何验证失败都必须返回可追踪失败原因并重新生成/修复，不允许 UI 绕过 Validator，也不允许用默认节点或隐藏边兜底。

## 4. 节点可访问性

### 4.1 访问判定规则

| 条件 | 结果 |
|------|------|
| 道韵节点（Layer 0） | 始终可点击（回到道韵页面） |
| 道痕未固化 + 非道韵节点 | 灰色，不可点击，tooltip"需先固化道痕" |
| 道痕已固化 + 节点从当前层可达 | 可点击进入战斗/灵脉 |
| 已访问过的节点 | 灰色，不可重复点击 |

### 4.2 可达性算法

```
IsNodeAccessible(layer, index):
  1. 如果 layer == 0 → true（道韵始终可访问）
  2. 如果道痕未固化 → false
  3. 查找 MapConnections 中 from=当前层、fromIndex=当前位置的条目
  4. 如果目标 layer/index 在 ToIndices 中 → true
  5. 否则 → false
```

### 4.3 已访问节点追踪

`GameManager.VisitedNodeIds`（`HashSet<string>`）记录所有已访问节点的 ID。战斗结束后自动将当前节点标记为已访问。

> 存档系统基于此实现节点级存档（详见 `05-技术设计/03-存档系统.md`）。

## 5. 交互设计

### 5.1 呼出式卷轴

- **入口**：TopBar 右侧「🗺 地图」按钮
- **动画**：卷轴从屏幕右侧滑入（x=1920 w=0 → x=320 w=1600），350ms ease-in-out
- **关闭**：再点地图按钮（toggle）或点卷轴右上角「收卷」
- **底层**：呼出时底页内容变暗，但不影响 TopBar 交互

### 5.2 节点点击

- 可访问节点 → 高亮悬停，点击进入对应场景（战斗/灵脉/道韵）
- 不可访问节点 → 灰色，点击无反应，悬停显示 tooltip

### 5.3 灵脉节点交互

灵脉节点不是战斗节点。玩家从地图点击可访问灵脉后，进入灵脉节点界面或 overlay，选择一项可用行动后结算。

| 选项 | 显示规则 | 点击结果 | 结算后 |
|------|------|------|------|
| **休养生息** | 始终显示；满血时禁用 | 回复 `floor(最大生命 × 30%)`，不超过最大生命 | 标记该灵脉节点已访问，返回地图 |
| **精进道行** | 始终显示；无可升级卡时禁用 | 打开当前牌组可升级卡列表，选择 1 张后永久替换为升级版 | 升级完成后标记该灵脉节点已访问，返回地图 |
| **疗愈道友** | MVP 单人模式下可隐藏；若显示则禁用 | 无队友时不能点击，不消耗灵脉 | 不改变地图状态 |
| **法宝触发选项** | 仅拥有对应法宝后显示或启用 | 按法宝定义结算，如下一场战斗获得 1 点斗劲、获得一件随机法宝等 | 若结算成功，标记该灵脉节点已访问，返回地图 |

灵脉结算失败或取消选择时，不应标记节点已访问。例如进入"精进道行"的选卡列表后取消，应该回到灵脉选项界面，而不是消耗灵脉。

### 5.4 战斗中地图

战斗场景同样支持呼出式地图 overlay（只读），通过 MapRenderer 静态工具类绘制与 MapScene 一致的地图视图。战斗中地图不可点击节点，仅用于查看路线。

### 5.5 道韵节点特殊处理

道韵节点（Layer 0）点击后从地图卷轴切回底页，底页直接渲染 3 张道韵卡。若已固化，则展示"道痕已固化"状态（选中卡高亮+✓，其余变灰）。

## 7. MVP 范围与限制

| 包含 | 不包含 |
|------|------|
| ✅ 4 层横向静态路线 | ❌ 多分支随机生成 |
| ✅ 道韵/战斗/灵脉/Boss 四种节点 | ❌ 精英/商店/事件/宝箱 |
| ✅ 呼出式卷轴 + 动画 | ❌ 地图节点缩略图/图标美术 |
| ✅ 节点访问判定 + 已访问追踪 | ❌ 路线预览/路径规划 |
| ✅ 战斗中只读地图 | ❌ 地图生成算法 |
| ✅ 灵脉节点最小交互（休养生息 / 精进道行 / 疗愈道友禁用或隐藏 / 法宝选项预留） | ❌ 完整队友系统 / 完整法宝系统 / 灵脉随机事件 |
| ✅ Act 1 Rev2 无交叉路线规则、混合层配额和图验证契约已定义 | ❌ Act 1 可复现 DAG 生成器尚未实现 |
