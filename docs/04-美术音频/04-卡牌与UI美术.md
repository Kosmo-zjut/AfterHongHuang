## 2. 通用交付规范

### 2.1 目录建议

美术源文件和导出文件建议放在 `洪荒之后-art/assets/` 下，按用途分组：

| 目录 | 用途 |
|------|------|
| `assets/source/` | PSD/KRA/CLIP 等可编辑源文件 |
| `assets/backgrounds/title/` | 标题和角色选择背景 |
| `assets/backgrounds/battle/` | 战斗场景背景 |
| `assets/characters/wuzhu/` | 巫祝立绘、头像、战斗状态 |
| `assets/enemies/mountain_monkey/` | 山野妖猴立绘、头像、状态 |
| `assets/ui/cards/` | 卡牌框、卡牌底纹、费用珠、类型图标 |
| `assets/ui/buttons/` | 通用按钮九宫格和状态图 |
| `assets/ui/topbar/` | TopBar 底板、图标、状态底纹 |
| `assets/ui/map_scroll/` | 地图卷轴底板、节点、连线装饰 |
| `assets/ui/dialogs/` | 胜利弹窗、奖励 overlay、遮罩 |
| `assets/placeholders/` | MVP 临时占位素材 |

### 2.2 命名规则

统一使用小写英文、数字和下划线，避免中文文件名进入引擎导入链。

```
{category}_{subject}_{variant}_{state}.{ext}
```

示例：

- `bg_title_buzhou_ruins_v01.png`
- `char_wuzhu_battle_idle.png`
- `enemy_mountain_monkey_idle.png`
- `ui_card_frame_huang_normal.png`
- `ui_button_primary_hover.9.png`
- `ui_dialog_victory_base.9.png`

状态后缀建议：

| 后缀 | 含义 |
|------|------|
| `normal` | 默认 |
| `hover` | 悬停 |
| `pressed` | 按下 |
| `disabled` | 禁用 |
| `selected` | 选中 |
| `locked` | 锁定 |
| `placeholder` | 占位 |

### 2.3 格式规范

| 类型 | 推荐格式 | 说明 |
|------|------|------|
| 大背景 | PNG/WebP | 首版优先 PNG，若体积过大再导出 WebP |
| 角色/敌人立绘 | PNG 透明背景 | 保留 alpha，方便战斗层级叠放 |
| UI 九宫格 | PNG 透明背景 | 文件名可加 `.9` 表示需在 Godot 设置 9-slice |
| 图标 | PNG 或 SVG | 笔触类图标优先 PNG；几何图标可 SVG |
| 源文件 | PSD/KRA/CLIP | 必须保留图层，便于改色、换文本框和拆分状态 |

### 2.4 色彩与可读性

| 用途 | 色值 | 备注 |
|------|------|------|
| UI 深棕底 | `#2B1B0E` | 面板、按钮、TopBar 主底 |
| 米白文字 | `#D4C5A9` | 主文字 |
| 伤害/HP 赤红 | `#C83A2A` | 伤害数字、HP |
| 护体/灵力青蓝 | `#4A90D9` | 护体条、灵力珠 |
| 古金高亮 | `#D4A83A` | 选中边框、主按钮、胜利 |
| 道痕紫韵 | `#7B68EE` | 道痕卡、地图道韵节点 |
| 灰禁用 | `#5C5C5C` | 锁定、不可点击 |

所有文本承载区域需预留暗底或半透明墨迹底，保证 1280 x 720 下可读。背景图不要在按钮和文字区放高对比细节。

### 4.2 MVP初始卡牌插画方向

| 卡牌 | 类型 | 插画方向 | MVP处理 |
|------|------|------|------|
| 拳袭 | 斗击 | 暗红拳风或骨枪短击，近景冲击感 | P1，可先用类型底纹占位 |

P0 阶段卡牌可不做单卡插画，但卡框、费用、类型、文本区必须统一。等奖赏卡池确定后，再补完整单卡插画。

## 5. 复用、修改与扩展判断

| 维度 | 判断 | 说明 |
|------|------|------|
| 复用性 | 可满足 MVP 后续迭代 | 按 `ui_button_*`、`ui_card_frame_*`、`ui_dialog_*` 做通用状态图，Map/Battle 可共用 TopBar 和按钮 |
| 修改性 | 可控 | 源文件分层，背景、边框、纹理、状态高亮拆开，后续改色或改尺寸不必重画整套 |
| 扩展性 | 足够支撑 v0.0.2-v0.0.3 | 卡牌稀有度、类型图标、地图节点和弹窗均预留命名槽位；未来加商店/事件/精英节点可按同类规则扩展 |
| 风险 | 卡牌插画量可能扩张 | MVP 先交卡框和类型底纹，单卡插画延后到正式奖赏卡池稳定后再批量绘制 |
| 风险 | UI 九宫格导入需代码侧配合 | 交付时需同时给出切片边距，Godot Theme/TextureRect 导入要统一配置 |
| 风险 | 标题/战斗背景可能抢 UI 可读性 | 背景绘制需遵守顶部 110px、底部 300px、按钮区域低细节安全区 |

## 10. ACT1地图节点图标与状态

### 10.1 共用规格

| 项目 | 规格 |
|------|------|
| 运行尺寸 | 96 x 96 px；Boss 节点可显示到 112 x 112 px |
| 源文件尺寸 | 192 x 192 px，保留透明安全边界 |
| 格式 | PNG 透明；几何占位也可交 SVG，但正式毛笔纹理优先 PNG |
| 组合方式 | 节点底图、状态叠层、hover/selected 光晕分开，不为 6 x 5 状态组合导出 30 张重复图 |
| 安全边界 | 主体占画布 68%~82%；四角留 12px 以上透明边；连线不得穿过主体中心 |
| UI原则 | 形状、内部符号、纹理三重编码；颜色只作为快速提示，不作为唯一状态依据 |

### 10.2 节点类型

| 类型 | 文件名 | 形状和内部符号 | 主辅色 | 识别要求 | 优先级 |
|------|------|------|------|------|:--:|
| 弱怪 | `ui_map_node_weak_act1.png` | 圆石轮廓 + 单道爪痕；外圈一处缺口 | 暗红 `#8B3A32` + 碎石灰 `#62584E` | 缩到 48px 仍能看出“圆石/单爪” | P0 |
| 强怪 | `ui_map_node_strong_act1.png` | 竖向断戈 + 双层肩甲形外框 | 锈红 `#743A2D` + 旧铜 `#8B6A36` | 断戈和双缺口必须与弱怪单爪区分 | P0 |
| 灵脉 | `ui_map_node_lingmai_act1.png` | 方形石槽 + 向上分叉的地脉线 | 青绿 `#497274` + 米白 `#D4C9B8` | 不使用圆点，保留方槽和分叉线 | P0 |
| 商店 | `ui_map_node_shop_act1.png` | 收紧布包 + 小秤/价格签 | 旧铜 `#8B6A36` + 墨褐 `#3B2517` | 布包轮廓和价格签作为识别点 | P0 |

### 10.3 状态叠层

状态图标独立导出，运行时叠在节点底图上。状态叠层不改节点类型本身，便于同一套节点复用到后续 ACT。

| 状态 | 文件名 | 非颜色识别 | 视觉处理 | 优先级 |
|------|------|------|------|:--:|
| Locked | `ui_map_state_locked.png` | 斜向断印线 + 四角短刻痕 | 去饱和、加纸纹和断裂封印；不使用完整锁头替代节点 | P0 |
| Available | `ui_map_state_available.png` | 开口圆环 + 底部一点墨印 | 节点主体正常，边缘留可点击呼吸空间 | P0 |
| Current | `ui_map_state_current.png` | 闭合粗环 + 指向性朱笔箭头 | 叠一圈粗笔迹和小旗标；不只使用金色描边 | P0 |
| Completed | `ui_map_state_completed.png` | 印章式对勾/横断封条 | 加半透明旧印，不遮住类型内部符号 | P0 |
| Skipped | `ui_map_state_skipped.png` | 破环 + 向下断笔 | 灰墨和低透明度，但保留节点形状，不直接隐藏 | P0 |

建议状态层同样使用 192 x 192 源、96 x 96 导出。hover/selected 光晕属于 UI 动态效果，不提前绘制进五种状态图，避免形成状态组合爆炸。

### 10.4 地图占位方案

先用深棕圆/方/签形几何底，加米白线性内部符号和状态叠层；节点间连线使用细墨线。禁止使用同一个红色圆点代表弱怪、强怪和 Boss，也禁止把锁定节点直接删除。

## 12. ACT1命名、像素和Godot导入

### 12.1 文件命名

```text
{category}_{subject}_{variant}_{state}.{ext}
```

ACT1 示例：

- `bg_battle_buzhou_outer_act1_v01.png`
- `enemy_mountain_monkey_battle_idle.png`
- `enemy_xiangliu_skeleton_entrance.png`
- `ui_map_node_weak_act1.png`
- `ui_map_state_locked.png`
- `card_art_wx_a1_boss_001.png`
- `ui_card_frame_tian_normal.png`

不使用中文文件名、空格、emoji 或同名覆盖。版本变更用 `_v02`，状态变更用 `_hover` / `_selected` / `_disabled`，不要靠文件夹覆盖旧版本。

### 12.2 格式和像素规则

| 资产 | 源/导出 | 格式 | 规则 |
|------|------|------|------|
| 背景 | 3840 x 2160 / 1920 x 1080 | PNG 初版；可审查后 WebP | sRGB；保留整画布，不裁掉 UI 安全区 |
| 普通敌人 | 1200 x 1200 / 900 x 1000 | PNG RGBA | 透明边界固定，基线统一，避免自动裁剪改变锚点 |
| Boss立绘 | 1600 x 1400 / 1200 x 1200 | PNG RGBA | 九首和水纹不能贴边；入口图与战斗图共享图层 |
| 地图图标 | 192 x 192 / 96 x 96 | PNG RGBA 或 SVG占位 | 图标不嵌文字说明；状态另导出叠层 |
| 卡面插画 | 1024 x 768 / 512 x 384 | PNG RGBA/RGB | 不绘制名称、费用、效果数字；保留四边安全边距 |
| 九宫格面板 | 按设计稿 2x / 运行尺寸 | PNG RGBA | 四角不变形区域清楚，不能把纹理接缝放在文字区 |

### 12.3 Godot导入注意事项

- 透明立绘和图标使用 RGBA，`Repeat` 关闭；保留透明边界，不使用会改变锚点的自动裁剪。
- 水墨背景和厚涂立绘启用纹理过滤；UI 图标不生成 mipmap，避免小尺寸文字感纹理发糊。正式项目若调整过滤策略，需要按 1280 x 720 窗口重新检查。
- 九宫格面板使用 `NinePatchRect`，四角边距在交付说明中填写；不把完整面板拉伸成普通 `TextureRect`。
- 背景使用 `TextureRect` 覆盖设计分辨率，透明叠层使用独立纹理；不要把动态水纹或余烬烘焙进唯一背景图。
- SVG 只作为几何占位或线性图标方案；正式毛笔纹理、纸张、骨骼和水墨边缘优先 PNG。
- 所有导出图保持 sRGB 和完整画布尺寸，导入后检查 alpha 边缘是否出现黑边、白边或 premultiply 光晕。
- Godot 导入配置只由开发/资源接入人员在工程侧验证；本任务不修改 `project.godot`、场景或代码。

## 13. ACT1生产优先级与最小批次

### 13.1 P0/P1/P2

| 优先级 | 生产内容 | 目标 |
|:--:|------|------|
| P0 | 战斗背景；6类地图节点底图；5种状态叠层；三弱怪 idle；相柳战斗 idle/avatar；天品卡框占位 | 让 ACT1 第一条可玩路线能替换代码色块，玩家能读懂节点和敌人层级 |
| P1 | 三强怪 idle；七敌人 hit/death 最小帧；商店页；两种事件页；Boss 入口页；三张 Boss 卡插画 | 支撑 ACT1 内容完整度和 Boss 奖励视觉闭环 |
| P2 | 水雾/余烬/符墨叠层；intent_pose；完整受击/死亡动画；双敌组合构图；其余五个 Boss 视觉 | 在接口稳定和首轮平衡通过后提升表现，不阻塞节点契约验收 |

### 13.2 最小生产批次

建议第一批交付 `ACT1-ART-CORE`：

1. `bg_battle_buzhou_outer_act1_v01.png` 和占位变体。
2. 六类地图节点底图 + 五种状态叠层。
3. `act1_weak_monkey`、`act1_weak_stone`、`act1_weak_scavenger` 三个 `battle_idle` 与头像。
4. `enemy_xiangliu_skeleton_battle_idle.png`、`enemy_xiangliu_skeleton_avatar.png`。
5. `ui_card_frame_tian_normal.png` 和三张卡面插画占位图。

这批不包含商店、事件、强敌完整动画和动态特效，便于在开发部 Phase A/节点页面接口变动时低成本返工。

### 13.3 复用项

- 复用现有 `ui_card_frame_huang_*` 的纸张、边框和文本区结构，增加天品边框变体，不重新设计卡面布局。
- 复用通用按钮四态、TopBar、地图卷轴和弹窗九宫格；ACT1 只新增节点类型、商店/事件/Boss 的内容图。
- 相柳入口和相柳战斗立绘共用骨骼、水纹和头颈图层；只改变裁切、姿态和背景。
- 事件两页共用一个事件面板、按钮、选项槽和遮罩，仅替换背景、徽记和主图。
- 地图类型底图与状态叠层分离，后续 ACT2/ACT3 可以复用状态图，不复制状态组合。

### 13.4 风险和暂不决策项

| 风险/事项 | 判断 | 下一步 |
