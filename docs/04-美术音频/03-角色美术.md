## 1. 通用敌人生产规范

### 1.1 画布和透明边界

| 类型 | 源文件 | 游戏导出 | 透明安全边界 |
|------|------|------|------|
| 普通敌人战斗立绘 | 1200 x 1200 | 900 x 1000 PNG | 头顶至少 110px 留给意图；脚底至少 60px 留给状态条；左右至少 60px 留给受击抖动 |
| 普通敌人头像 | 512 x 512 | 192 x 192 PNG | 主体占 70%~82%，保留轮廓，不把眼睛贴边 |
| 相柳入口/战斗立绘 | 1600 x 1400 | 1200 x 1200 PNG | 头颈和水纹不触碰画布四边；九首轮廓可完整读出但不拆目标 |

统一以脚底或盘绕最低点作为基线。透明画布内不要裁掉发丝、烟、水、碎石等受击时会外扩的部分。导出文件只保留必要 alpha，不使用黑底模拟透明。

### 1.2 状态帧最小集

每个敌人先交独立 PNG，避免在玩法接口未稳定时绑定 SpriteFrames 或动画长度：

| 状态 | 最小帧 | 视觉要求 |
|------|:--:|------|
| `idle` | 1 | 站位、轮廓、材质和主题色必须独立可识别 |
| `hit` | 2 | 接触帧 + 回正帧；保留本体轮廓，不能只闪白 |
| `death` | 3 | 失衡/裂开、倒下/崩散、残留物；每帧都能作为静态图展示 |
| `intent_pose` | 1 可复用 idle 变体 | 只在需要时制作，优先通过姿势变化表达行动，不依赖新特效 |

建议动画采样：idle 12 fps，hit 10~12 fps，death 8~10 fps。若代码最终只支持静态立绘，保留 `hit_01` 和 `death_01` 作为替换图即可，不伪造未接入的动画。

### 1.3 战斗 UI 安全边界

战斗中敌人位于画面右侧，推荐把立绘可见主体压在 `x=1220~1840, y=160~760` 对应的角色区内。以下内容不能侵入：

- `y=0~110` 的 TopBar。
- 敌人头顶意图区，约 `y=120~260`；高角、武器尖端和飘散特效要留出空隙。
- 立绘脚下 HP/护体和状态图标区，约 `y=730~850`。
- 底部手牌区 `y>=750`，大型尾巴、石块、潮水需要提前裁切或降低透明度。

受击/死亡外扩优先向角色区内部或中央低信息区扩展，不得压住 TopBar、意图、HP 和手牌。颜色只用于加速识别，轮廓、材质和动作必须独立成立。

### 1.4 命名规则

```text
enemy_{subject}_{asset}_{state}.{ext}
```

示例：

- `enemy_mountain_monkey_battle_idle.png`
- `enemy_mountain_monkey_battle_hit_01.png`
- `enemy_mountain_monkey_battle_death_02.png`
- `enemy_xiangliu_skeleton_entrance.png`
- `enemy_xiangliu_skeleton_avatar.png`

## 3. 七个敌人的可生产 brief

### 3.1 山野妖猴

| 项目 | Brief |
|------|------|
| 轮廓/体型 | 瘦长、前倾、长臂略过膝；脚掌外翻，重心低，尾部只做短而乱的轮廓，避免与山魈王混淆。头小、肩窄、手指长，保持“随时窜走”的不稳定三角形。 |
| 材质 | 粗毛、尘土、湿石粉；肩背可粘少量碎石，但不能像碎石山精一样整块岩化。 |
| 主辅色 | 主色深灰褐 `#3B302A`；辅色旧黄 `#B7A64A` 用于眼睛和灵猴闪避提示；尘白 `#9B8D7A` 用于毛尖和擦伤。 |
| 识别点 | 弯曲长臂、偏头、旧黄眼光、肩背碎石；静态缩小到 96px 图标时仍能读出“猴形+长臂”。 |
| 意图动作 | `嬉斗`：蹲伏、双手拍地、肩后出现两道错开的残影；`打7/打13`：一手撑地，另一手向前甩臂，伤害数字承担 7/13 差异，资产不做两套敌人。 |
| 受击/死亡最小帧 | hit 2 帧：肩背碎石飞散、身体短缩后回弹；death 3 帧：失衡后跪地、蜷缩成尘灰、只留一对暗黄眼光熄灭。 |
| UI安全边界 | 头顶和长臂不能伸进 `y=120~260` 意图区；尾部和尘土不能进入 `y>=750` 手牌区；hit 外扩向左上，不压右侧 HP 条。 |

### 3.2 碎石山精

| 项目 | Brief |
|------|------|
| 轮廓/体型 | 矮胖的岩块聚合体，头部像一块向前突出的楔石，肩宽大于身高，双脚是两块不对称巨石；轮廓要稳、重、近似倒三角。 |
| 材质 | 层叠碎石、砂砾、湿泥；接缝中有少量青色灵气，不画成发光水晶或完整石像。 |
| 主辅色 | 碎石灰 `#5C5A54`；土黄 `#92724A` 做泥土和旧矿痕；裂隙青 `#497274` 只放在护体裂纹。 |
| 识别点 | 单侧高肩、头部楔石、胸口三道裂纹；小图标用“矮岩块+裂纹”识别，不用人物脸。 |
| 意图动作 | `伏石`：身体压低、双臂抱胸，护体石层闭合；`掷石`：右肩脱落一块石弹向前；`裂地/碎岩`：双臂抬高后砸地，脚下出现短裂线。 |
| 受击/死亡最小帧 | hit 2 帧：受击侧掉落两块小石、裂纹短亮；death 3 帧：肩块崩落、主体塌成三堆石块、裂隙青光熄灭。 |
| UI安全边界 | 楔石头顶不超过意图区下沿；掷石的飞石做独立小特效，不把敌人本体伸进中央日志区；脚下碎石不能遮住护体条。 |

### 3.3 掠灵散修

| 项目 | Brief |
|------|------|
| 轮廓/体型 | 消瘦中等身材，旧道袍下摆不齐，身体略侧，像一直在观察逃路；一只袖口明显比另一只长，形成不对称识别。 |
| 材质 | 湿旧布、粗麻绳、烧焦符纸、磨损木杖或短符刃；不使用金属铠甲，和不周残兵拉开层级。 |
| 主辅色 | 墨青灰 `#2E3B3B`；符纸米白 `#D4C9B8`；暗朱 `#8B3A32` 只用于符火和袖口印记。 |
| 识别点 | 一长一短的袖口、胸前收灵小囊、飘在身边的两张破符；头像必须保留兜帽/侧脸和符纸。 |
| 意图动作 | `观望`：手持符纸遮面，六边形护体薄膜展开；`符火`：抬手夹符，暗朱火线沿前臂走；`游走`：身体横移、衣摆拖出一条墨线；`诈退`：披风向后掀开，下一击从侧面回身。 |
| 受击/死亡最小帧 | hit 2 帧：符纸被打散、肩膀向后折；death 3 帧：兜帽落地、衣袍瘪下、符纸被暗朱火星烧成空白。 |
| UI安全边界 | 飘符不得进入敌人意图区；横移动作只在自身右侧安全区内完成；符火亮点不超过局部，不遮住 HP 数字。 |

### 3.4 不周残兵

| 项目 | Brief |
|------|------|
| 轮廓/体型 | 直立厚重，残甲使肩线硬，长戈形成一条可读的竖斜线；身体部分中空，露出干枯骨和旧布，不做完整军阵。 |
| 材质 | 旧铁、氧化铜、干骨、破旗布；甲片边缘钝裂，表面有水锈和土层。 |
| 主辅色 | 旧铁黑 `#292A29`；锈红 `#743A2D`；旧铜 `#8B6A36`；骨白只做少量关节。 |
| 识别点 | 断裂长戈、半片胸甲、肩后短残旗；“兵”的直立和“残”的缺口必须一眼成立。 |
| 意图动作 | `结阵`：戈尖落地、肩甲向内收，残旗在身后展开；`长戈`：枪线从右上向左下劈落；`残军合击`：短暂出现两道透明戈影，不新增敌人；`回阵`：戈柄横置、甲片重新扣合。 |
| 受击/死亡最小帧 | hit 2 帧：甲片震落锈屑、残旗后摆；death 3 帧：单膝跪地、长戈脱手、甲胄内部塌为空壳。 |
| UI安全边界 | 长戈尖端必须收在 `y=160~700` 内，不刺入意图或 TopBar；残旗透明度低于主体，不遮挡 HP/护体文本；死亡倒向画面右侧，避免压中央日志。 |

### 3.5 符阵散修

| 项目 | Brief |
|------|------|
| 轮廓/体型 | 细长、站姿稳定，身体被三层不完整方阵纸符包住；人物本体比符阵暗，外轮廓靠纸符的方形节奏识别。 |
| 材质 | 旧纸、朱砂、黑墨、细铜线和少量裂玉片；符纸边缘卷曲、被水浸，但不做整屏光阵。 |
| 主辅色 | 墨紫 `#3E3448`；符纸米白 `#D4C9B8`；朱砂 `#A6402B`；裂玉青 `#497274` 仅用于护体残光。 |
| 识别点 | 三层错位方阵、额前单张竖符、朱砂连线；小图标使用“方阵+竖符”，不用人脸。 |
| 意图动作 | `布符`：三张符纸插入三角位置，方阵闭合一瞬；`火符`：额前竖符变赤；`引爆`：方阵向内折叠后向外炸开；`续符`：重新补上一张破纸。 |
| 受击/死亡最小帧 | hit 2 帧：一角方阵缺纸、紫墨线断开；death 3 帧：纸符同时落下、主体被墨灰吞没、地面只留一圈未闭合朱砂线。 |
| UI安全边界 | 方阵最大外框不得越过角色区左右边缘；阵顶不能进入意图区；纸符碎片向下落但不能覆盖护体条和手牌。 |

### 3.6 山魈王

| 项目 | Brief |
|------|------|
| 轮廓/体型 | 宽肩、长臂、背部隆起，头部前探；体型明显大于前三个敌人，但仍保持单体立绘可完整放入右侧。头顶可有破损石冠/骨角轮廓，作为“王”的单一识别点。 |
| 材质 | 粗硬黑毛、岩土、苔藓、磨损骨冠；毛发不能画成干净兽皮，需有雨水和尘土压结。 |
| 主辅色 | 炭黑 `#2F2A28`；苔绿 `#4A5A45`；土褐 `#76503A`；眼部暗金 `#A68A3C`。 |
| 识别点 | 宽肩长臂、破损石冠、苔藓肩背、直视玩家的暗金眼；狂势只改眼光和姿态，不换整套颜色。 |
| 意图动作 | `震吼/狂啸`：胸腔打开、头抬高、暗金眼光扩张；`裂地`：双拳落地、肩背前压；`撕咬`：单侧头部前冲，保持身体不出安全区；`喘息`：低头、手撑膝，护体苔光聚拢。 |
| 受击/死亡最小帧 | hit 2 帧：毛发被冲开、石冠掉一小块；death 3 帧：跪地撑住、石冠和苔块掉落、身体向后沉入尘雾。 |
| UI安全边界 | 头顶不超过意图区下沿；长臂和拳击动作不能遮 HP/护体；尘雾只在脚下和身后，不能覆盖底部手牌。 |

### 3.7 相柳之骸

| 项目 | Brief |
|------|------|
| 轮廓/体型 | 盘绕的巨大蛇身骨架，九条头颈形成高低错落的扇形轮廓；MVP 是单体目标，九首只作为视觉和意图来源，不拆九个可选目标。 |
| 材质 | 浸在浊水中的骨骼、湿黑脊椎、剥落鳞片、骨缝中的青黑水光；骨骼不能洁白，需有泥和水锈。 |
| 主辅色 | 浊青黑 `#21474A`；骨白 `#D4C9B8`；暗红 `#8B2500` 用于阶段危险裂光；旧金 `#8B6A36` 仅用于 Boss 标记或残旧骨饰。 |
| 识别点 | 九首骨颈、盘绕骨架、肋骨间流动的浊水；即使缩为 96px Boss 图标，也必须先读出“九首+骨圈”。 |
| 意图动作 | `守巢`：骨身收成环，首颈向内护住水心；`三首噬/九首齐噬`：三或九条颈骨同时向前，但攻击目标仍是单体；`浊水/浊水反噬`：一首抬高吐出低矮水幕；`回潮护身`：盘绕骨圈闭合，水光上升。 |
| 受击/死亡最小帧 | hit 2 帧：受击处骨片震落、浊水向外喷；death 3 帧：骨圈断裂、九首依次低垂、残骨沉入一滩无光浊水。 |
| UI安全边界 | 最高头颈必须避开意图区，最低骨圈不能压 HP/护体；水幕不进入手牌区；死亡扩散向背景和下方低信息区，不遮 Boss 奖励弹窗。 |

## 4. 占位与复用策略

### 最小生产批次

- P0：三个弱怪 `battle_idle`、相柳之骸 `battle_idle` 与 `avatar`；这些是第一条 ACT1 路线和 Boss 入口的最小替换集合。
- P1：三个强怪 `battle_idle`、七个敌人的 `hit_01`、相柳入口立绘、三个弱怪和 Boss 的 `death_01`。
- P2：完整 hit/death 帧、intent_pose、战斗特效、双敌组合构图、其余五个 Boss 设计池。

所有敌人先用同一套透明画布、基线和命名规则，后续新增敌人只需要替换主体图，不改 UI 锚点和状态条位置。敌人头像可从战斗立绘裁切，但必须重新检查小尺寸轮廓，不能直接缩小导致五官和骨骼糊成一团。

### 占位方案

占位图使用单色剪影 + 一个材质识别点：猴为长臂和黄眼，山精为楔石和裂纹，散修为竖符，残兵为断戈，符阵散修为方阵，山魈王为石冠，相柳为九首骨圈。占位不使用 emoji，不用同一张紫色方块替代全部敌人。
