## 1. 视觉生产基线

### 1.1 可执行方向

- **世界感**：不周天崩后的潮湿废墟。断山、浊水、碎骨、旧符与余烬共同构成生存现场，而非壮丽仙境或整洁古风建筑。
- **画法**：水墨厚涂，轮廓保留粗粝毛笔断线；大块明暗优先于细密纹理。材质用笔触区分：湿石钝重、旧纸干涩、骨骼哑白、余烬内亮。
- **色彩**：大面积使用废墟墨黑 `#211B18`、碎石灰褐 `#62584E`、浊水青黑 `#21474A`；旧铜暗金 `#8B6A36`、余烬暗红 `#8B2500`、符纸米白 `#D4C9B8` 仅作为功能焦点。巫祝可额外使用火焰橙 `#E85D04` 与暗金 `#A68A3C`。
- **光影**：环境光低、方向明确。巫祝的暖光来自皮下火种；敌人和场景以冷湿暗面承托，避免均匀打光和霓虹边缘光。

### 1.2 构图与镜头规则

| 场景 | 镜头与构图 | UI 安全要求 |
|------|------|------|
| 标题页 | 16:9 远景，不周断山与暗红天际建立世界尺度，中央偏下保留按钮空域 | 不烘焙标题、菜单或版本号；文字区保持低对比 |
| 战斗背景 | 16:9 平视中远景，左右角色对峙，断山/水沟形成斜向视线 | TopBar `y=0~110`、手牌 `y=750~1080`、中央反馈区 `x=720~1200,y=160~720` 保持低细节 |
| 战斗立绘 | 透明背景，中近景 3/4 视角；巫祝面向右、敌人面向左，脚部基线稳定 | 头顶为意图/HP 留空，主体和大动作不侵入手牌与中央反馈区 |
| 地图卷轴 | 固定左侧起点，由左向右展开的横向路径；纸面适合拖拽阅读 | 不按右侧抽屉构图；节点、连线和状态均留出可点击空间 |
| 卡牌与图标 | 小尺寸先读轮廓，再读材质，最后读点缀色 | 不在插画内生成名称、数值、费用、说明或状态文字 |

### 1.3 明确禁用项

- 禁止日系萌系、性感化巫祝、干净仙侠时装、明亮宫殿、赛博霓虹、欧美写实照片感。
- 禁止大面积纯蓝水、纯橙火、满屏粒子、平滑渐变背景、过密噪点或高光铺满主体。
- 禁止图内文字、伪汉字、UI 数值、卡牌名称、按钮标签、Logo、签名和水印。
- 禁止把多个功能状态烘焙进一张资源；节点类型、节点状态、按钮状态和动态特效必须可拆分。
- 禁止为相柳之骸绘制九个独立可选目标或九个 HP 信息区；九首仅是单体 Boss 的轮廓与意图来源。

### 1.4 神兽与妖兽方向

- 神兽/妖兽优先以“大轮廓 + 标志性器官 + 云气或灵气环绕”读取；角、鬃毛、鳞甲、尾部、四肢比例和飘带式云纹服务于成熟东方奇幻剪影，不按现实动物解剖细刻。
- 保持二维动画化规则：粗深色轮廓、平面主色块、每种材质 2~3 阶明暗、正常多色与少量纸纹；不画写实毛发、逼真生物材质或微观纹理。
- 气质为“洪荒遗种”的庄严与异质感，避免恐怖写实、日系萌宠和直接复刻任何参考兽形、纹样、配色或构图。

### 1.5 多分辨率构图与源文件规格

- 清单中的 `1920×1080` 表示 16:9 的逻辑构图与运行时安全区，不是全屏位图母版的上限。标题页、角色选择页和战斗背景的批准源图最低保留 `3840×2160` 母版；运行时导出尺寸和压缩策略由接入阶段另行确认。
- 全屏场景必须分离背景延展、主要人物/前景和 UI 安全区。标题、菜单、版本号、数值、按钮和规则说明由 Godot UI 叠加，禁止烘焙进背景。
- 角色、异兽、法宝和前景物按其最大显示尺寸保留独立高分辨率 RGBA 源图；不得把可交互 UI、文字或关键轮廓压成单一低分辨率背景。
- 所有 16:9 核心构图均保留左右延展区：超宽屏仅展示更多环境、云气或遗迹，不得移动标题/菜单安全区、战斗左右站位、底部手牌或焦点面板的核心关系。
- 卡框、按钮、图标和边角装饰遵循可缩放控件规格，交付九宫格边距、锚点和独立状态层。该规则不要求把视觉基准候选图全部重绘为 4K；候选图用于定调，只有批准进入生产的资源才按母版规格交付。

## 3. 文件边界、命名与版本

本节是后续生产目录约定，不在本任务创建任何目录或文件。

| 区域 | 建议路径 | 允许内容 | 不允许内容 |
|------|------|------|------|

| 批准图/源文件 | `洪荒之后-art/assets/source/` | PSD/KRA/CLIP 分层母版、蒙版、修图层、批准记录 | 不保存未审核候选的最终替代品 |

统一命名：`{domain}_{subject}_{variant}_{state}_v##.{ext}`。全小写英文、数字、下划线；不使用空格、中文、emoji 或覆盖式同名文件。

示例：

```text
char_wuzhu_battle_idle_v01.png
enemy_mountain_monkey_battle_idle_v01.png
ui_map_node_weak_act1_normal_v01.png
ui_map_state_locked_v01.png
ui_button_primary_hover_v01.9.png
```

- 新构图、修图或内容调整递增版本号，如 `_v02`；`approved` 只放当前批准版本，历史版本留在同一资产的 `archive/` 子目录。
- `_normal`、`_hover`、`_pressed`、`_disabled`、`_selected`、`_locked` 是状态，不代替版本号。
- 每个导出批次附一份 `delivery_note.md`，写明文件、运行尺寸、是否透明、锚点/九宫格边距、推荐过滤和已知限制。

## 5. AI 图像筛选与导入前检查

### 5.1 筛选门槛

候选图必须同时满足以下条件才可进入 `approved`：

1. **方向一致**：水墨厚涂、废墟材质、沉郁基调成立；高饱和色面积受控。
2. **轮廓可读**：在 50% 和预期运行尺寸下，角色/节点仍可区分主体；敌人不互相趋同。
3. **构图可接入**：严格遵守透明边界、站位方向与 UI 安全区；标题背景和战斗背景没有抢占文本区的亮主体。
4. **内容干净**：无文字、伪文字、数字、水印、签名、边框、错误肢体、重复头部或不可解释的装备。
5. **可编辑**：批准版本至少保留可分离的主体、背景/纸纹、主要特效或蒙版；不能只交付唯一扁平原图。

### 5.2 导入前检查

- 导出尺寸与清单一致，PNG 为 sRGB；透明角色、图标和框体使用 RGBA。
- 检查 alpha 边缘无黑边、白边或预乘光晕；透明立绘不自动裁剪，避免锚点漂移。
- 角色脚部基线一致；地图节点状态叠层能与任意类型底图重合；按钮和卡框的可拉伸边界独立。
- 背景先按 1920 x 1080 与 1280 x 720 预览，确认 TopBar、手牌、文字和按钮安全区没有高对比干扰。
- UI 图标不生成 mipmap；背景和厚涂立绘的过滤、压缩和九宫格边距由资源接入人员在 Godot 工程中确认。

### 5.3 后续接入映射边界

- 美术部交付**命名、尺寸、透明边界、九宫格边距、锚点建议和 `delivery_note.md`**；不修改 `project.godot`、场景、C#、Theme 或导入配置。
- UI/UX 部确认页面容器、交互状态和视觉摆放；开发部负责资源路径、Godot 导入设置、场景引用及运行时验证。
- 游戏 UI 负责渲染名称、数值、费用、按钮文案、HP、状态和奖励结果；美术文件只提供背景、框体、图标和插画，不承担玩法事实来源。

## 6. 推荐批次与风险

| 批次 | 内容 | 目标 | 主要风险 |
|------|------|------|------|
| A: 视觉锚点 | 战斗背景、巫祝 idle/头像、山野妖猴 idle/头像、TopBar/按钮基础 | 先统一最常见画面与可读性 | 角色和 UI 实际锚点未冻结时，需避免紧贴边缘的构图 |
| B: 路线可读 | 地图卷轴、6 类节点、5 类状态、碎石山精/掠灵散修 | 完成首条路线的视觉语义 | 节点尺寸或状态叠层接口变化会影响裁切，但不应改变类型设计 |
| C: 首屏闭合 | 标题背景、黄品/道痕卡框、斗击/术法图标、天品框占位 | 让主循环的首屏与卡牌层统一 | 卡牌文本区和奖励卡尺寸需由 UI/UX 与开发接入前复核 |

推荐每个资产先生成 4~6 张候选，筛选 1~2 张进入人工修图和批准；不在同一轮同时批量生成 P1 场景、Boss 卡和完整动画。这样能先锁定笔触、色板、人物比例和 UI 兼容性，避免把不稳定接口放大成资产返工。

已知风险：当前 `01-视觉风格指南.md` 仍为缺失占位稿；本方案以既有巫祝、ACT1 场景、角色与卡牌/UI规格作为临时事实源。正式生产前需将本文件中的视觉基线回填或合并到风格指南，避免长期出现两个风格入口。

## 7. 需要用户最后确认的视觉决策

以下不阻塞方案，但应在批准第一批出图前确认：

1. **标题页主视觉**：推荐使用“无人远景不周废墟”，标题与菜单均由 Godot UI 叠加；是否需要把巫祝放入标题首屏。
2. **AI 出图基准**：推荐先以“厚涂程度中高、毛笔轮廓可见、材质粗粝”为锚点，接受每资产 4~6 张候选后人工修图；是否允许更强烈的墨线风格。
3. **首批范围**：推荐按 A -> B -> C 三个小批次推进，先只做 P0 静态资源；是否批准在 A 批通过后启动实际生成。

## 8. 记录

### A0 风格修正记录（2026-07-22）
