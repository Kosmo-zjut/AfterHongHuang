## 1. ACT1视觉总控

不周废墟是天崩之后的地表残骸区。视觉核心不是“宏大的山水风景”，而是被水、火、碎石和残留法阵反复冲刷过的生存现场。所有场景保持水墨厚涂、粗粝毛边和低饱和底色，功能信息只用局部赤、青、金、紫提亮。

### 1.1 共用构图安全区

以下安全区适用于 1920 x 1080 运行画面。背景可有细节，但不要在这些区域放高对比主体：

| 区域 | 坐标建议 | 视觉要求 |
|------|------|------|
| TopBar | `y=0~110` | 深色、低纹理，不能有亮色裂缝或文字形状 |
| 玩家立绘 | `x=100~720, y=150~780` | 允许中等细节，脚下状态条附近留暗底 |
| 敌人立绘/意图 | `x=1200~1840, y=130~780` | 敌人头顶意图区必须干净，不能被背景尖峰干扰 |
| 中央信息区 | `x=720~1200, y=160~720` | 低对比，用于日志、飘字、目标反馈 |
| 手牌区 | `x=240~1680, y=750~1080` | 低频暗色，避免水纹、碎石、亮火遮挡卡面 |
| 结束回合按钮 | `x=1640~1880, y=820~1020` | 右下角保持连续暗底，不放高亮岩石或水花 |

### 1.2 ACT1共用色板

| 色块 | Hex | 用途 |
|------|------|------|
| 废墟墨黑 | `#211B18` | 深景、遮罩、角色背后暗底 |
| 碎石灰褐 | `#62584E` | 岩体、断墙、残骸 |
| 浊水青黑 | `#21474A` | 天河残水、潮气、相柳主题 |
| 旧铜暗金 | `#8B6A36` | 商店、Boss 入口、旧阵纹 |
| 余烬暗红 | `#8B2500` | 天火、危险提示、巫祝呼应 |
| 符纸米白 | `#D4C9B8` | 纸张、骨骼、可读文字底 |

高饱和色只出现在主体识别点，不能整屏使用。水和火同时出现时，以浊水青黑为大面积底色，以余烬暗红做小面积冲突点。

## 2. 不周废墟战斗背景

### 2.1 最小交付

| 文件 | 尺寸 | 格式 | 用途 | 优先级 |

| `bg_battle_buzhou_outer_act1_v01.png` | 1920 x 1080 导出；3840 x 2160 源文件 | PNG/WebP；源文件分层 | ACT1 普通战斗和强敌战斗底图 | P0 |

| `bg_battle_buzhou_outer_act1_water_overlay.png` | 1920 x 1080 | 透明 PNG | P1，天河/相柳战斗的缓慢水纹叠层 | P1 |
| `bg_battle_buzhou_outer_act1_ember_overlay.png` | 1920 x 1080 | 透明 PNG | P1，巫祝和 Boss 阶段切换的局部余烬 | P1 |

### 2.2 画面构成

- 远景：断裂的不周山脊线，保留一条暗红天光，不出现完整城市或宫殿。
- 中景：倾斜岩层、断裂石柱、被水冲出的沟壑，中央偏上留出敌人意图和战斗飘字空间。
- 近景：少量湿黑碎石和旧符片，左右角色脚下不要堆高，避免遮住 HP/护体条。
- 光源：左侧可有巫祝余烬的暖色反光，右侧以浊水冷色压住，不把背景做成平均铺满的渐变。
- 视线：中央应有一条由断山和水沟形成的斜向路径，把注意力引向战斗双方，不把焦点放在 UI 安全区。

### 2.3 占位方案

先用三层纯色/剪影组合：`#211B18` 深景、`#62584E` 岩体剪影、`#21474A` 水沟薄层，加一条 `#8B2500` 暗红天光。占位图必须保留左右立绘和底部手牌的暗区，不使用纯黑全屏或高对比噪点。

## 3. 行脚宝商页面

行脚宝商页面是节点底层页面，地图和套牌通过统一 TopBar 呼出。美术资产要支持“商品已售、灵韵不足、离开商店”三类状态，不把状态画死在商品图上。

### 3.1 最小资产清单

| 文件 | 尺寸建议 | 格式 | 用途 | 优先级 |
|------|------|------|------|:--:|
| `bg_node_shop_act1_v01.png` | 1920 x 1080 导出；3840 x 2160 源文件 | PNG/WebP | 商店页面底图，顶部和商品区留暗 | P1 |
| `char_roaming_merchant_act1_idle.png` | 768 x 1024 透明画布 | PNG | 行脚宝商半身/坐姿立绘，放在左侧或后景 | P1 |
| `prop_roaming_merchant_counter.png` | 1024 x 512 | PNG 透明 | 破旧木案、布包、灵韵串、纸签 | P1 |
| `ui_shop_panel_base.9.png` | 1180 x 760 设计稿 | PNG 九宫格 | 货架和服务区共用面板底 | P1 |
| `ui_shop_offer_slot.9.png` | 320 x 420 | PNG 九宫格 | 卡牌/法宝商品槽，内容由 UI 叠加 | P1 |
| `ui_shop_service_icon_remove.png` | 96 x 96 | PNG/SVG | 除牌服务，使用断裂卡片加墨刀形状 | P1 |
| `ui_shop_service_icon_reroll.png` | 96 x 96 | PNG/SVG | 重列货架，使用旋转纸签形状 | P1 |
| `ui_shop_service_icon_leave.png` | 96 x 96 | PNG/SVG | 离开，使用收拢布包/向外箭头形状 | P1 |

### 3.2 视觉方向

商人不做华丽 NPC 卡面，先做“能在废墟活下来的人”：旧布、木案、收紧的包裹、几张被水浸过的价格签。人物主体保持墨灰和旧铜色，脸部可以被兜帽或布巾部分遮住，避免在没有角色设定的情况下扩写身份。

商品状态由 UI 层处理：已售用空槽和落下的纸签，灵韵不足用压暗加锁形标记，不能只把商品染成红色。法宝货架未开放时不交付假商品图，保留空货架状态。

### 3.3 占位方案

复用 `ui_dialog_victory_base.9.png` 或同风格深棕九宫格面板作为商店面板；商人用深灰半身剪影；商品槽用旧纸矩形、价格位置和三种服务图标占位。这样不阻塞商店页面接入，也不把临时视觉误当正式资源。

## 4. 问号事件页面

两种事件共用事件页框体和选项按钮，只替换背景、主图和少量装饰，避免每个事件单独造一套 UI。

### 4.1 天河倒灌

| 文件 | 尺寸建议 | 格式 | 用途 | 优先级 |
|------|------|------|------|:--:|
| `bg_event_heavenly_river_act1_v01.png` | 1920 x 1080；源文件 3840 x 2160 | PNG/WebP | 被天河残水冲开的废墟、碎符和斜向水口 | P1 |
| `ui_event_heavenly_river_emblem.png` | 192 x 192 | PNG 透明 | 水口与断符结合的事件徽记 | P1 |
| `vfx_event_heavenly_river_sheet.png` | 1920 x 1080 透明 | PNG | P2，水雾和纸符漂流叠层 | P2 |

画面重点是“水从不该出现的地方灌下来”：冷青水幕占后景，破碎符纸被冲向画面一侧，中央选项区保持低对比。不要画成平静河流，也不要用大面积蓝色渐变。

### 4.2 散修遗篆

| 文件 | 尺寸建议 | 格式 | 用途 | 优先级 |
|------|------|------|------|:--:|
| `bg_event_scavenger_seal_act1_v01.png` | 1920 x 1080；源文件 3840 x 2160 | PNG/WebP | 半塌符阵、散修遗物和最后一笔符线 | P1 |
| `ui_event_scavenger_seal_emblem.png` | 192 x 192 | PNG 透明 | 断裂符箓印记 | P1 |
| `ui_event_scavenger_seal_diagram.png` | 768 x 768 | PNG 透明 | 事件主图，可叠在面板后方 | P1 |
| `vfx_event_scavenger_ink.png` | 1024 x 1024 透明 | PNG | P2，墨线补全/散开效果 | P2 |

画面重点是“阵还在等最后一笔”：半圆护体阵纹不闭合，中心留出空位，周围有被压在碎石下的符纸。颜色以旧铜、符纸米白和暗紫墨为主，不能出现完整明亮法阵。

### 4.3 共用事件页边界

- 事件主图安全框建议 `x=250~1670, y=150~680`，不可覆盖 TopBar 和底部按钮区。
- 选项区使用现有通用按钮四态，选项状态由 UI 叠加，不为每个结果绘制独立按钮图。
- 不可用选项保留图标和文字，只叠加锁形、灰墨和短提示，不隐藏离开选项。

### 5.2 构图和复用

- 相柳不是九个独立目标：入口图可以出现九个头颈的回环暗示，但不要给九个头分别画 HP 框或目标圈。
- 主体集中在画面中右，左侧留给巫祝和进入按钮；九首的轮廓以骨白/浊青对比识别，背景不使用纯黑剪影吞掉骨骼。
- 入口页的三阶段标签使用形状和文字区分：潮线、裂口、断骨三个符号，不能只用蓝/红/黑三种颜色。
- `enemy_xiangliu_skeleton_entrance.png` 与战斗立绘共用骨架、头颈和水纹图层；入口版本只允许增加姿态和裁切，不重新设计物种。

### 5.3 占位方案

使用战斗背景的暗化版本 + 三个不同高度的蛇首骨架剪影 + 古金标题底板；阶段标签使用三种几何符号占位。三张 Boss 卡先用天品框和卡名占位，不提前伪造完整卡面。

## 6. ACT1场景生产顺序

### 最小生产批次

1. P0：战斗背景合成图、地图节点/状态图标、通用面板和 Boss 天品卡框。
2. P0：三弱怪战斗 idle、相柳之骸战斗 idle/入口剪影，确保第一条路线能替换代码占位。
3. P1：三强怪 idle、商店页、两种事件页、Boss 入口页。
4. P2：水雾/余烬/符墨叠层、受击/死亡动画、商店和事件的细节道具。

### 风险

- 场景页由开发部和 UI/UX部按 NodePage 契约接入，若节点尺寸或 TopBar 高度变化，背景安全区需重新验收；本文件不修改 UI/UX 文档。
- 水和火的叠加容易把画面推向高饱和。优先压低面积，保留局部高光。
- Boss 入口与战斗背景复用能节省产量，但必须保留相柳九首和浊潮的识别点，不能只做背景换色。
- 法宝货架当前可能为空数组，商店资产必须支持空货架，不交付假商品或假图标。
